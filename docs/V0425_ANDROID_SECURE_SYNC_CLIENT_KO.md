# CallTag v0.42.5 Android 데이터 보호·복구 클라이언트

최종 갱신: 2026-08-05

## 목적

앱 삭제·기기 변경 시 고객관리 데이터가 사라지는 문제를 해결하기 위한 Android P1 클라이언트 기반이다. 서버 기능은 별도 flag와 암호화 secret이 준비되기 전까지 비활성 상태이며, 앱에서도 사용자가 명시적으로 동의하기 전에는 동기화 요청을 시작하지 않는다.

## 사용자 화면

더보기 → 앱·계정 → 데이터 보호·복구

- 기본값 OFF
- `데이터 보호 켜기` 선택 시 저장 범위 안내 후 동의
- 고객·상담·메모·후속 일정·고객 상태만 우선 동기화
- 통화 녹음, 휴대폰 전체 연락처, 전체 문자함은 업로드하지 않음
- 마지막 완료 시각, 대기 중 변경 건수, 서버 보관 건수 표시
- 서버 준비 전에는 `서버 기능 준비 중`으로 표시
- 서버 실패 시에도 로컬 DB를 삭제하거나 초기화하지 않음

## 로컬 구조

기존 `calltag.db`는 변경하지 않는다. 별도 `calltag_sync_local.db`에서 다음을 관리한다.

- 계정별 동기화 상태
- 로컬 숫자 ID와 서버 UUID 매핑
- 레코드별 version
- payload hash
- pending outbox
- 삭제 tombstone
- 증분 pull cursor
- 마지막 시도·성공·오류 상태

계정 구분은 서버 profile의 `ownerId`를 우선 사용한다. 기존 서버 응답에 ownerId가 없는 임시 호환 상태에서는 이메일을 SHA-256으로 변환한 로컬 계정 키를 사용한다.

## 기기 식별

- 24바이트 SecureRandom으로 기기 ID 생성
- Android Keystore AES-GCM으로 암호화해 SharedPreferences에 저장
- 서버에는 기기 ID 원문이 전달되지만 서버 저장 시 HMAC으로 변환
- 앱 삭제 후에는 기존 키와 ID가 삭제되어 새 기기로 등록

## 동기화 순서

1. 로그인과 사용자 동의 확인
2. 민감정보가 없는 `/api/calltag-sync/status`로 서버 활성화 여부 확인
3. 최초 실행이면 `/bootstrap`으로 기존 서버 데이터 복구
4. 로컬 고객·상담·할 일·상태 snapshot 생성
5. 변경 payload hash 비교
6. 최대 100건씩 `/push`
7. cursor 기반 `/pull`
8. 성공 항목만 pending 해제
9. 마지막 성공 시각과 서버 건수 저장

서버 flag가 OFF이면 고객 payload를 생성하거나 push하기 전에 중단한다.

## 동기화 엔터티

### customer

- 이름
- 전화번호
- 고객 상태
- 유입 source
- 메모
- 최초·최근 연락 시각

### interaction

- 연결 고객 UUID
- 통화 유형
- 시작·종료 시각
- 통화시간
- 결과
- 상담 메모

### task

- 연결 고객·상담 UUID
- 일정 종류
- 제목
- 예정 시각
- 완료 상태·완료 시각

### stage

- 고객 상태 이름
- 순서
- 색상

문자 템플릿·자동문자 설정·발송 결과·첨부 이미지는 P2에서 분리한다.

## 충돌 정책

- 서버 version보다 오래된 데이터는 덮어쓰지 않음
- 같은 version에 다른 payload가 있으면 자동 병합하지 않고 오류 상태 표시
- 로컬 pending 변경이 있는 항목에 원격 변경이 도착하면 로컬 변경을 보존하고 사용자 확인 상태로 남김
- 삭제는 tombstone으로 전송

## 안전장치

- 사용자 동의 기본 OFF
- 로그인 세션이 없으면 동작하지 않음
- 계정별 매핑 완전 분리
- 서버 readiness 확인 전 고객 payload 전송 금지
- 한 번에 최대 100건
- foreground 반복 호출 15분 throttle
- 서버 준비 중에는 6시간 backoff
- 동기화 실패 시 로컬 데이터 유지
- 기존 `.ctbackup` 수동 백업 유지

## 서버 활성화 전 남은 작업

- 서버 PR 병합
- staging D1 migration 적용
- 암호화·검색 secret 등록
- staging flag 활성화
- 계정 A/B 격리 실검증
- 빈 기기 bootstrap 복원 실검증
- 두 기기 동시 변경 conflict 실검증
- 탈퇴·서버 데이터 삭제 흐름 연결
- 개인정보처리방침에 서버 저장 항목·보관기간 반영

## 운영 상태

- Android 코드 포함
- 사용자 opt-in 기본 OFF
- 서버 운영 flag OFF
- 운영 고객 데이터 전송 미시작
- Google 로그인과 결제 활성화는 별도 작업
