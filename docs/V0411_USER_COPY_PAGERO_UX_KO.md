# 콜태그 v0.41.1 사용자 문구·페이지로 연결 화면 개선

기준일: **2026-08-04**

## 목적

일반 사용자가 볼 필요가 없는 개발·운영 표현을 화면에서 제거하고, 페이지로 문의 연결 상태와 사용 방법을 한눈에 이해할 수 있도록 정리한다.

## 사용자 확인 반영

사용자가 v0.41.0에서 다음 항목을 확인했다고 회신했다.

- 페이지로 문의 알림 수신
- 앱 종료·잠금화면 알림
- 알림 후 고객 반영 흐름
- 중복 문의 처리 등 후처리 동작

사용자 확인 범위를 넘어 내부 장애 상황까지 검증 완료로 확대하지 않는다.

## 페이지로 연결 화면

기존 표현:

- 지금 동기화
- 동기화 중
- 실시간 서버 확인 중
- 이 기기 실시간 등록 필요
- Firebase 운영 설정
- 마지막 동기화 실패와 내부 오류 코드

변경 표현:

- 새 문의 확인
- 문의 확인 중
- 페이지로 연결 완료
- 새 문의 알림 켜짐
- 새 문의 알림 준비 중
- 마지막 확인을 마치지 못했어요

화면 구성:

1. 페이지로 문의가 콜태그에 자동 등록된다는 핵심 설명
2. 현재 연결 계정
3. 페이지로 연결 여부
4. 새 문의 알림 여부
5. 마지막 문의 확인 결과
6. 새 문의 확인 버튼
7. 페이지로 관리화면 이동
8. 고객 문의가 콜태그에 들어오는 3단계 사용 안내

## 더보기 화면

- `앱 진단` 메뉴 제거
- 페이지로 메뉴명을 `페이지로 문의 연결`로 변경
- 각 메뉴 설명을 실제 사용 목적 중심으로 수정
- 그룹문자·자동문자·백업 설명에서 캠페인·암호화 같은 내부 표현 제거

## 권한 화면

- Android 권한창·미허용·SMS 같은 표현 제거
- 사용 목적 중심으로 표시
  - 연락처 보기
  - 전화 화면 메모 준비
  - 전화 수신 확인
  - 문자 보내기
  - 알림 받기
- 기존 Google·삼성 연락처는 유지된다는 안내 유지

## 계정 화면

- 서버 연결 오류 문구를 인터넷 연결 안내로 변경
- 회원탈퇴 실패 시 내부 오류 원문을 사용자에게 표시하지 않음
- `회원정보 새로고침`을 `회원정보 다시 불러오기`로 변경

## 재발 방지

GitHub Actions에 사용자 문구 검사를 추가했다.

- 페이지로 화면에 `지금 동기화`, `동기화 중`, Firebase, 토큰, 실시간 서버, errorCode가 다시 들어오면 빌드 실패
- 더보기 화면에 `앱 진단` 또는 `DiagnosticActivity` 진입이 다시 들어오면 빌드 실패
- 권한 화면에 Android 권한창·미허용 표현이 다시 들어오면 빌드 실패
- 계정 화면에서 예외 원문을 직접 노출하면 빌드 실패
