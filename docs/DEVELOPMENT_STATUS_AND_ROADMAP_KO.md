### 13차 — DB 정합성·고아 작업·남은 알람 복구

버전: `0.32.0` / versionCode `34`  
기능 HEAD: `1390af22abee3fcaf52587a13863cdca573ede97`

상세 기준:

- [`PATCH_13_DATA_INTEGRITY_PLAN_KO.md`](PATCH_13_DATA_INTEGRITY_PLAN_KO.md)

#### 자동 실행 순서

```text
앱 시작·재부팅·앱 업데이트
→ 기존 예약문자 복구
→ 데이터 정합성 검사
→ 고아 작업 차단·참조 정리
→ 캠페인 상태 재동기화
```

예약 복구와 정합성 복구를 같은 스레드에서 순서대로 실행해 서로 상태를 덮어쓰지 않게 했다.

#### 캠페인 수신자 연결 복구

- `message_id > 0`인데 문자 작업이 없으면 수신자를 `FAILED`
- `message_id = 0`인데 진행 상태면 수신자를 `FAILED`
- 문자 작업의 `campaign_id`와 수신자의 캠페인 ID가 다르면 `FAILED`
- 누락 문자 작업을 새로 생성하거나 자동 발송하지 않음

복구 사유를 수신자별 상태에 남기고 캠페인 전체 집계를 다시 계산한다.

#### 고아 문자 작업 복구

다음 문자 작업을 고아 작업으로 판단한다.

- `campaign_id`가 있는데 캠페인이 없음
- 캠페인은 있지만 해당 `message_id`를 가진 수신자가 없음

처리:

| 작업 상태 | 처리 |
|---|---|
| `SCHEDULED / READY` | 예약 알람 취소 후 `CANCELLED` |
| `SENDING` | 자동 재발송 금지, `FAILED` |
| 최종 상태 | 상태 유지, 남은 알람 취소 |

#### 최종 상태 알람 정리

최근 예약 범위의 다음 작업 ID로 AlarmManager PendingIntent 취소를 멱등 실행한다.

- `SENT`
- `FAILED`
- `SKIPPED`
- `CANCELLED`

AlarmManager의 전체 알람 목록은 앱이 조회할 수 없으므로 DB의 작업 ID를 기준으로 동일 PendingIntent를 취소한다.

#### 늦은 SMS 콜백 보호

SMS 전송 콜백은 현재 문자 작업이 실제 `SENDING`일 때만 반영한다.

다음 상태에 늦게 도착한 성공·실패 콜백은 무시한다.

- `SENT`
- `FAILED`
- `SKIPPED`
- `CANCELLED`
- 그 밖의 `SENDING`이 아닌 상태

따라서 취소된 문자가 늦은 성공 콜백으로 다시 `SENT`가 되는 문제를 차단한다. 무시 이벤트는 고객 정보 없이 작업 ID와 현재 상태만 기록한다.

#### 수동 그룹 참조 정리

현재 고객 DB에 없는 `message_group_members.customer_id` 행만 삭제한다. 스마트 그룹은 실행할 때 현재 고객 DB를 다시 계산하므로 별도 정리가 필요 없다.

캠페인 수신자의 고객명·전화번호·본문은 과거 발송 이력 스냅샷이므로 고객 삭제만으로 제거하지 않는다.

#### 캠페인 삭제 안전장치

- 캠페인 삭제 전 연결 문자 작업의 PendingIntent 취소
- 남은 `SCHEDULED/READY` 작업 `CANCELLED`
- 이미지 예약 구성 정보 정리
- `SENDING` 작업이 있으면 결과 확인 전 삭제 차단
- 개별 문자 발송내역은 유지

#### 진단 화면

기존 `상태 재계산` 버튼을 `정합성 복구`로 확장했다.

Build 성공만으로 위 항목을 통과했다고 기록하지 않는다.

## 5. 남은 패치 순서

이 패치는 진행한다. 외부 데이터 활용을 위한 내보내기와 완전히 분리한다.

- 캠페인 내역
- 문자 발송내역
- 자동화 설정
- 회선 설정

필수 기준:

- 버전 정보가 포함된 하나의 앱 복구용 백업 묶음

- 민감정보 보호
- 백업 파일을 일반 CSV·엑셀처럼 열어 활용할 수 없게 설계

포함 금지:

- CSV·XLSX 내보내기

## 6. 별도 보류·추후 업데이트 기능

### 6.1 데이터 내보내기 — 유료 확장 기능

상태: **보류, 현재 패치 금지**

예상 범위:

- 고객 목록 CSV·XLSX
- 캠페인 결과 CSV·XLSX
- 조건별 고객 목록 추출
- 관리자용 보고서
- 외부 CRM 이전용 데이터

가격, 권한, 개인정보 경고, 다운로드 만료, 감사 로그를 별도 기획한 뒤 개발한다. 사용자가 다시 승인하기 전 구현하지 않는다.

### 6.2 웹 동기화·웹 관리자

현재 Android 로컬 데이터와 마케팅 웹사이트는 별개다. 앱 데이터가 웹에 실시간 동기화된다고 표현하면 안 된다.

별도 설계가 필요한 항목:

- 서버 데이터 모델
- 로그인과 기기 연결
- 암호화와 개인정보 처리
- 충돌 해결
- 오프라인 동기화
- 웹 권한
- 삭제·탈퇴 처리

### 6.3 이미지 단체문자

현재 이미지 템플릿은 수동 문자와 사용자 확인형 예약 문자에서 사용한다. 이미지 단체문자는 구현하지 않았다.

## 7. 다음 작업자가 반드시 지킬 규칙

1. 작업 전 Draft PR `#1`의 최신 HEAD와 파일 SHA를 다시 확인한다.
2. `main`의 웹 변경과 Android 개발 브랜치 변경 범위를 분리한다.
3. 같은 파일을 병렬 수정하지 않는다.
4. 사용자가 명시적으로 지시하기 전 `main`에 병합하지 않는다.
5. PR은 개발 중 Draft 상태를 유지한다.
6. 문서에 적혀 있다는 이유만으로 구현됐다고 보고하지 않는다.
7. Build 성공은 실제 단말 검증 성공과 다르다고 명시한다.
8. 실제 발송 완료를 확인할 수 없는 이미지 MMS를 `발송 완료`로 표시하지 않는다.
9. 발송 제외·중복방지·일정 상태·SIM 상태 검사는 실제 발송 직전까지 유지한다.
10. 기존 고객·문자·템플릿·그룹·캠페인 데이터를 파괴하는 DB 초기화를 하지 않는다.
11. DB 변경 시 기존 데이터 보존 마이그레이션을 작성한다.
12. 불명확한 `SENDING` 작업을 자동 재발송하지 않는다.
13. `PAUSED` 캠페인을 자동 재개하지 않는다.
14. 누락 문자 작업을 자동 재생성하거나 고아 작업을 자동 발송하지 않는다.
15. 늦은 SMS 콜백이 최종 상태를 덮어쓰지 못하게 한다.
16. 캠페인 수신자 스냅샷과 현재 고객 DB를 동일 데이터로 취급하지 않는다.
17. 백업·복원과 데이터 내보내기를 같은 기능으로 합치지 않는다.
18. CSV·XLSX·외부 데이터 내보내기는 사용자가 다시 승인하기 전 구현하지 않는다.
19. 비식별 진단 정보에 고객명·전화번호·문자 본문을 넣지 않는다.
20. 공개 제품명은 콜태그로 통일한다.
