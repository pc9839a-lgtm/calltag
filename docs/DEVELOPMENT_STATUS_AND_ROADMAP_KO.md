## 1. 현재 상태 한눈에 보기

콜태그는 현재 다음 범위까지 Android 코드 구현과 Debug APK 빌드가 완료됐다.

- 통화 전 고객 맥락 표시 기반
- 통화 종료 후 고객 상태·메모·일정·문자 정리
- 저장형 문자 템플릿과 변수 치환
- 수신·발신·부재중·후속문자
- 문자 발송 제외와 중복발송 방지
- 고객 상세 문자
- 일정과 후속문자 생명주기 연결
- 이미지 첨부 템플릿과 사용자 확인형 MMS 작성
- 수동 그룹과 스마트 그룹
- 단체문자 캠페인
- 수신자별 발송 상태·취소·재시도
- 권한·SIM·문자 작업·캠페인 상태를 확인하는 앱 진단 화면
- 캠페인 수신자 상태를 문자 작업 기준으로 안전하게 재계산하는 기능
- 실제 단말 E2E 체크리스트와 비식별 진단 이벤트 기록

현재 빌드 성공은 **컴파일과 APK 패키징 성공**을 뜻한다. 실제 SIM 발송, 제조사별 백그라운드 제한, 재부팅 복구, 대량 발송 안정성까지 실기기 검증이 끝났다는 뜻은 아니다.

`main`에는 병합하지 않았으며 PR `#1`은 Draft 상태를 유지한다.

## 2. 확정된 제품 기준

### 2.1 단일 제품

- 정식 한글명: `콜태그`
- 정식 영문명: `CallTag`
- 공개 대표 도메인: `https://calltag.pagero.kr`
- Android 앱과 계정은 하나다.
- 전화관리와 문자자동화는 별도 앱이 아니라 콜태그 내부 기능군이다.
- `콜링크`, `페이지로 콜링크`는 레거시 소스 설명에서만 사용한다.
- 공개 앱 UI, 웹사이트, 스토어 소개, 고객 안내에 레거시 명칭을 별도 서비스처럼 노출하지 않는다.

### 2.2 가격 기준

| 상품 | 월 구독료 | 제공 범위 |
|---|---:|---|
| 전화관리 | 1,900원 | 고객·통화·상태·메모·일정·통계 |
| 문자자동화 | 990원 | 템플릿·자동·수동·예약·그룹·단체문자 |
| 통합 이용 | 2,500원 | 전화관리와 문자자동화 전체 및 연결 자동화 |

결제·서버 구독 검증은 아직 출시 수준으로 완료되지 않았다. 개발 빌드에서 기능 검증을 위해 통합 권한을 기본 적용하더라도 이를 운영 결제 구현 완료로 표현하면 안 된다.

### 2.3 핵심 사용자 흐름

```text
전화 수신 전 고객 맥락 확인
→ 통화
→ 통화 종료 큰 정리창
→ 고객 상태·메모·다음 할 일 저장
→ 즉시 문자 또는 후속문자
→ 고객 타임라인 반영
```

### 2.4 데이터 정책

- **앱 데이터 백업·복원은 향후 필수 패치로 구현한다.**
- 백업은 장애·기기 변경·데이터 손상에 대비해 같은 콜태그 앱으로 복구하는 기능이다.
- **CSV·XLSX·외부 CRM용 파일 등 데이터 내보내기는 현재 구현하지 않는다.**
- 데이터 내보내기는 추후 별도 유료 기능으로 기획·개발한다.
- 백업 파일을 고객 목록이나 캠페인 결과표처럼 일반적으로 열어 활용하는 파일로 만들지 않는다.
- 기본 백업 기능에 CSV, XLSX, 범용 연락처, 캠페인 결과표 내보내기를 포함하지 않는다.

### 2.5 진단 정보 정책

`앱 상태 진단`의 복사 기능은 고객 데이터 내보내기가 아니다.

포함:

- 앱 버전과 Android API
- 권한 허용 여부
- 활성 SIM 수와 선택 회선의 유효 여부
- 고객·일정·그룹·문자 작업·캠페인 건수
- 상태 불일치와 연결 작업 누락 건수
- 비식별 작업 ID와 기술 이벤트 유형

포함하지 않음:

- 고객명
- 전화번호
- 문자 본문
- 고객 메모
- 고객 목록
- 캠페인 수신자 명단

### 2차 — 다수 저장형 템플릿 보관함

- 템플릿 여러 개 저장·수정·복제·삭제
- 검색·즐겨찾기·최근 사용
- 수신·발신·부재중·후속 기본 템플릿 분리
- 기존 고정 문구를 최초 실행 시 보관함으로 이전
- 수동문자와 자동발송이 같은 템플릿 저장소 사용

### 3차 — 문자 발송 제외 공통 정책

- 전화 고객관리 제외와 문자 발송 제외 분리
- 자동문자 제외
- 전체 문자 제외
- 수신·발신·부재중·후속 유형별 제외
- 생성·예약·실행·실제 발송 직전 검사
- 제외 건은 실패가 아닌 `SKIPPED`로 기록

### 4차 — 공통 멱등키 중복발송 방지

- 통화·일정·캠페인·템플릿·전화번호·본문 기반 멱등키
- 자동·수동·예약 발송 충돌 차단
- 같은 캠페인에서 같은 번호 한 번만 처리
- 동일 템플릿·본문 제한 시간 내 재사용 차단
- 중복 요청을 `SKIPPED`로 기록하고 기존 내역 정보 표시
- 실패·제외·취소는 재시도 가능
- 메시지 DB v2 보존 마이그레이션

### 5차 — 통화 종료창 템플릿 직접 선택

- 통화 종료 큰 정리창에서 템플릿 보관함 직접 선택
- 수신·발신·부재중 유형에 맞는 템플릿 제공
- 현재 고객·통화·계정·일정 정보 즉시 치환
- 직접 편집한 발송본과 원본 템플릿 분리
- 선택 템플릿 ID를 중복방지 컨텍스트에 전달

### 6차 — 고객 상세 핵심 행동 재구성

- 고객 상세 상단 행동을 `전화 / 일정 추가 / 문자`로 통일
- 고객 상태 변경을 고객명 옆 상태 배지로 이동
- 문자 작성 화면에 고객 ID와 전화번호 자동 전달
- 문자 발송 제외 설정 역할 분리

### 7차 — 일정과 후속문자 생명주기 연결

연결 방식:

- 없음
- 지금 안내문자
- 일정 하루 전
- 일정 시간
- 일정 완료 후

적용 내용:

- 일정 ID와 문자 내역 연결
- 일정 변경 시 `문자 유지 / 함께 변경`
- 일정 완료·삭제·다시 열기와 예약문자 동기화
- 통화에 의한 일정 자동 완료 경로 포함
- 오래된 알람이 실행돼도 일정 상태를 다시 검사하고 조건 불충족 시 `SKIPPED`

### 8차 — 이미지 첨부 템플릿과 MMS 작성 흐름

- 갤러리 이미지를 앱 전용 저장소로 복사
- 최대 긴 변 1,600px, JPEG 약 900KB 이내 압축
- 템플릿별 이미지 추가·교체·미리보기·삭제
- 템플릿 복제와 메시지별 이미지 스냅샷
- `FileProvider` 읽기 전용 공유 URI
- 이미지 문자는 기본 메시지 앱에 번호·본문·이미지를 채워 작성창 실행
- 예약 이미지 문자는 지정 시각 알림으로 사용자에게 전송 요청
- `전송 필요 / 메시지 앱 열림 / 실패` 상태 구분

제한:

- 이미지 MMS 최종 전송 버튼은 사용자가 기본 메시지 앱에서 누른다.
- 콜태그가 확인할 수 없는 실제 전송 완료를 허위로 표시하지 않는다.
- 자동발송 기본 템플릿과 단체문자는 현재 텍스트 전용이다.

### 9차 — 수동 그룹·스마트 그룹·단체문자 캠페인

수동 그룹:

- 고객 여러 명 직접 선택
- 고정 그룹 저장·수정·삭제
- 동일 고객 ID 중복 저장 방지

스마트 그룹:

- 고객 상태
- 7일·30일·90일 이상 미접촉
- 미완료 일정 보유
- 거래 고객·미거래 고객
- 조건 조합
- 캠페인 실행 직전 최신 고객 데이터로 재계산

단체문자 캠페인:

- 그룹·텍스트 템플릿·시작 지연시간 선택
- 캠페인당 최대 500명
- 고객별 변수 개별 치환
- 수신자별 4초 간격 순차 예약
- 중복번호·번호 오류·발송 제외·변수 오류 고객 개별 `SKIPPED`
- 수신자별 실제 문자 상태와 사유 표시
- 남은 발송 일괄 취소
- 실패·건너뜀·취소 고객 재시도
- 재시도 시 최신 고객 정보로 문구 재치환
- 재시도 전용 키로 기존 캠페인 멱등키 충돌 방지

분리 저장소:

```text
calltag.db             고객·통화·상태·일정
calltag_messages.db    문자 작업·발송내역
calltag_groups.db      수동·스마트 그룹
calltag_campaigns.db   캠페인·수신자 상태
```

### 10차 — 실기기 진단·상태 재계산 기반

버전: `0.29.0` / versionCode `31`  
검증: GitHub Actions `Build CallTag APK #857` 성공  
Android 기능 커밋: `522b7df5f5745822175383a6c4bc90a1e8d3c6db`

추가 기능:

- 계정 화면의 `앱 상태 진단` 진입점
- 앱 버전·Android API·단말 정보 확인
- 문자·전화·통화기록·연락처·알림·오버레이 권한 확인
- 활성 SIM 목록과 선택한 문자 회선의 유효성 확인
- 고객·미완료 일정·그룹 건수 확인
- 문자 작업 상태별 건수 확인
- 예약시각이 지났지만 `SCHEDULED`인 작업 탐지
- 캠페인 수신자와 문자 작업의 상태 불일치 탐지
- 캠페인이 참조하는 문자 작업 누락 탐지
- 작업 없이 진행 상태인 캠페인 수신자 탐지
- 이미지 템플릿 파일 누락 탐지
- 문자 작업을 기준으로 캠페인 수신자 상태와 캠페인 집계 재계산
- 최근 예약 리시버 실행과 SMS 성공·실패를 비식별 이벤트로 제한 저장
- 단일 SIM·듀얼 SIM·권한 거부·제외·중복·장문·예약·재시도·재부팅·100명 캠페인 체크리스트
- 고객명·전화번호·문자 본문을 제외한 기술 진단 정보만 클립보드 복사

안전 기준:

- 상태 재계산은 고객·문자·캠페인 데이터를 삭제하지 않는다.
- 예약시각이 지난 작업을 진단 화면에서 임의로 즉시 발송하지 않는다.
- 연결 작업 누락을 새 문자 발송으로 자동 복구하지 않는다.
- 실제 전송 여부를 확인할 수 없는 상태를 완료로 변경하지 않는다.
- 기술 진단 복사는 데이터 내보내기 유료 기능과 별개다.

검증 방식:

- 기존 PR `#1`이 `main`의 웹 변경과 충돌해 PR용 CI가 생성되지 않아 임시 Draft PR `#2`로 동일 Android 코드를 검증했다.
- Build `#857`에서 Java 컴파일, Debug APK 패키징, `calltag-v0.29.0-debug-apk` 업로드가 모두 성공했다.
- 임시 PR `#2`는 병합하지 않고 닫았다.
- 기능 코드는 `agent/calltag-foundation`에 유지한다.

중요:

- **10차 진단 코드 구현은 완료됐다.**
- **실제 휴대전화와 실제 SIM에서 체크리스트를 수행하는 검수는 아직 남아 있다.**
- 실기기 검수에서 발견되는 오류는 11차로 넘어가기 전 또는 11차와 함께 즉시 수정한다.

## 4. 실제 단말에서 아직 수행해야 할 검수

다음 흐름은 실제 Android 휴대전화와 테스트 번호로 직접 확인해야 한다.

```text
고객 등록
→ 수동 그룹 생성
→ 스마트 그룹 생성
→ 캠페인 작성
→ 고객별 변수 치환
→ 예약 생성
→ 순차 발송
→ 성공·실패 상태 반영
→ 실패 고객 재시도
→ 캠페인 완료
```

필수 체크:

- 단일 SIM 수동·자동·예약 문자
- 듀얼 SIM 선택 회선
- SMS·전화·통화기록·연락처·알림 권한 거부
- 발송 제외 고객
- 그룹 안 중복번호
- 이름 없는 고객
- 잘못된 번호
- 장문 분할 발송
- 앱을 닫은 상태의 예약 발송
- 휴대전화 재부팅 후 예약 상태
- 100명 이상 캠페인 화면·상태 갱신
- 통화 종료 처리와 캠페인 발송 동시 발생

진입 경로:

```text
계정 및 개인정보
→ 앱 상태 진단
→ 자동 점검
→ 실제 단말 E2E 체크리스트
```

## 5. 남은 코드 패치 순서

신규 기능보다 실제 사용자 데이터와 문자 발송 안전을 우선한다.

### 11차 — 앱 종료·재부팅·업데이트 후 예약 복구

- 앱 강제 종료 후 미발송 작업 복구
- 최근 앱 목록 제거 후 복구
- 휴대전화 재부팅 후 AlarmManager 재등록
- 앱 업데이트 후 미발송 작업 재등록
- 예약 시간이 지난 작업의 처리 기준 확정
- 완료·취소·실패 작업 재등록 방지
- 동일 작업 중복 예약 방지
- 복구 결과를 캠페인과 발송내역에 표시
- 진단 이벤트에 복구 시작·성공·실패 기록

### 12차 — SIM 변경과 캠페인 제어

- 선택 회선 제거·비활성화 감지
- 기본 문자 SIM 변경 대응
- 잘못된 subscription ID 복구
- 비행기 모드·서비스 불가 처리
- 캠페인 일시정지·재개
- 연속 실패 시 자동 중단
- 동시에 여러 캠페인이 실행될 때 충돌 방지
- 사용자가 발송 속도와 위험을 이해할 수 있는 안내

### 13차 — DB 정합성·고아 작업 복구

- 캠페인 수신자는 있는데 문자 작업이 없는 경우
- 문자 작업은 있는데 캠페인 수신자가 없는 경우
- 캠페인 삭제 후 알람이 남는 경우
- 취소 직후 늦은 발송 완료 콜백이 도착하는 경우
- 고객 삭제 후 그룹·캠페인에 고객 ID가 남는 경우
- 앱 시작 시 가벼운 무결성 검사
- 문자 DB 기준 캠페인 상태 재계산 자동화
- 복구 항목에 복구 사유 기록

### 14차 — 앱 데이터 백업·복원

이 패치는 진행한다. 단, 외부 데이터 활용을 위한 내보내기와 완전히 분리한다.

백업 대상:

- 고객

- 템플릿 이미지
- 발송 제외 정책
- 그룹
- 캠페인 내역
- 문자 발송내역
- 자동화 설정
- 회선 설정

필수 기준:

## 6. 별도 보류·추후 업데이트 기능

### 6.1 데이터 내보내기 — 유료 확장 기능

상태: **보류, 현재 패치 금지**

예상 범위:

- 고객 목록 CSV·XLSX
- 캠페인 결과 CSV·XLSX
- 조건별 고객 목록 추출
- 관리자용 보고서
- 외부 CRM 이전용 데이터

가격, 권한, 개인정보 경고, 다운로드 만료, 감사 로그를 별도 기획한 뒤 개발한다. 사용자가 다시 승인하기 전 구현하지 않는다.

### 6.2 웹 동기화·웹 관리자

현재 Android 로컬 데이터와 마케팅 웹사이트는 별개다. 앱 데이터가 웹에 실시간 동기화된다고 표현하면 안 된다.

필요한 별도 설계:

- 서버 데이터 모델
- 로그인과 기기 연결
- 암호화와 개인정보 처리
- 충돌 해결
- 오프라인 동기화
- 웹 권한
- 삭제·탈퇴 처리

### 6.3 이미지 단체문자

현재 이미지 템플릿은 수동 문자와 사용자 확인형 예약 문자에서 사용한다. 이미지 단체문자는 구현하지 않았다. 사용자 확인 없이 자동 MMS를 대량 발송하는 기능으로 오해하면 안 된다.

## 7. 다음 작업자가 반드시 지킬 규칙

1. 작업 전 Draft PR `#1`의 최신 HEAD를 다시 확인한다.
2. `main`과 개발 브랜치가 충돌 상태일 수 있으므로 Android 파일과 웹 파일 변경 범위를 분리한다.
3. 같은 브랜치에 다른 변경이 들어올 수 있으므로 파일 SHA를 다시 가져온 뒤 수정한다.
4. 같은 파일을 병렬로 쓰지 않는다.
5. 사용자가 명시적으로 지시하기 전 `main`에 병합하지 않는다.
6. PR은 개발 중 Draft 상태를 유지한다.
7. 문서에 적혀 있다는 이유만으로 구현됐다고 보고하지 않는다.
8. Build 성공은 실제 단말 검증 성공과 다르다고 명시한다.
9. 실제 발송 완료를 확인할 수 없는 이미지 MMS를 `발송 완료`로 표시하지 않는다.
10. 발송 제외·중복방지·일정 상태 검사는 발송 직전까지 유지한다.
11. 기존 고객·문자·템플릿·그룹·캠페인 데이터를 파괴하는 DB 초기화를 하지 않는다.
12. DB 변경 시 기존 데이터 보존 마이그레이션을 작성한다.
13. 자동발송 기본 템플릿과 단체문자는 현재 텍스트 전용 정책을 유지한다.
14. 백업·복원과 데이터 내보내기를 같은 기능으로 합치지 않는다.
15. CSV·XLSX·외부 데이터 내보내기는 사용자가 다시 승인하기 전 구현하지 않는다.
16. 비식별 진단 정보에 고객명·전화번호·문자 본문을 넣지 않는다.
17. 예약시각이 지난 작업을 명시적 정책 없이 자동 발송하지 않는다.
18. 공개 제품명은 콜태그로 통일한다.
