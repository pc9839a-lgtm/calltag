## 2. 현재 핵심 동작

### 전화 수신 메모

- Android Contacts Provider 기반 표시가 주 기능이다.
- 콜태그 전용 RawContact를 생성해 동일 번호의 Google·삼성 연락처와 결합한다.
- 기존 원본 연락처 행은 직접 수정하거나 삭제하지 않는다.
- 표시 형식은 `고객명 · 최근 메모`다.
- 최근 메모는 최대 16자다.
- 이름없는고객은 `고객 + 전화번호 끝 4자리`로 표시한다.
- 앱 사용 중 5초마다 변경 내용을 동기화한다.
- 기능을 끄면 콜태그가 만든 연락처만 삭제한다.

### 통화 종료 정리

- 통화기록 확인 후 전화 앱 종료 전환이 끝난 다음 소형 팝업을 한 번만 실행한다.
- 팝업은 가로 최대 420dp, 세로 최대 560dp다.
- 긴 내용은 팝업 내부에서 스크롤한다.
- 바깥 영역 터치로 닫히지 않는다.
- 사용자가 닫기·저장·제외를 선택하기 전 자동 종료하지 않는다.

### v0.40.8 안정화

- 로그인 확인 서버 응답이 멈춰도 최대 8초 후 저장된 로그인 상태로 진입한다.
- 저장된 세션이 없으면 로그인 화면으로 이동한다.
- 계정 화면의 `앱 상태 진단` 메뉴를 제거했다.
- 일반 사용자 APK의 Manifest에서 DiagnosticActivity 등록을 제거했다.
- 통화 종료 팝업의 최소 높이를 420dp에서 300dp로 낮췄다.
- 작은 화면에서 팝업 여백과 내부 높이를 다시 계산한다.
- Android 11 이상에서는 키보드 높이를 감지해 팝업 높이를 줄인다.
- 키보드가 떠도 하단 저장 버튼은 팝업 하단에 고정한다.
- 헤더·입력창·섹션 여백·문자 입력창 높이를 줄여 첫 화면 밀도를 개선했다.

## 3. 사용자 화면 노출 기준

사용자 화면에 노출하지 않는다.

- 테스트 고객
- 테스트 팝업
- 수신 서비스 호출 여부
- 마지막 진단 시각
- RawContact·Provider·CallScreeningService 같은 내부 용어
- 개발용 상태값과 예외 메시지
- 빌드·브랜치·커밋·서버 응답 원문

사용자 화면에는 다음만 표시한다.

- 현재 기능이 켜졌는지
- 사용자가 해야 할 조치
- 실패했을 때 다시 시도할 방법
- 기존 연락처와 데이터가 어떻게 보존되는지

내부 진단은 사용자 화면과 분리된 개발 문서·로그에서만 관리한다.

## 4. 남은 패치 우선순위

### P0 — 통화 종료 팝업 실기기 회귀 검증

1. 통화 종료 후 소형 팝업이 자동으로 열리는지
2. 손대지 않은 상태로 30초 이상 유지되는지
3. 에이닷·삼성 전화 종료 화면에 다시 밀리지 않는지
4. 화면 잠금·홈·다른 앱 사용 중 각각 열리는지
5. 저장·닫기·제외 전에는 자동 종료하지 않는지

### P1 — 전화 수신 메모 경계 조건

1. 미저장 번호 표시
2. 이름없는고객 표시
3. Google·삼성 동일 번호 연락처 결합
4. 메모 수정 후 5초 이내 갱신
5. 기능 해제 후 콜태그 연락처만 제거

### P1 — 앱 시작 안정화 실기기 QA

1. 정상 네트워크에서 로딩 화면 확인
2. 오프라인에서 8초 이내 저장된 세션으로 진입
3. 만료·손상된 세션에서 로그인 화면 이동
4. 서버 응답이 늦게 도착해도 화면이 두 번 열리지 않는지
5. 로그인·설정·메인 화면 중복 실행 여부

### P1 — 통화 종료 팝업 UX 마감

1. 작은 화면에서 잘림 확인
2. 큰 글자 설정에서 저장 버튼 접근성 확인
3. 키보드 표시 중 팝업 높이 재계산 확인
4. 메모·문자 입력 중 저장 버튼이 가려지지 않는지
5. 저장 중 중복 탭과 Activity 중복 실행 재검증
6. 미응답·거절·발신 실패별 기본 문구 정리

### P1 — 사용자 화면 개발 흔적 추가 정리

- 전화 화면 설정의 테스트 버튼 제거

- 계정 화면의 앱 상태 진단 메뉴 제거
