## 2. 현재 핵심 동작

### 전화 수신 메모

- Android Contacts Provider 기반 표시가 주 기능이다.
- 콜태그 전용 RawContact를 동일 번호의 Google·삼성 연락처와 결합한다.
- 원본 연락처 행은 직접 수정하거나 삭제하지 않는다.
- 표시 형식은 `고객명 · 최근 메모`다.
- 최근 메모는 최대 16자다.
- 앱 사용 중 5초마다 변경 내용을 동기화한다.

### 통화 종료 정리

- 통화기록 확인 후 전화 앱 종료 전환이 끝난 다음 소형 팝업을 한 번만 실행한다.
- 팝업은 가로 최대 420dp, 세로 최대 560dp, 최소 높이 300dp다.
- 긴 내용은 팝업 내부에서 스크롤한다.
- 하단 저장 버튼은 고정한다.
- 바깥 영역 터치로 닫히지 않는다.
- 사용자가 닫기·저장·제외를 선택하기 전 자동 종료하지 않는다.

### 페이지로 문의 자동등록

- 페이지로 문의 큐를 콜태그 로그인 세션으로 조회한다.
- 전화번호 기준으로 신규 고객을 생성하거나 기존 고객을 갱신한다.
- 문의 내용은 고객 메모와 `PAGERO_INQUIRY` 상담이력으로 저장한다.
- `eventId` 수신 기록과 ACK로 동일 문의 중복 등록을 막는다.
- 신규 문의 반영 후 연락처 이름·최근 메모 동기화를 즉시 요청한다.

### v0.40.9 실시간 문의 알림

- 서버는 페이지로 문의 저장 후 개인정보 없는 FCM 데이터 신호를 보낸다.
- 앱은 푸시 신호 수신 직후 문의 큐를 강제 동기화한다.
- 푸시 수신만으로 알림을 띄우지 않는다.
- 고객 DB에 실제 신규·갱신 건수가 반영된 뒤 `페이지로 문의 접수` 알림을 표시한다.
- 동기화 중 추가 푸시가 오면 강제 재동기화를 한 번 예약한다.
- 앱이 열려 있고 실시간 연결 전이면 30초 간격으로 안전 보조 동기화한다.
- 실시간 연결 후에는 앱 사용 중 5분 간격으로 누락 여부만 점검한다.
- 백그라운드 무한 폴링은 하지 않는다.
- GitHub Actions가 Firebase Android 설정 Secret을 BuildConfig에 주입하도록 변경했다.
- 사용자 화면에는 Firebase·토큰·서버 같은 구현 용어를 노출하지 않는다.

## 7. 절대 지켜야 할 규칙

- 콜태그 앱은 `pc9839a-lgtm/calltag` 저장소에서 작업한다.
- 앱 개발 기준 브랜치는 `agent/calltag-foundation`이다.
- 사용자 지시 전 앱 `main`에 병합하지 않는다.
- 앱 PR `#1`은 Draft 상태를 유지한다.
- 페이지로 서버 PR `#48`은 운영 Secret·migration·QA 확인 전 Draft를 유지한다.
