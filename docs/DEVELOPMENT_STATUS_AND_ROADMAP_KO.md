|---|---:|---|

### 데이터 정책

- 앱 데이터 백업·복원은 구현 완료했다.
- 백업은 같은 콜태그 앱의 복구 기능이다.
- CSV·XLSX·고객 목록·캠페인 결과표·연락처 파일·CRM 이전 형식은 구현하지 않는다.
- 데이터 내보내기는 추후 별도 유료 기능으로만 검토한다.
- `.ctbackup`을 일반 데이터 파일로 변환하지 않는다.

### 진단 개인정보 정책

진단 정보에는 앱·Android 버전, 권한, SIM 상태, 작업 건수와 비식별 작업 ID만 포함할 수 있다.

포함 금지:

- 고객명
- 전화번호
- 문자 본문
- 고객 메모
- 고객 목록

## 4. 14차 — 암호화 백업·복원

### 사용자 경로

```text
계정 및 개인정보
→ 백업 및 복원
```

### 백업 형식

```text
확장자 .ctbackup
CTBK 헤더
→ PBKDF2-HMAC-SHA256
→ AES-256-GCM
→ 암호화 ZIP
   ├─ manifest.json
   ├─ databases/calltag*.db
   ├─ preferences/*.json
   └─ files/message_images/*
```

- 사용자 암호 8자 이상
- 암호는 앱이나 파일에 저장하지 않음
- 올바른 암호 없이는 복원 불가
- 파일 형식 버전·앱 버전·패키지명 기록

### 포함 데이터

- 고객·상태·메모
- 통화 활동
- 일정과 일정 종류
- 미정리 통화
- 문자 작업과 발송내역
- 수동·스마트 그룹
- 캠페인과 수신자 상태
- 문자자동화 설정과 선택 회선
- 문자 템플릿과 기본 템플릿 지정
- 발송 제외 정책
- 일정과 후속문자 연결 설정
- 앱 전용 템플릿 이미지

### 제외 데이터

- 로그인 세션과 인증 토큰
- 구독·결제·영수증 상태
- SMS 분할 콜백 임시 상태
- 진단 이벤트·체크리스트
- 임시 캐시
- 외부 연락처 원본

새 기기에서는 본인 계정으로 다시 로그인하고 구독 권한을 서버·스토어 기준으로 다시 확인해야 한다.

### 무결성 검사

복원 전 다음을 검사한다.

- `CTBK` 헤더와 지원 형식 버전
- AES-GCM 인증 태그
- 패키지명 `kr.pagero.calltag`
- 현재 앱보다 새 버전 백업인지
- 허용된 내부 경로만 존재하는지
- ZIP 경로 탈출 여부
- 압축 해제 최대 크기
- 파일별 크기와 SHA-256
- 필수 `calltag.db` 존재

검증 전에는 현재 앱 데이터를 변경하지 않는다.

### 복원·롤백

1. `SENDING` 문자 작업이 있으면 백업·복원을 차단한다.
2. 통화 모니터 서비스를 중지한다.
3. 현재 DB·설정·이미지를 앱 내부 롤백 스냅샷으로 보존한다.
4. 현재 예약 PendingIntent를 취소한다.
5. 검증된 백업 데이터로 교체한다.
6. 현재 앱 DB helper로 마이그레이션을 실행한다.
7. 모든 CallTag DB에 `PRAGMA quick_check`를 실행한다.
8. 템플릿 이미지 누락을 확인한다.
9. DB 정합성과 예약문자 복구를 다시 실행한다.
10. 성공하면 화면을 다시 시작한다.

복원은 병합이 아니라 백업 시점 데이터로 교체한다. 현재 데이터와 백업 데이터를 ID별로 합치지 않는다.

## 5. 남은 실제 단말 검수

14차 필수 시나리오:

- Android 파일 선택기로 `.ctbackup` 생성
- Google Drive·내 파일·제조사 파일 앱 위치 저장
- 올바른 암호 복원
- 잘못된 암호 복원 차단
- 파일 일부 손상·잘림·변조 차단
- 현재 앱보다 새 버전에서 만든 백업 차단
- 이전 앱 DB 버전 백업의 보존 마이그레이션
- 실제 다른 기기로 복원
- 템플릿 이미지 포함·누락 처리
- 예약문자와 일시정지 캠페인 복원
- 복원 실패 유도 후 기존 데이터 자동 롤백
- 500명 캠페인과 다량 이미지가 있는 큰 백업

Build 성공만으로 위 검수를 통과했다고 기록하지 않는다.

기존 10~13차의 실제 SIM·재부팅·제조사 절전·늦은 콜백·고아 데이터 시나리오도 계속 남아 있다.
