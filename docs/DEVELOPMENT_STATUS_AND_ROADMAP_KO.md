| 상태 | 처리 |
|---|---|
| 미래 `SCHEDULED` | 원래 예약시각으로 알람 재등록 |
| 30분 이내 지연 `SCHEDULED` | 현재부터 5초 간격 순차 재등록 |

| 불명확한 `SENDING` | 자동 재발송하지 않고 `FAILED` 전환 |
| `SENT / FAILED / SKIPPED / CANCELLED` | 재등록하지 않음 |

안전장치:

- 동일 문자 작업 ID 기반 PendingIntent 재사용
- 앱 시작·부팅 복구 직렬화
- 완료·취소 작업 중복 등록 차단

### 12차 — SIM 변경과 캠페인 제어

버전: `0.31.0` / versionCode `33`  
기능 HEAD: `60276d48d619bfd11ab991fe71efd53ad0b97600`

#### 캠페인별 회선 저장

캠페인 생성 시 다음 값을 `calltag_campaigns.db`에 저장한다.

- `subscription_id`
- `pause_reason`
- `consecutive_failures`

Campaign DB를 `v1→v2`로 올렸으며 기존 캠페인과 수신자 데이터를 삭제하지 않는 보존 마이그레이션을 적용했다. 구버전 캠페인의 회선값은 `-1`로 시작하며, 진행 중인 구버전 캠페인은 임의 회선으로 발송하지 않고 재개 과정에서 현재 활성 회선을 다시 지정한다.

#### SIM 검사

1차 검사:

```text
예약 알람 실행
→ 캠페인 상태 확인
→ 캠페인에 저장된 SIM 활성 여부 확인
→ 현재 설정의 선택 SIM과 캠페인 SIM 비교
```

2차 검사:

```text
SMS 발송 준비
→ 실제 SmsManager 호출 직전 활성 SIM 재확인
```

다음 경우 남은 발송을 자동 일시정지한다.

- 캠페인에 지정한 SIM 제거
- SIM 비활성화
- eSIM 프로필 비활성화
- 문자 설정에서 다른 회선 선택
- 구버전 캠페인의 회선 정보 없음

수신자를 실패 처리하지 않고 캠페인을 일시정지해 회선 확인 후 재개할 수 있게 한다.

#### 캠페인 일시정지

- 사용자가 상세 화면에서 직접 일시정지 가능
- SIM 변경 감지 시 자동 일시정지
- 연속 통신 오류 발생 시 자동 일시정지
- 남은 `SCHEDULED/READY` 알람 해제
- 문자 작업은 삭제하지 않고 `SCHEDULED`로 보존
- 캠페인 상태는 `PAUSED`
- 중단 사유를 캠페인 화면에 표시
- 이미 통신사로 넘어간 `SENDING` 한 건은 강제로 되돌리지 않음

#### 캠페인 재개

- 현재 활성 SIM이 있어야 재개 가능
- 현재 문자 설정의 선택 SIM을 캠페인 회선으로 다시 저장
- 남은 `SCHEDULED/READY` 작업만 현재 시각부터 4초 간격으로 재배치
- 연속 실패 횟수 초기화
- 이미 완료·실패·건너뜀·취소된 작업은 자동 재개하지 않음

#### 연속 실패 안전장치

다음 통신 오류를 캠페인별 연속 실패로 계산한다.

- `RESULT_ERROR_NO_SERVICE`
- `RESULT_ERROR_RADIO_OFF`
- `RESULT_ERROR_GENERIC_FAILURE`

정책:

- 연속 3회 발생 시 남은 캠페인 자동 일시정지
- 성공 발송 발생 시 연속 실패 횟수 0으로 초기화
- 번호 오류·변수 오류·발송 제외는 통신 연속 실패에 포함하지 않음

#### 동시 캠페인 충돌 방지

- 미완료 또는 일시정지 캠페인이 있으면 새 캠페인 시작 차단
- 일시정지 캠페인 재개 전 다른 미완료 캠페인 확인
- 구버전 데이터에서 동시에 실행되는 캠페인이 발견되면 후순위 캠페인 일시정지
- 한 시점에 하나의 캠페인만 실제 발송 진행

#### 재부팅 복구와 일시정지 연동

앱 시작·재부팅·앱 업데이트 복구가 실행돼도 `PAUSED` 캠페인의 `SCHEDULED/READY` 작업은 알람을 다시 등록하지 않는다. 일시정지 상태와 남은 작업을 그대로 보존한다.

## 4. 실제 단말에서 남은 검수


기존 필수 시나리오:

- 앱 종료·재부팅·업데이트 예약 복구
- 100명 이상 캠페인
- 통화 종료 정리와 캠페인 발송 동시 발생

12차 추가 시나리오:

- 캠페인 진행 중 물리 SIM 제거
- 캠페인 진행 중 eSIM 비활성화
- 캠페인 진행 중 기본 문자 SIM 변경
- 캠페인 진행 중 콜태그 선택 회선 변경
- 비행기 모드에서 연속 발송 실패
- 통신 서비스 없음 상태에서 3회 연속 실패
- 자동 일시정지 후 회선 변경·재개
- 사용자 직접 일시정지 후 앱 종료·재부팅
- 재부팅 후 일시정지 캠페인이 자동 재개되지 않는지 확인
- 캠페인 발송 중 새 캠페인 생성 차단
- 일시정지 캠페인이 있는 상태에서 새 캠페인 생성 차단
- 이미 `SENDING`인 한 건과 남은 예약의 상태 구분

Build 성공만으로 위 항목을 통과했다고 기록하지 않는다.

- 캠페인 삭제 후 예약 알람이 남는 경우
- 취소 직후 늦은 SMS 완료 콜백이 도착하는 경우
- 고객 삭제 후 그룹·캠페인에 고객 ID가 남는 경우
- 문자 작업과 캠페인 상태의 자동 무결성 검사
- 앱 시작 시 가벼운 정합성 점검
- 고아 알람 취소
- 복구 사유 기록
- 데이터 삭제 없이 복구 가능한 항목만 자동 수정

### 14차 — 앱 데이터 백업·복원

이 패치는 진행한다. 외부 데이터 활용을 위한 내보내기와 완전히 분리한다.

- 고객·상태·메모
- 통화 활동

- 발송 제외
- 그룹
- 캠페인·문자 발송내역
- 자동화·회선 설정

- 버전 정보가 포함된 하나의 백업 묶음

## 6. 별도 보류 기능

### 데이터 내보내기 — 유료 확장 기능

상태: **보류, 현재 패치 금지**

예상 범위:

- 고객 목록 CSV·XLSX
- 캠페인 결과 CSV·XLSX
- 조건별 고객 목록 추출
- 외부 CRM 이전용 데이터

가격·권한·개인정보 경고·다운로드 만료·감사 로그를 별도로 기획한 뒤 개발한다. 사용자가 다시 승인하기 전 구현하지 않는다.

### 웹 동기화·웹 관리자

현재 Android 로컬 데이터와 마케팅 웹사이트는 별개다. 앱 데이터가 웹에 실시간 동기화된다고 표현하지 않는다.

### 이미지 단체문자

현재 이미지 템플릿은 수동 문자와 사용자 확인형 예약 문자에 사용한다. 이미지 단체문자는 구현하지 않았다.

## 7. 다음 작업자가 반드시 지킬 규칙

1. 작업 전 Draft PR `#1`의 최신 HEAD를 다시 확인한다.
2. `main`과 개발 브랜치의 웹·Android 변경 범위를 분리한다.
3. 수정 전 각 파일 SHA를 다시 가져온다.
4. 같은 파일을 병렬 수정하지 않는다.
5. 사용자가 명시적으로 지시하기 전 `main`에 병합하지 않는다.
6. PR은 개발 중 Draft 상태를 유지한다.
7. Build 성공을 실제 단말 검증 성공으로 표현하지 않는다.
8. 기존 고객·문자·템플릿·그룹·캠페인 데이터를 초기화하지 않는다.
9. DB 변경 시 보존 마이그레이션을 작성한다.
10. 발송 제외·중복방지·일정 상태·SIM 상태 검사를 실제 발송 직전까지 유지한다.
11. 불명확한 `SENDING` 작업을 자동 재발송하지 않는다.
12. 일시정지 캠페인을 앱 시작·재부팅 복구에서 자동 재개하지 않는다.
13. 이미지 메시지 작성창을 연 상태를 실제 발송 완료로 표시하지 않는다.
14. 자동발송 기본 템플릿과 단체문자는 현재 텍스트 전용이다.
15. 백업·복원과 데이터 내보내기를 합치지 않는다.
16. CSV·XLSX·외부 반출 기능은 사용자가 다시 승인하기 전 구현하지 않는다.
17. 진단 정보에 고객명·전화번호·문자 본문을 넣지 않는다.
18. 공개 제품명은 콜태그로 통일한다.
