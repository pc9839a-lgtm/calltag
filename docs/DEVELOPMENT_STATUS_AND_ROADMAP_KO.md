## 1. 현재 상태 한눈에 보기

콜태그는 현재 다음 기능까지 코드 구현과 Debug APK 빌드가 완료됐다.

- 통화 전 고객 맥락 표시 기반
- 통화 종료 후 고객 상태·메모·일정·문자 정리
- 저장형 문자 템플릿과 변수 치환
- 수신·발신·부재중·후속문자
- 문자 발송 제외와 중복발송 방지
- 고객 상세 문자
- 일정과 후속문자 생명주기 연결
- 이미지 첨부 템플릿과 사용자 확인형 MMS 작성
- 수동 그룹과 스마트 그룹
- 단체문자 캠페인
- 수신자별 발송 상태·취소·재시도

현재 빌드 성공은 **컴파일과 APK 패키징 성공**을 뜻한다. 실제 SIM 발송, 제조사별 백그라운드 제한, 재부팅 복구, 대량 발송 안정성까지 실기기 검증이 끝났다는 뜻은 아니다.

`main`에는 병합하지 않았으며 Draft PR 상태를 유지한다.

## 2. 확정된 제품 기준

### 2.1 단일 제품

- 정식 한글명: `콜태그`
- 정식 영문명: `CallTag`
- 공개 대표 도메인: `https://calltag.pagero.kr`
- Android 앱과 계정은 하나다.
- 전화관리와 문자자동화는 별도 앱이 아니라 콜태그 내부 기능군이다.
- `콜링크`, `페이지로 콜링크`는 레거시 소스 설명에서만 사용한다.
- 공개 앱 UI, 웹사이트, 스토어 소개, 고객 안내에 레거시 명칭을 별도 서비스처럼 노출하지 않는다.

### 2.2 가격 기준

| 상품 | 월 구독료 | 제공 범위 |
|---|---:|---|
| 전화관리 | 1,900원 | 고객·통화·상태·메모·일정·통계 |
| 문자자동화 | 990원 | 템플릿·자동·수동·예약·그룹·단체문자 |
| 통합 이용 | 2,500원 | 전화관리와 문자자동화 전체 및 연결 자동화 |

결제·서버 구독 검증은 아직 출시 수준으로 완료되지 않았다. 개발 빌드에서는 기능 검증을 위해 통합 권한을 기본 적용할 수 있으나, 이를 운영 결제 구현 완료로 표현하면 안 된다.

### 2.3 핵심 사용자 흐름

```text
전화 수신 전 고객 맥락 확인
→ 통화
→ 통화 종료 큰 정리창
→ 고객 상태·메모·다음 할 일 저장
→ 즉시 문자 또는 후속문자
→ 고객 타임라인 반영
```

### 2.4 데이터 정책 확정

- **백업·복원은 향후 필수 패치로 구현한다.**
- 백업은 앱 데이터를 안전하게 보관하고 같은 앱으로 되돌리는 복구 기능이다.
- **CSV·엑셀·외부 파일 형태의 데이터 내보내기는 현재 구현하지 않는다.**
- 데이터 내보내기는 추후 별도 유료 기능으로 기획·개발한다.
- 백업 파일을 일반 고객 목록이나 캠페인 결과 파일처럼 열어 활용하는 기능으로 만들지 않는다.
- 무료·기본 백업 기능에 CSV, XLSX, 범용 연락처 목록, 캠페인 결과표 내보내기를 몰래 포함하지 않는다.

## 4. 아직 완료되지 않은 패치

아래 순서는 신규 기능보다 실제 사용자 데이터와 문자 발송 안전을 우선한 순서다.

## 10차 — 실제 단말 E2E 검증과 진단 패치

목표: 앱 내부 주요 흐름을 실제 Android 단말과 실제 SIM으로 처음부터 끝까지 검증한다.

검증 흐름:

```text
고객 등록
→ 수동 그룹 생성
→ 스마트 그룹 생성
→ 캠페인 작성
→ 고객별 변수 치환
→ 예약 생성
→ 순차 발송
→ 성공·실패 상태 반영
→ 실패 고객 재시도
→ 캠페인 완료
```

필수 검증:

- 단일 SIM
- 듀얼 SIM
- SMS 권한 허용·거부
- 알림 권한 허용·거부
- 발송 제외 고객
- 그룹 안 중복번호
- 이름 없는 고객
- 잘못된 번호
- 장문 분할 발송
- 100명 이상 캠페인
- 통화 종료 처리와 캠페인 발송 동시 발생

필요한 코드:

- 진단 로그 화면 또는 공유 가능한 내부 진단 정보
- 캠페인·문자 작업 ID 연결 확인
- 사용자에게 이해 가능한 실패 사유 정리
- 발견된 크래시·UI 깨짐·중복 실행 패치

## 13차 — DB 정합성·고아 작업 복구

- 캠페인 수신자는 있는데 문자 작업이 없는 경우
- 문자 작업은 있는데 캠페인 수신자가 없는 경우
- 캠페인 삭제 후 알람이 남는 경우
- 취소 직후 늦은 발송 완료 콜백이 도착하는 경우
- 고객 삭제 후 그룹·캠페인에 고객 ID가 남는 경우
- 앱 시작 시 가벼운 무결성 검사
- 문자 DB를 기준으로 캠페인 상태 재계산
- 복구한 항목에 복구 사유 기록

## 14차 — 앱 데이터 백업·복원

이 패치는 진행한다. 단, 외부 데이터 활용을 위한 내보내기 기능과 분리한다.

백업 대상:

- 고객
- 고객 상태와 메모
- 통화 활동
- 일정
- 문자 템플릿
- 템플릿 이미지
- 발송 제외 정책
- 그룹
- 캠페인 내역
- 문자 발송내역
- 자동화 설정
- 회선 설정

필수 기준:

- 하나의 버전 정보가 포함된 백업 묶음 생성
- 백업 무결성 검사
- 복원 전 현재 데이터 안전 보관
- 복원 실패 시 원상 복구
- 구버전 DB 마이그레이션
- 이미지 파일 누락 검사
- 동일 고객·템플릿·캠페인 충돌 기준 정의
- 민감정보 보호

**포함하지 않는 기능:**

- CSV 내보내기
- XLSX 내보내기
- 고객 목록 외부 반출
- 캠페인 결과표 외부 반출
- 범용 연락처 파일 생성
- 다른 서비스로 가져가기 위한 데이터 변환

위 내보내기 기능은 추후 별도 유료 기능으로만 검토한다. 현재 패치에서 구현하지 않는다.

## 5. 별도 보류·추후 업데이트 기능

아래 기능은 현재 남은 필수 패치와 섞지 않는다.

### 5.1 데이터 내보내기 — 유료 확장 기능

상태: **보류, 현재 패치 금지**

추후 별도 상품 또는 상위 요금제 기능으로 검토한다.

예상 범위:

- 고객 목록 CSV·XLSX
- 캠페인 결과 CSV·XLSX
- 조건별 고객 목록 추출
- 관리자용 보고서
- 외부 CRM 이전용 데이터

해당 기능은 별도 기획에서 가격, 권한, 개인정보 경고, 다운로드 만료, 감사 로그를 먼저 확정한 뒤 개발한다.

### 5.2 웹 동기화·웹 관리자

현재 Android 로컬 데이터와 마케팅 웹사이트는 별개다. 앱 데이터가 웹에 실시간 동기화된다고 구현 완료로 표현하면 안 된다.

웹 동기화가 필요하면 별도 대형 패치로 다음을 확정해야 한다.

- 서버 데이터 모델
- 로그인과 기기 연결
- 암호화와 개인정보 처리
- 충돌 해결
- 오프라인 동기화
- 웹 권한
- 삭제·탈퇴 처리

출시 1차 범위에 포함할지는 별도로 결정한다.

### 5.3 이미지 단체문자

현재 이미지 템플릿은 수동 문자와 사용자 확인형 예약 문자에서 사용한다. 이미지 단체문자는 구현하지 않았다. Android 기본 메시지 앱과 사용자 확인 없이 자동 MMS를 대량 발송하는 기능으로 오해하면 안 된다.

## 6. 다음 작업자가 반드시 지킬 규칙

1. 작업 전 Draft PR `#1`의 최신 HEAD를 다시 확인한다.
2. 같은 브랜치에 다른 웹·Android 변경이 동시에 들어올 수 있으므로 파일 SHA를 다시 가져온 뒤 수정한다.
3. 같은 파일을 병렬로 쓰지 않는다.
4. 사용자가 명시적으로 지시하기 전 `main`에 병합하지 않는다.
5. PR은 개발 중 Draft 상태를 유지한다.
6. 문서에 적혀 있다는 이유만으로 구현됐다고 보고하지 않는다.
7. Build 성공은 실제 단말 검증 성공과 다르다고 명시한다.
8. 실제 발송 완료를 확인할 수 없는 이미지 MMS를 `발송 완료`로 표시하지 않는다.
9. 발송 제외·중복방지·일정 상태 검사는 발송 직전까지 유지한다.
10. 기존 고객·문자·템플릿·그룹·캠페인 데이터를 파괴하는 DB 초기화를 하지 않는다.
11. DB 변경 시 기존 데이터 보존 마이그레이션을 작성한다.
12. 자동발송 기본 템플릿과 단체문자는 현재 텍스트 전용 정책을 유지한다.
13. 백업·복원과 데이터 내보내기를 같은 기능으로 합치지 않는다.
14. CSV·XLSX·외부 데이터 내보내기는 사용자가 다시 승인하기 전 구현하지 않는다.
15. 공개 제품명은 콜태그로 통일한다.
