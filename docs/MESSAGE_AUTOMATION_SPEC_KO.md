# 콜태그 문자자동화 상세 명세

기준일: 2026-07-31  
상위 문서: [`CALLTAG_UNIFIED_PRODUCT_PLAN_KO.md`](CALLTAG_UNIFIED_PRODUCT_PLAN_KO.md)

> 이 문서는 콜링크의 문자 기능을 콜태그 안으로 이전할 때 반드시 지켜야 하는 상세 기준이다. 단순한 문자 작성 화면이 아니라 저장형 템플릿, 자동화, 제외, 중복방지, 그룹·단체문자까지 하나의 모듈로 설계한다.

---

## 1. 문자 메뉴 구조

```text
문자
├ 수신
├ 발신
├ 부재중
├ 후속
├ 템플릿
├ 그룹·단체문자
├ 예약·후속문자
├ 발송내역
├ 발송 제외
└ 설정
```

문자 홈 최상단에는 `수신 / 발신 / 부재중 / 후속` 네 자동화 유형을 카드로 보여준다.

각 카드에 표시할 정보:

- 켜짐·꺼짐
- 현재 기본 템플릿
- 발송 시점
- 기본 회선
- 업무시간 적용 여부
- 최근 발송 결과

---

## 2. 자동화 유형

### 2.1 수신

조건:

- 수신 전화
- 실제 연결
- 통화 종료

설정:

- 사용 여부
- 템플릿
- 정리창에서 확인 후 발송 / 자동발송
- 발송 지연 초·분
- 업무시간
- 중복 제한
- 회선

### 2.2 발신

조건:

- 사용자가 발신
- 실제 연결
- 통화 종료

수신과 독립된 템플릿과 규칙을 사용한다.

### 2.3 부재중

조건:

- 부재중 수신
- 거절 수신

사용자 메뉴는 하나로 유지하되 내부 기록에는 `MISSED`와 `REJECTED`를 구분한다.

### 2.4 후속

후속문자는 특정 통화, 고객, 일정 또는 사용자의 수동 선택에 연결되는 예약 문자다.

발송 시점:

- 1일 후
- 3일 후
- 7일 후
- 날짜·시간 직접 선택
- 일정 하루 전
- 일정 시간
- 일정 완료 후

화면의 기능명은 항상 `후속문자`로 표기하고 선택값에서 시점을 보여준다.

## 3. 저장형 문자 템플릿

### 3.1 기본 원칙

콜링크처럼 사용자가 여러 템플릿을 저장하고 반복 사용해야 한다. 자동화 설정에 문구 하나만 저장하는 구조는 금지한다.

### 3.2 템플릿 필드

```text
id
title
body
category
favorite
image_refs
supported_channels
subscription_scope
created_at
updated_at
last_used_at
usage_count
```

### 3.3 템플릿 기능

- 새로 저장
- 수정
- 복제
- 삭제
- 즐겨찾기
- 최근 사용
- 검색
- 카테고리 이동
- 이미지 첨부
- 기본 템플릿 지정
- 회선별 템플릿 지정

### 3.4 기본 템플릿 지정

각 자동화 유형은 템플릿 ID를 참조한다.

```text
수신 → template_id
발신 → template_id
부재중 → template_id
후속 → template_id
```

템플릿 내용이 수정되면 이후 신규 발송에는 최신 내용을 사용한다. 이미 예약된 문자는 생성 당시의 `body_snapshot`을 보존하되 사용자가 원본 변경을 예약문자에도 반영할지 선택할 수 있다.

### 3.5 템플릿 선택 UX

문자 버튼을 누르면 빈 작성창보다 템플릿 선택을 먼저 보여준다.

노출 순서:

1. 즐겨찾기
2. 최근 사용
3. 현재 상황 추천
4. 전체 템플릿
5. 직접 작성

## 4. 변수 치환

### 4.1 지원 변수

```text
{고객명}
{전화번호}
{통화일자}
{통화시간}
{내이름}
{상호명}
{다음일정}
```

### 4.2 치환 데이터 출처

| 변수 | 데이터 출처 |
|---|---|
| `{고객명}` | customer.display_name |
| `{전화번호}` | customer.primary_phone 또는 call_event.phone |
| `{통화일자}` | call_event.started_at |
| `{통화시간}` | call_event.started_at |
| `{내이름}` | 로그인 사용자 이름 |
| `{상호명}` | 계정 브랜드·상호명 |
| `{다음일정}` | 연결된 일정 또는 가장 가까운 미완료 일정 |

### 4.3 검증 규칙

- 저장 시 지원하지 않는 `{...}` 패턴 검출
- 미지원 변수는 저장 전에 경고
- 발송 직전 다시 검증
- 미치환 변수가 남아 있으면 발송 차단
- 고객명 없음: `고객`
- 전화번호 없음: 발송 차단
- 다음 일정 없음: 경고 후 빈값 허용 또는 일정 선택

### 4.4 미리보기

편집 화면에서 실제 고객을 선택하거나 예시 고객으로 치환된 결과를 보여준다.

```text
템플릿
안녕하세요, {고객명}님. {다음일정}에 다시 연락드리겠습니다.

실제 발송
안녕하세요, 김민수님. 8월 3일 오전 10시에 다시 연락드리겠습니다.
```

단체문자에서는 최소 3명의 수신자 미리보기를 제공해 고객별 치환 결과를 확인한다.

## 5. 문자 발송 제외

### 5.1 제외 유형

#### 자동문자 제외

- 수신·발신·부재중 자동문자 차단
- 후속문자 차단
- 단체문자 기본 제외
- 사용자가 고객 상세에서 수동발송 가능

#### 전체 문자 제외

- 자동·후속·예약·단체·수동 모두 차단
- 해제 전에는 발송 버튼 비활성화

#### 특정 유형 제외

- 수신만 제외
- 발신만 제외
- 부재중만 제외
- 후속만 제외

### 5.2 제외 등록

등록 위치:

- 고객 상세
- 문자 > 발송 제외
- 단체문자 대상 검토
- 실패·수신거부 처리

필드:

```text
id
customer_id
normalized_phone
scope
trigger_types
reason
created_at
expires_at
disabled_at
```

### 5.3 발송 직전 검사

모든 발송 경로가 동일한 제외 검사기를 사용한다.

```text
ManualSend
AutomaticSend
ScheduledSend
BulkSend
→ MessageExclusionPolicy.check()
```

화면에서 제외됐다고 표시했더라도 발송 큐 실행 직전에 다시 검사한다.

## 6. 중복발송 방지

### 6.1 중복 범위

- 동일 통화에서 자동문자 한 번
- 동일 통화에서 자동문자와 정리창 수동문자 병합
- 동일 일정에 활성 후속문자 한 건
- 같은 고객·템플릿·본문의 최근 발송 제한
- 같은 번호가 여러 그룹에 포함돼도 캠페인당 한 번
- 예약문자와 즉시문자의 발송 시점 충돌 검사

### 6.2 멱등키

```text
workspace_id
normalized_phone
source_type
source_id
trigger_type
template_id
body_hash
```

예:

- 통화: `source_type=CALL`, `source_id=call_event_id`
- 일정: `source_type=TASK`, `source_id=task_id`
- 단체문자: `source_type=CAMPAIGN`, `source_id=campaign_id`

활성 상태 `QUEUED / SCHEDULED / SENDING / SENT`에서 같은 키를 새로 만들지 않는다.

### 6.3 실패 처리

`FAILED`는 성공 중복으로 계산하지 않는다. 다만 통신사 요청 상태가 불명확한 경우에는 `UNKNOWN`으로 기록하고 즉시 재발송 전에 사용자 확인을 요구한다.

### 6.4 사용자 제한 시간

- 1시간
- 6시간
- 12시간
- 24시간
- 3일
- 7일
- 직접 입력

### 6.5 강제 재발송

다음 정보를 보여준 후 사용자가 직접 승인한다.

```text
같은 고객에게 2시간 전에 동일한 문자를 보냈습니다.
[취소] [그래도 보내기]
```

강제 재발송도 별도 기록한다.

## 7. 고객 상세 문자

고객 상세 상단:

```text
전화 / 일정 추가 / 문자
```

상태 변경은 상태 배지를 누른다.

문자 흐름:

```text
문자
→ 템플릿 선택
→ 치환 미리보기
→ 내용·이미지 수정
→ 지금 보내기 / 예약 / 후속문자
→ 발송
```

발송 전 표시:

- 고객명
- 전화번호
- 선택 회선
- 템플릿명
- 실제 발송 내용
- 최근 중복 여부
- 문자 제외 여부

## 8. 일정과 문자

일정 추가 화면에 `연결 문자`를 포함한다.

선택:

- 없음
- 지금 안내문자
- 일정 하루 전
- 일정 시간
- 일정 완료 후

연결된 예약 문자는 후속문자로 저장한다.

### 8.1 일정 변경

```text
일정 시간이 변경됐습니다.
연결된 후속문자도 변경할까요?
[문자 유지] [함께 변경]
```

기본 선택은 `함께 변경`이다.

### 8.2 일정 완료

- `일정 완료 후` 문자 발송 또는 예약
- 아직 남은 `일정 전` 문자는 취소

### 8.3 일정 삭제

- 연결된 미발송 후속문자 취소
- 취소 이유 `연결된 일정 삭제`

## 9. 그룹

### 9.1 수동 그룹

- 그룹명
- 설명
- 고객 직접 추가·삭제
- 고객 상세에서 그룹 추가

### 9.2 스마트 그룹

조건 기반으로 실시간 계산한다.

조건 예시:

- 고객 상태
- 사용자 태그
- 최근 연락일
- 다음 일정
- 일정 종류
- 통화 결과
- 문자 발송 여부
- 관리공백

복수 조건은 `모두 충족 / 하나 이상 충족`을 지원한다.

### 9.3 그룹 중복

한 고객이 여러 그룹에 들어갈 수 있다. 단체문자 실행 시 전화번호 기준 최종 중복 제거한다.

## 10. 단체문자

### 10.1 캠페인 생성

```text
그룹 선택
→ 추가 고객 선택
→ 제외 고객 선택
→ 템플릿 선택
→ 수신자별 미리보기
→ 지금 발송 / 예약
→ 발송 확인
```

### 10.2 대상 산출

반드시 다음 결과를 보여준다.

```text
그룹 전체 120명
중복번호 제거 8명
자동문자 제외 4명
전체 문자 제외 2명
최근 동일문자 발송 6명
번호 오류 1명
최종 발송 99명
```

자동문자 제외 고객을 단체문자에도 기본 제외한다. 사용자가 수동 발송 가능 대상까지 포함하려면 별도 옵션과 확인이 필요하다. 전체 문자 제외는 절대 포함하지 않는다.

### 10.3 발송 방식

- 수신자별 변수 개별 치환
- 설정 간격으로 순차 발송
- 회선 선택
- 예약 발송
- 진행률 표시
- 남은 발송 취소
- 실패 고객만 재발송

### 10.4 캠페인 상태

```text
DRAFT
READY
SCHEDULED
SENDING
PAUSED
COMPLETED
PARTIAL_FAILED
CANCELLED
```

수신자 상태:

```text
PENDING
EXCLUDED
DUPLICATE
INVALID
SENDING
SENT
FAILED
CANCELLED
```

## 11. 후속문자 취소 정책

발송 직전에 아래 조건을 다시 검사한다.

- 고객과 새 통화 발생
- 고객 상태 완료·종료
- 연결 일정 변경·완료·삭제
- 자동문자 제외 또는 전체 문자 제외
- 같은 목적의 수동문자 발송
- 새 후속문자로 대체
- 구독 만료
- 규칙 비활성화

취소 이유를 사용자에게 숨기지 않는다.

## 13. 통화 종료 정리창과 자동화

수신·발신 자동발송이 활성화된 경우 곧바로 별도 발송 작업을 만들지 않는다.

```text
통화 종료
→ 자동발송 예정 작업 생성
→ 큰 통화 정리창에서 문구 표시
→ 사용자가 수정·취소·확정
→ 저장 시 한 번만 발송
```

정리창을 꺼둔 사용자만 백그라운드 자동발송을 사용한다.

부재중은 정리창 없이 자동발송할 수 있다.

## 16. 검수 기준

- 템플릿을 저장·수정·복제·삭제 후 재실행해도 유지된다.
- 지원 변수는 정확히 치환된다.
- 미지원 또는 미치환 변수가 있으면 발송되지 않는다.
- 전체 문자 제외 고객에게 어떤 경로로도 문자가 발송되지 않는다.
- 자동문자 제외 고객은 수동발송만 명시적 확인 후 가능하다.
- 같은 통화에서 자동·수동문자가 중복 발송되지 않는다.
- 같은 번호가 여러 그룹에 있어도 캠페인당 한 번만 발송된다.
- 단체문자 전에 제외·중복·번호 오류 인원이 표시된다.
- 일정 변경·완료·삭제가 연결 후속문자에 반영된다.
- 발송·제외·중복·취소 사유가 발송내역과 고객 타임라인에 남는다.
