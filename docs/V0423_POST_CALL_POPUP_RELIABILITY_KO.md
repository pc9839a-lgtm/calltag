# CallTag v0.42.3 통화 종료 팝업 신뢰성 패치

- 작성일: 2026-08-04
- 대상: 전화 종료 후 큰 고객 정리 화면
- 버전: `0.42.3` / versionCode `63`
- 브랜치: `docs/billing-referral-app-handoff-20260804`
- 상태: Draft PR 검증용, 운영 병합 전

## 1. 증상

전화 종료 후 큰 정리 화면이 정상 표시되는 경우도 있지만 간헐적으로 표시되지 않았다.

특히 다음 환경에서 재현 가능성이 높았다.

- 짧은 간격으로 연속 통화
- 삼성 전화 또는 에이닷의 통화기록 저장이 늦는 경우
- 통화 종료 직후 전화 앱 화면이 아직 닫히지 않은 경우
- Android가 백그라운드 Activity 실행을 조용히 제한한 경우

## 2. 확인한 직접 원인

### 2.1 이전 통화기록을 발견하면 재시도가 종료됨

기존 로직은 통화 종료 후 최근 2분 범위의 가장 최신 통화기록을 조회했다.

새 통화기록이 아직 시스템 DB에 반영되지 않은 상태에서 바로 전 통화기록이 조회되면 다음 상황이 발생했다.

1. 조회 결과는 `null`이 아님
2. 하지만 이미 처리한 `lastCallId`와 동일함
3. 신규 통화가 아니므로 팝업은 실행하지 않음
4. 그 상태에서 조회 루프를 종료함
5. 몇 초 뒤 실제 신규 통화기록이 저장돼도 더 이상 확인하지 않음

연속 통화에서 팝업이 빠지는 핵심 원인이었다.

### 2.2 PendingIntent 성공을 화면 표시 성공으로 간주함

기존 실행기는 `PendingIntent.send()`가 예외 없이 끝나면 팝업이 실제로 보였다고 간주했다.

Android는 백그라운드 Activity 시작 요청을 제한하면서도 전송 호출 자체는 성공으로 반환할 수 있다. 이 경우 앱은 성공으로 판단해 알림 fallback도 남기지 않았다.

### 2.3 통화기록 재시도 시간이 짧고 변경 감지가 없음

기존 재시도는 제한된 횟수만 수행했다. 제조사 전화 앱에서 통화기록 저장이 더 늦어지면 신규 기록을 찾지 못한 채 종료될 수 있었다.

## 3. 패치 내용

### 3.1 현재 통화기록이 아니면 재시도 유지

다음 조회 결과는 성공으로 처리하지 않고 계속 재시도한다.

- 조회 결과 없음
- 이미 처리한 `lastCallId`
- 현재 통화 시작 시각과 맞지 않는 오래된 기록

신규 통화기록을 실제로 찾거나 최종 제한시간이 끝날 때만 조회 상태를 종료한다.

### 3.2 CallLog ContentObserver 추가

`CallLog.Calls.CONTENT_URI` 변경을 감시한다.

전화 앱이 늦게 통화기록을 저장하더라도 시스템 DB 변경 신호가 오면 250ms 후 즉시 다시 조회한다. 정해진 타이머 재시도와 변경 감지를 함께 사용한다.

### 3.3 재시도 구간 확대

재시도 지연:

```text
0.8초 → 1.2초 → 2초 → 3.5초 → 5.5초 → 8초 → 12초 → 16초
```

단계별 누적 대기와 ContentObserver 즉시 확인을 병행한다.

### 3.4 팝업 실제 표시 확인

`PostCallLaunchReceipt`가 다음 값을 기록한다.

- 실행 요청한 통화기록 ID
- 실행 요청 시각
- 실제 PostCallActivity 시작·재개가 확인된 통화기록 ID
- 실제 표시 확인 시각

`CallTagApplication.ActivityLifecycleCallbacks`에서 PostCallActivity가 생성·시작·재개된 경우에만 표시 성공으로 확정한다.

### 3.5 Android 백그라운드 실행 제한 fallback

첫 실행 요청 후 실제 화면 표시가 확인되지 않으면:

1. 2.4초 후 Activity 실행을 한 번 더 시도
2. 추가 2.4초 후에도 화면 표시가 없으면 큰 정리 알림을 남김
3. 알림을 누르면 해당 통화의 정리 화면으로 이동

따라서 Activity가 조용히 차단돼도 아무 흔적 없이 누락되지 않는다.

### 3.6 이전 팝업 충돌 방지

이전 통화의 PostCallActivity가 아직 남아 있고 새 통화 ID와 다르면 이전 화면을 닫은 뒤 새 통화 화면을 실행한다.

중복 실행 방지는 단순 실행 요청 성공이 아니라 실제 화면 표시가 확인된 경우에만 적용한다.

## 5. 데이터 안전

이번 패치는 다음 항목을 변경하지 않는다.

- 고객 DB
- 상담이력
- 메모
- 문자 발송내역
- 일정
- 추천인·결제 서버 데이터
- 페이지로 문의 연동

통화기록 ID와 팝업 표시 확인 시각만 별도 SharedPreferences에 최소 저장한다.

## 6. 실기기 검증 항목

### 기본

- 수신 통화 종료 후 큰 정리 화면
- 발신 통화 종료 후 큰 정리 화면
- 부재중 전화 후 정리 화면
- 거절 전화 후 정리 화면
- 연결되지 않은 발신 후 정리 화면

### 연속 통화

- 30초 안에 연속 두 번 통화
- 같은 번호 연속 통화
- 다른 번호 연속 통화
- 첫 팝업을 닫지 않은 상태에서 다음 통화

### 앱 상태

- CallTag 전면
- CallTag 백그라운드
- CallTag 화면을 최근 앱에서 제거한 상태
- 잠금화면
- 삼성 전화
- 에이닷 전화

### fallback

- 팝업 Activity 표시가 제한되는 환경에서 알림이 남는지
- fallback 알림을 눌렀을 때 해당 통화 정보가 열리는지
- 동일 통화 팝업이 중복으로 여러 개 열리지 않는지

## 7. 완료 기준

- 이전 통화기록이 조회돼도 신규 기록 재시도가 중단되지 않음
- CallLog 저장 지연 시 변경 감지 후 처리
- PendingIntent 전송 성공과 실제 화면 표시 성공을 분리
- 실제 화면이 안 뜨면 재실행 후 알림 fallback
- 기존 고객·문자·일정 데이터 회귀 없음
- Android 빌드와 정적 계약 검사 성공
