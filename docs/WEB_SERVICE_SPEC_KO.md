# 콜태그 웹 서비스 기획서

기준일: 2026-07-30  
Android 저장소: `pc9839a-lgtm/calltag`  
기준 디자인: 페이지로 콜링크 앱·웹 제품군  
권장 공개 도메인: `https://calltag.pagero.kr`

## 1. 서비스 정의

콜태그 웹은 Android 앱에서 수집·정리한 고객, 통화 후 상담 결과, 일정, 메모를 PC와 모바일 웹에서 조회·수정하는 관리 화면이다.

별도의 독립 CRM을 새로 만드는 것이 아니라 페이지로 콜링크와 같은 계정·데이터·구독 체계를 사용하는 동일 서비스군으로 개발한다.

제품군 역할:

- `페이지로 콜링크`: 통화 종료 후 문자 작성·발송·템플릿 관리
- `페이지로 콜태그`: 고객 분류·상담 이력·일정·후속업무 관리
- `페이지로 비즈니스`: 콜링크와 콜태그를 묶는 공통 계정·결제·웹 관리 체계

사용자에게는 앱이 두 개여도 계정과 데이터는 하나로 인식되어야 한다.

## 2. 도메인 전략

### 2.1 권장 도메인

- 콜태그 웹: `calltag.pagero.kr`

이유:

- 페이지로 브랜드 소유 관계가 즉시 보인다.
- 별도 도메인 구매 없이 SSL·DNS·배포 관리가 단순하다.
- 콜링크와 다른 기능이지만 같은 제품군이라는 점을 유지한다.
- 추후 통합 로그인과 쿠키·인증 정책을 구성하기 쉽다.

### 2.2 향후 통합 도메인

- 통합 포털 후보: `app.pagero.kr`
- 통합 포털 내부 경로:
  - `/calllink`
  - `/calltag`
  - `/account`
  - `/billing`

초기에는 `calltag.pagero.kr`을 독립 진입점으로 사용하고, 통합 포털 구축 후에도 해당 주소를 유지하여 콜태그 화면으로 연결한다.

### 2.3 금지

- 제품마다 완전히 다른 브랜드 도메인 사용
- 앱과 웹의 로그인 계정 분리
- 콜링크 고객과 콜태그 고객을 별도 데이터로 중복 저장

## 3. 웹 서비스의 핵심 목적

웹은 통화 감지 기능을 대체하지 않는다. 통화 감지는 Android 앱이 담당하고, 웹은 다음 업무에 집중한다.

1. 고객과 상담 흐름을 큰 화면에서 확인
2. 월간·주간 일정 관리
3. 고객 상태와 메모 일괄 수정
4. 콜링크 문자 발송 이력과 콜태그 상담 이력을 한 타임라인에서 확인
5. 메시지 템플릿과 후속업무를 연결
6. 데이터 백업·내보내기
7. 계정·구독·기기 관리

## 4. 정보 구조

웹 기본 메뉴는 페이지로 콜링크의 화면 구조와 시각 체계를 그대로 사용한다.

### 4.1 공통 메뉴

1. `홈`
2. `고객`
3. `캘린더`
4. `통화·상담`
5. `문자`
6. `템플릿`
7. `전체`

콜태그만 이용하는 사용자는 문자·템플릿 메뉴에서 콜링크 기능 안내를 볼 수 있다. 콜링크도 이용 중이면 같은 화면에서 바로 사용할 수 있다.

### 4.2 홈

홈은 사용자가 오늘 처리해야 할 항목만 보여준다.

- 기한이 지난 일정
- 오늘 연락할 고객
- 아직 정리하지 않은 통화
- 보내기로 했지만 발송하지 않은 자료·문자
- 신규 고객 수
- 최근 통화
- 빠른 고객 추가

주요 CTA는 하나만 사용한다.

- 기본 CTA: `최근 통화에서 고객 추가`

### 4.3 고객

- 전체·신규·상담 중·기존·VIP·휴면 필터
- 이름·전화번호·메모 검색
- 최근 연락일 정렬
- 다음 일정 유무 표시
- 고객 상태 일괄 변경
- CSV 내보내기

고객 상세:

- 고객 기본정보
- 현재 관계 상태
- 진행 중 상담건
- 예정 일정
- 통화 이력
- 상담 결과
- 콜링크 문자 발송 이력
- 메모
- 상태 변경 이력

### 4.4 캘린더

- 월간·주간·목록 보기
- 일정 종류 필터
- 담당 기능 필터: 전화·미팅·자료·문자
- 드래그로 날짜·시간 변경
- 일정 완료·다시 열기
- 일정 클릭 시 고객 상세 패널 표시

### 4.5 통화·상담

- Android 앱에서 감지한 최근 통화
- 정리 완료·미정리 구분
- 수신·발신 구분
- 통화시간
- 상담 결과
- 고객 연결 상태
- 다음 행동

웹에서 미정리 통화를 처리하면 Android 앱에도 즉시 반영한다.

### 4.6 문자

콜링크 기능을 웹에 그대로 연결한다.

- 발송 예정
- 발송 완료
- 실패
- 고객별 발송 이력
- 통화 후 자동 문자 설정
- 이미지 첨부 내역

### 4.7 템플릿

- 콜링크 문자 템플릿
- 업종별 템플릿
- 고객 상태별 추천 템플릿
- 일정 종류와 문자 템플릿 연결

예:

- 일정 `자료 보내기` 완료 전 → 자료 안내 문자 템플릿 노출
- 일정 `방문·미팅` 전날 → 위치·시간 안내 템플릿 노출

### 4.8 전체

- 계정
- 연결된 Android 기기
- 통화 감지 상태
- 콜링크·콜태그 이용 상태
- 구독·결제
- 제외번호
- 데이터 내보내기
- 개인정보 처리방침
- 회원탈퇴

## 5. 화면 구조

### 5.1 PC

- 좌측 고정 사이드바
- 상단 현재 메뉴명·검색·계정
- 본문 최대 폭 제한
- 목록과 상세를 동시에 보는 2열 구조 허용
- 주요 CTA는 화면 우측 상단에 한 개만 배치

### 5.2 모바일 웹

- 앱과 같은 하단 내비게이션 사용
- 긴 사이드바 사용 금지
- 고객·일정 상세는 전체 화면으로 전환
- Android 앱 설치 사용자는 `앱에서 열기` 제공

### 5.3 디자인 기준

- 페이지로 콜링크와 같은 색상·타이포·카드·버튼·모달 사용
- 콜태그만의 새 디자인 언어를 만들지 않는다.
- 읽기 전용 카드와 클릭 가능한 행을 명확히 구분한다.
- 긴 회색 기본 다이얼로그와 텍스트 목록을 사용하지 않는다.
- 선택지는 실제 버튼·칩·목록 행으로 표현한다.

## 6. 핵심 사용자 흐름

### 6.1 최근 통화에서 고객 추가

1. 웹 홈 또는 고객 화면에서 `최근 통화에서 고객 추가`
2. Android 앱이 동기화한 최근 통화 목록 표시
3. 전화번호·연락처 이름·통화일시 자동 표시
4. 이미 등록된 번호는 `등록됨`으로 표시
5. 미등록 번호 선택
6. 고객명 확인·상태 선택
7. 저장
8. 앱과 웹 고객목록에 즉시 반영

### 6.2 상담 후 일정 생성

1. 고객 상세에서 상담 결과 선택
2. 다음 행동 선택
3. 날짜·시간 지정
4. 저장
5. 캘린더와 Android 홈에 동시에 표시

### 6.3 콜링크 문자와 연결

1. 고객 상세 또는 일정에서 `문자 보내기`
2. 고객 상태·일정 종류에 맞는 콜링크 템플릿 표시
3. 템플릿 선택·수정
4. Android 콜링크 앱에서 발송 또는 예약
5. 발송 결과가 고객 타임라인에 기록

## 7. 데이터 동기화 원칙

- Android 앱은 통화 감지와 오프라인 입력의 원본 역할을 한다.
- 서버는 계정별 고객·일정·이력의 중앙 저장소 역할을 한다.
- 웹은 서버 데이터를 조회·수정한다.
- 앱이 오프라인이면 로컬 SQLite에 먼저 저장하고 연결 시 동기화한다.
- 각 레코드는 `updated_at`, `device_id`, `version`을 가진다.
- 단순 충돌은 최신 수정 우선으로 처리한다.
- 고객 상태·일정 완료·삭제 충돌은 활동 이력에 남기고 사용자에게 알린다.

## 8. 공통 계정과 권한

- 콜링크와 콜태그는 같은 페이지로 계정을 사용한다.
- 한 계정에 여러 Android 기기를 연결할 수 있다.
- 초기 버전은 개인 워크스페이스 하나만 제공한다.
- 팀 기능은 후속 단계에서 `workspace_id` 기준으로 확장한다.
- 앱별 별도 회원가입은 금지한다.

초기 웹 MVP 제외:

- 팀별 권한

- AI 통화 요약
- 회계·세금계산서
- 대규모 콜센터 CTI

## 10. 출시 조건

다음 조건을 만족해야 웹을 공개한다.

- 앱에서 추가한 고객이 웹에 중복 없이 나타난다.
- 웹에서 바꾼 상태가 앱에 반영된다.
- 앱·웹 일정 완료 상태가 일치한다.
- 최근 통화번호가 다른 고객과 잘못 연결되지 않는다.
- 콜링크 문자 이력이 정확한 고객에게 연결된다.
- 탈퇴·데이터 삭제 시 앱과 서버 데이터가 함께 처리된다.
