# 콜태그 14차 패치 — 앱 데이터 백업·복원 기준

기준일: 2026-08-01  
대상 버전: `0.33.0` / versionCode `35`  
대상 브랜치: `agent/calltag-foundation`

## 목적

기기 변경, 앱 장애, 데이터 손상에 대비해 콜태그 앱 데이터를 하나의 전용 백업 파일로 보존하고 같은 콜태그 앱에서 복원한다. 이 기능은 고객 목록이나 캠페인 결과를 외부 업무에 활용하는 데이터 내보내기가 아니다.

## 백업 대상

- `calltag`로 시작하는 앱 전용 SQLite DB
  - 고객·상태·메모·통화 활동·일정
  - 문자 작업·발송내역
  - 수동·스마트 그룹
  - 캠페인·수신자 상태
  - 일정 종류
  - 미정리 통화
- 문자자동화 설정과 선택 회선
- 템플릿과 기본 템플릿 지정
- 문자 발송 제외 정책
- 일정과 후속문자 연결 설정
- 앱 전용 템플릿 이미지

## 백업 제외

- 로그인 세션과 인증 토큰
- 구독·결제·영수증 상태
- SMS 분할 콜백 임시 상태
- 진단 체크리스트와 진단 이벤트
- 복구 실행 로그와 임시 캐시
- 외부 연락처 원본

새 기기에서 복원하더라도 사용자는 자신의 콜태그 계정으로 다시 로그인해야 하며 구독 권한은 서버·스토어 기준으로 다시 확인한다.

## 파일 형식

확장자: `.ctbackup`

구조:

```text
CTBK 전용 헤더
→ PBKDF2-HMAC-SHA256로 사용자 암호에서 키 파생
→ AES-256-GCM 암호화
→ 내부 ZIP
   ├─ manifest.json
   ├─ databases/calltag*.db
   ├─ preferences/*.json
   └─ files/message_images/*
```

- 암호는 앱이나 백업 파일에 저장하지 않는다.
- 암호를 잊으면 복원할 수 없다.
- 내부 데이터는 암호화 전용 패키지이며 CSV·XLSX·연락처 파일을 만들지 않는다.
- 파일 형식 버전과 앱 버전을 manifest에 기록한다.

## 무결성 검사

복원 전에 다음을 전부 확인한다.

- `CTBK` 전용 헤더
- 지원하는 형식 버전
- AES-GCM 인증 태그
- 패키지명 `kr.pagero.calltag`
- 허용된 내부 경로만 존재하는지
- 각 파일 크기
- 각 파일 SHA-256
- ZIP 경로 탈출 여부
- 압축 해제 최대 용량
- SQLite `PRAGMA quick_check`

검증이 끝나기 전 현재 앱 데이터는 건드리지 않는다.

## 복원과 롤백

1. 현재 발송 중인 `SENDING` 문자 작업이 있으면 복원을 차단한다.
2. 통화 모니터 서비스를 중지한다.
3. 현재 DB·설정·이미지를 앱 내부 롤백 스냅샷으로 보존한다.
4. 기존 예약 PendingIntent를 모두 취소한다.
5. 검증된 백업 데이터로 교체한다.
6. 각 DB를 현재 앱 버전의 SQLiteOpenHelper로 열어 보존 마이그레이션을 실행한다.
7. DB `quick_check`, 템플릿 이미지 누락, 데이터 정합성을 다시 검사한다.
8. 예약문자 복구를 실행한다.
9. 모든 단계가 성공하면 롤백 스냅샷을 삭제한다.

교체 또는 검증 중 오류가 발생하면 즉시 롤백 스냅샷으로 되돌리고 실패 사유를 표시한다.

## 충돌 정책

복원은 병합이 아니라 **백업 시점의 앱 데이터로 교체**한다.

- 현재 고객과 백업 고객을 ID별로 합치지 않는다.
- 현재 캠페인과 백업 캠페인을 중복 생성하지 않는다.
- 현재 템플릿 이미지 디렉터리는 백업 이미지 디렉터리로 교체한다.
- 로그인 세션과 결제 권한은 현재 기기 값을 유지한다.
- 백업에 없는 선택적 DB·설정은 현재 앱의 기본값으로 다시 생성한다.

병합 복원은 고객·문자·일정 ID 충돌과 중복발송 위험이 있어 이번 범위에서 구현하지 않는다.

- 암호 입력
- 복원 전 최종 경고
- 백업·복원 결과와 포함 항목 수 표시
- 복원 성공 후 앱 화면 다시 시작
