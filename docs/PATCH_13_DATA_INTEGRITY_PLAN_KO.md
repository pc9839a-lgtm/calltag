# 콜태그 13차 패치 — 데이터 정합성·고아 작업·남은 알람 복구 기준

기준일: 2026-07-31  
대상 버전: `0.32.0` / versionCode `34`  
대상 브랜치: `agent/calltag-foundation`

## 목적

문자 작업 DB, 캠페인 DB, 고객 DB, 그룹 DB가 서로 다른 파일로 분리돼 있기 때문에 앱 종료·삭제·업데이트·부분 실패 이후 연결 정보가 어긋날 수 있다. 13차는 없는 데이터를 임의 생성하거나 문자를 자동 재발송하지 않고, 오발송 위험이 있는 고아 작업을 차단하고 안전하게 참조를 정리한다.

## 복구 원칙

1. 고객·문자·캠페인 이력을 초기화하거나 전체 삭제하지 않는다.
2. 연결 대상이 없는 활성 문자 작업은 발송하지 않고 `CANCELLED` 처리한다.
3. 문자 작업이 없는 활성 캠페인 수신자는 새 문자를 만들지 않고 `FAILED` 처리한다.
4. 완료·실패·건너뜀·취소 작업에 남아 있을 수 있는 AlarmManager PendingIntent는 취소한다.
5. 일시정지 캠페인은 무결성 검사나 재부팅 복구로 자동 재개하지 않는다.
6. 이미 통신사로 전달됐을 수 있는 `SENDING` 작업은 자동 재발송하지 않는다.
7. 취소·실패 이후 늦게 도착한 SMS 결과 콜백은 현재 최종 상태를 덮어쓰지 않는다.
8. 삭제된 고객 ID가 수동 그룹에 남아 있으면 그룹 멤버 참조만 제거한다.
9. 캠페인 이력의 고객 스냅샷은 과거 발송 기록이므로 고객 삭제만으로 삭제하지 않는다.
10. 복구 결과에는 고객명·전화번호·문자 본문을 기록하지 않는다.

## 자동 검사 시점

- 앱 프로세스 시작
- 휴대전화 재부팅 후 예약 복구 완료 시점
- 앱 업데이트 후 예약 복구 완료 시점
- 앱 상태 진단 화면의 수동 `정합성 복구` 실행

동시에 여러 검사가 요청돼도 한 번씩 직렬 실행한다.

## 검사·복구 항목

### 1. 캠페인 수신자 → 문자 작업 연결 누락

- `message_id > 0`인데 `message_jobs`에 작업이 없는 경우
- 수신자가 `SCHEDULED`, `READY`, `SENDING`이면 `FAILED`
- 사유: `연결된 문자 작업을 찾을 수 없어 자동 발송하지 않았습니다.`
- 캠페인 집계를 다시 계산한다.

### 2. 작업 없는 진행 수신자

- `message_id = 0`인데 수신자가 진행 상태인 경우
- 새 문자 작업을 만들지 않는다.
- `FAILED`로 전환하고 복구 사유를 남긴다.

### 3. 문자 작업 → 캠페인 또는 수신자 연결 누락

- `campaign_id`가 있는데 캠페인이 없는 활성 작업
- 캠페인은 있지만 해당 `message_id`를 가진 수신자가 없는 활성 작업
- 예약 알람을 취소하고 문자 작업을 `CANCELLED` 처리한다.
- 이미 최종 상태인 작업은 상태를 바꾸지 않고 남은 알람만 취소한다.

### 4. 최종 상태 작업의 남은 알람

대상:

- `SENT`
- `FAILED`
- `SKIPPED`
- `CANCELLED`

문자 작업 ID 기반 PendingIntent를 취소한다. AlarmManager 자체 목록은 조회할 수 없으므로 DB의 최종 상태 작업 ID를 기준으로 멱등 취소한다.

### 5. 캠페인 삭제

캠페인 내역을 삭제하기 전에 해당 캠페인의 `SCHEDULED`, `READY` 작업 알람을 취소하고 문자 작업을 `CANCELLED` 처리한다. `SENDING` 작업은 결과 불명확 상태이므로 자동 취소·재발송하지 않고 캠페인 삭제를 차단한다.

### 6. 늦은 SMS 결과 콜백

SMS 콜백 수신 시 현재 상태가 다음이면 결과를 무시한다.

- `CANCELLED`
- `SKIPPED`
- `FAILED`
- 이미 `SENT`

늦은 콜백은 진단 이벤트에 비식별 작업 ID와 무시 사유만 기록한다. 현재 최종 상태와 캠페인 집계를 덮어쓰지 않는다.

### 7. 삭제 고객의 수동 그룹 참조

`message_group_members.customer_id`가 현재 `customers.id`에 없으면 해당 멤버 행만 삭제한다. 스마트 그룹은 실행 시 고객 DB를 다시 계산하므로 별도 정리가 필요 없다.

### 8. 캠페인 상태 재계산

문자 작업과 수신자 정합성 복구 후 모든 캠페인을 문자 작업 기준으로 동기화하고 전체·진행·완료·실패·건너뜀·취소 집계를 다시 계산한다. `PAUSED` 캠페인에 활성 작업이 남아 있으면 `PAUSED` 상태를 유지한다.

## 사용자 화면

`계정 및 개인정보 → 앱 상태 진단`의 기존 `상태 재계산`을 `정합성 복구`로 확장한다.

표시할 항목:

- 고아 캠페인 문자 작업
- 연결 문자 작업 누락 수신자
- 작업 없는 진행 수신자
- 최종 상태 알람 정리 건수
- 삭제 고객 그룹 참조 정리 건수
- 늦은 SMS 콜백 무시 건수
- 마지막 자동·수동 복구 시각과 요약

진단 복사 정보에는 고객명·전화번호·문자 본문을 포함하지 않는다.

## 현재 패치에서 하지 않는 것

- 누락 문자 작업 자동 재생성
- 고아 작업 자동 재발송
- 고객 목록 CSV·XLSX 내보내기
- 캠페인 결과 외부 반출
- 백업·복원 구현
- 외부 CRM 데이터 변환

백업·복원은 14차에서 진행한다. 데이터 내보내기는 별도 유료 기능으로 계속 보류한다.

## 완료 기준

- 보존 마이그레이션 없이 기존 DB를 초기화하지 않는다.
- 자동 복구가 여러 번 실행돼도 추가 발송이나 상태 반복 변경이 없다.
- 고아 활성 작업이 실제 발송되지 않는다.
- 캠페인 수신자와 문자 작업의 상태가 재계산 후 일치한다.
- 최종 상태 작업의 예약 PendingIntent가 멱등 취소된다.
- 늦은 콜백이 취소·실패 상태를 완료로 바꾸지 않는다.
- Java 컴파일, Debug APK 패키징, APK 아티팩트 업로드가 성공한다.
- 실제 휴대전화 검수 항목은 코드 빌드 완료와 별도로 문서에 남긴다.
