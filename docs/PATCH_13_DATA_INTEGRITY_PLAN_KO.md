## 목적

문자 작업 DB, 캠페인 DB, 고객 DB, 그룹 DB는 서로 다른 파일로 분리돼 있다. 앱 종료·삭제·업데이트·부분 실패 이후 연결 정보가 어긋나면 이미 취소된 문자가 발송되거나 캠페인 상태가 실제 문자 작업과 다르게 표시될 수 있다.

13차는 없는 데이터를 임의 생성하거나 문자를 자동 재발송하지 않고, 오발송 위험이 있는 고아 작업을 차단하고 잘못된 참조와 남은 알람을 안전하게 정리한다.

## 확정 복구 원칙

1. 고객·문자·캠페인 이력을 전체 초기화하거나 삭제하지 않는다.
2. 연결 대상이 없는 활성 문자 작업은 발송하지 않고 `CANCELLED` 처리한다.
3. 문자 작업이 없는 활성 캠페인 수신자는 새 문자를 만들지 않고 `FAILED` 처리한다.
4. 완료·실패·건너뜀·취소 작업에 남아 있을 수 있는 PendingIntent를 취소한다.
5. 일시정지 캠페인은 무결성 검사나 재부팅 복구로 자동 재개하지 않는다.
6. 이미 통신사로 전달됐을 수 있는 `SENDING` 작업은 자동 재발송하지 않는다.
7. 취소·실패 이후 늦게 도착한 SMS 결과 콜백은 현재 최종 상태를 덮어쓰지 않는다.
8. 삭제된 고객 ID가 수동 그룹에 남아 있으면 그룹 멤버 참조만 제거한다.
9. 캠페인 수신자의 고객명·전화번호·본문 스냅샷은 과거 발송 기록이므로 고객 삭제만으로 제거하지 않는다.
10. 복구 결과와 진단 정보에 고객명·전화번호·문자 본문을 기록하지 않는다.

## 자동 검사 시점

- 앱 프로세스 시작
- 휴대전화 재부팅 후 예약 복구 완료 시점
- 앱 업데이트 후 예약 복구 완료 시점
- 앱 상태 진단 화면의 수동 `정합성 복구` 실행

자동 실행 순서:

```text
예약문자 복구
→ 데이터 정합성 검사
→ 고아 작업 차단·참조 정리
→ 캠페인 상태 재동기화
```

앱 시작과 부팅 복구는 각각 하나의 백그라운드 흐름에서 순차 실행한다.

## 구현 항목

### 1. 캠페인 수신자 → 문자 작업 연결 누락

- `message_id > 0`인데 `message_jobs`에 작업이 없으면 수신자를 `FAILED`
- `message_id = 0`인데 수신자가 진행 상태면 수신자를 `FAILED`
- 문자 작업의 `campaign_id`와 수신자의 캠페인 ID가 다르면 수신자를 `FAILED`
- 복구 사유를 수신자 상태에 기록
- 누락 문자 작업 자동 재생성 금지
- 자동 재발송 금지

### 2. 문자 작업 → 캠페인·수신자 연결 누락

고아 작업 조건:

- `campaign_id`가 있는데 캠페인이 없음
- 캠페인은 있지만 해당 `message_id`를 참조하는 수신자가 없음

처리:

| 작업 상태 | 처리 |
|---|---|
| `SCHEDULED / READY` | 예약 알람 취소 후 `CANCELLED` |
| `SENDING` | 자동 재발송 금지, `FAILED` |
| `SENT / FAILED / SKIPPED / CANCELLED` | 상태 유지, 남은 알람 취소 |

### 3. 최종 상태 작업의 남은 알람

최근 예약 범위의 다음 작업 ID를 기준으로 동일 PendingIntent 취소를 멱등 실행한다.

- `SENT`
- `FAILED`
- `SKIPPED`
- `CANCELLED`

Android는 앱이 AlarmManager 전체 목록을 조회하는 API를 제공하지 않으므로 DB의 작업 ID를 이용해 기존 PendingIntent와 동일한 식별자로 취소한다.

### 4. 늦은 SMS 결과 콜백

SMS 결과 콜백은 현재 문자 작업이 실제 `SENDING`일 때만 반영한다.

다음 상태에 늦게 도착한 성공·실패 콜백은 무시한다.

- `SENT`
- `FAILED`
- `SKIPPED`
- `CANCELLED`
- 그 밖의 `SENDING`이 아닌 상태

따라서 취소된 작업이 늦은 성공 콜백으로 다시 `SENT`가 되는 문제를 차단한다. 무시 횟수와 비식별 작업 ID만 진단 기록에 남긴다.

고객이 이미 삭제된 경우에는 문자 결과 타임라인을 새로 삽입하지 않는다.

### 5. 삭제 고객의 수동 그룹 참조

현재 `customers.id`에 없는 `message_group_members.customer_id` 행만 제거한다.

- 수동 그룹의 잘못된 참조만 정리
- 스마트 그룹은 실행 시 현재 고객 DB로 재계산
- 캠페인 과거 수신자 스냅샷은 유지

### 6. 캠페인 삭제 안전장치

캠페인 내역 삭제 전에 다음을 실행한다.

- 연결된 문자 작업 PendingIntent 취소
- 남은 `SCHEDULED/READY` 작업 `CANCELLED`
- 이미지 예약 구성 정보 정리
- `SENDING` 작업이 있으면 결과 확인 전 삭제 차단
- 개별 문자 발송내역 유지

### 7. 캠페인 상태 재동기화

정합성 복구 후 모든 캠페인을 문자 작업 기준으로 동기화한다.

- 수신자 상태와 사유 갱신
- 수신자 예약시각 갱신
- 전체·진행·완료·실패·건너뜀·취소 집계 재계산
- 활성 작업이 남은 `PAUSED` 캠페인은 일시정지 상태 유지

### 8. 앱 상태 진단

`계정 및 개인정보 → 앱 상태 진단`의 기존 `상태 재계산`을 `정합성 복구`로 확장했다.

표시 항목:

- 고아 캠페인 문자 작업
- 연결 문자 작업 누락 수신자
- 작업 없는 진행 수신자
- 캠페인 연결 ID 불일치
- 삭제 고객 그룹 참조
- 늦은 SMS 콜백 누적 무시 건수
- 마지막 자동·수동 복구 시각과 요약

추가 실기기 체크리스트:

- 고아 예약 작업 발송 차단
- 취소 후 늦은 SMS 콜백 상태 보호
- 캠페인 삭제 후 알람 미실행
- 삭제 고객 그룹 참조 정리
