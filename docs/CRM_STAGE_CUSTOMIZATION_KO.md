# 콜태그 영업 단계 커스텀 기준

## 1. 목적

콜태그의 고객 상태는 고객의 등급을 매기기 위한 값이 아니다.

영업자가 현재 고객과의 일이 어디까지 진행됐는지 빠르게 확인하고, 다음 행동을 놓치지 않기 위한 진행 단계다.

따라서 `VIP`, `우수 고객`처럼 영업 현장에서 기준이 불명확한 등급은 기본 상태로 사용하지 않는다.

## 2. 기본 영업 단계

최초 설치 시 아래 단계를 제공한다.

1. 신규 문의
2. 요구 확인
3. 견적·자료 발송
4. 검토 중
5. 계약 예정
6. 계약 완료

이 단계는 예시일 뿐이며 사용자가 직접 수정할 수 있다.

## 3. 커스텀 가능 범위

사용자는 앱에서 다음 작업을 할 수 있어야 한다.

- 단계 추가
- 단계 이름 변경
- 단계 순서 변경
- 단계 삭제

단계명은 최대 18자로 제한한다.

영업 단계는 최소 1개를 유지한다.

단계를 삭제하면 해당 단계에 있던 고객은 남아 있는 첫 번째 단계로 이동한다.

## 4. 유입경로 정책

유입경로는 고객 등록 필수값으로 사용하지 않는다.

고객에게 매번 유입경로를 확인해야 하는 구조는 실제 통화 후 입력 흐름을 방해하므로 Android MVP의 고객 등록·상세 화면에서 제거한다.

향후 광고·웹 문의·콜링크 등 시스템에서 자동으로 확인할 수 있는 경우에만 내부 메타데이터로 저장한다.

## 5. 고객 목록 UX

### 상단

- `+ 고객 추가`: 주요 행동 버튼
- `전체 상태 ▾`: 상태 필터 버튼
- `영업 단계 편집`: 단계 관리 버튼

고정된 2×2 상태 필터는 사용하지 않는다. 단계 개수가 사용자마다 달라질 수 있기 때문이다.

### 고객 카드

고객 카드에는 다음을 표시한다.

- 고객명
- 전화번호
- 최근 연락일
- 현재 영업 단계 버튼
- `고객 상세 보기 ›`

현재 영업 단계는 읽기 전용 배지가 아니라 `단계명 ▾` 형태의 명확한 버튼으로 표시한다.

이 버튼을 누르면 고객 상세 화면에 들어가지 않고도 상태를 즉시 변경할 수 있어야 한다.

카드의 나머지 영역을 누르면 고객 상세 화면으로 이동한다.

## 6. 상태 변경 기록

고객 상태를 변경하면 다음 정보를 활동 이력에 남긴다.

- 변경 전 단계
- 변경 후 단계
- 변경 시각

예시:

`요구 확인 → 견적·자료 발송`

단계 이름이 변경되면 해당 단계를 사용 중인 고객의 상태명도 함께 변경한다.

## 7. 통화 후 처리 원칙

새 고객은 사용자가 설정한 첫 번째 단계에 등록한다.

통화 결과나 일정 등록만으로 고객 단계를 강제로 자동 변경하지 않는다.

계약 완료 결과를 선택한 경우에만 사용자가 설정한 마지막 단계로 이동할 수 있다.

## 8. UI 구분 규칙

- 주요 실행: 채워진 파란 버튼
- 보조 실행: 테두리·배경이 있는 보조 버튼
- 선택형 상태: `단계명 ▾` 버튼
- 화면 이동: 우측 화살표가 있는 전체 행
- 읽기 전용 정보: 배경·화살표·눌림 효과 없음

일반 텍스트에 클릭 기능만 붙이는 방식은 사용하지 않는다.

## 9. 캘린더 안정화 규칙

- 선택 날짜는 파란 배경과 흰색 글자로 표시한다.
- 오늘 날짜는 테두리로 표시한다.
- 일정이 있는 날짜는 하단 점으로 표시한다.
- 날짜 셀 높이와 바깥 여백을 확보해 선택 배경이 잘리지 않게 한다.
- 큰 글자 환경에서도 날짜와 일정 표시가 겹치지 않아야 한다.

## 10. 이번 패치 범위

- DB 버전 2 마이그레이션
- 기존 `NEW`, `CONSULTING`, `EXISTING`, `VIP`, `DORMANT` 값 변환
- VIP 기본 상태 제거
- 유입경로 입력·표시 제거
- 영업 단계 추가·이름 변경·순서 변경·삭제 화면
- 고객 목록 상태 필터 선택형 전환
- 고객 카드에서 상태 즉시 변경
- 고객 상세에서 커스텀 단계 선택
- 캘린더 선택 배경과 일정 표시 잘림 개선
