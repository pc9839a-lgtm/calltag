## 1. 제품 정의

콜태그는 전화가 오기 전 고객 맥락을 확인하고, 통화가 끝난 뒤 고객 상태·메모·일정·문자를 한 번에 처리하며 필요한 시점의 후속문자와 고객 그룹 대상 단체문자까지 연결하는 Android 고객관리 앱이다.

> 전화 한 통을 고객관리 행동으로 끝냅니다.

기본 전화 앱을 교체하지 않으며 통화녹음·AI 요약 앱과 공존한다.

## 3. 핵심 흐름

```text
전화 수신 전 고객 맥락 확인
→ 통화
→ 통화 종료 큰 정리창
→ 고객 상태·메모·다음 할 일 저장
→ 즉시 문자 또는 후속문자
→ 고객 타임라인 반영
```

사용자에게 내부 기술 용어와 긴 설정 절차를 핵심 화면으로 노출하지 않는다.

## 4. 전화·고객·일정

### 통화 종료 정리

- 고객명
- 고객 상태
- 통화 결과
- 통화 메모
- 다음 할 일 종류와 시각
- 문자 템플릿과 치환된 문구
- 후속문자 시점
- 저장만 하기
- 저장하고 문자 보내기

### 고객 상세

```text
전화 / 일정 추가 / 문자
```

상태 변경은 고객명 옆 상태 배지에서 처리한다.

### 일정 연결 문자

- 없음
- 지금 안내문자
- 일정 하루 전
- 일정 시간
- 일정 완료 후

일정 변경·완료·삭제·다시 열기와 통화에 의한 자동 완료가 연결 문자의 예약·발송·취소 상태에 반영돼야 한다. 발송 직전에도 현재 일정 상태를 다시 검사한다.

---

## 5. 문자 자동화

문자 기능 유형:

```text
수신 / 발신 / 부재중 / 후속
```

후속문자 시점:

```text
1일 후 / 3일 후 / 7일 후 / 직접 선택
일정 하루 전 / 일정 시간 / 일정 완료 후
```

### 저장형 템플릿

- 저장·수정·복제·삭제
- 즐겨찾기·최근 사용·검색
- 이미지 첨부
- 수신·발신·부재중·후속 기본 템플릿

지원 변수:

```text
{고객명}
{전화번호}
{통화일자}
{통화시간}
{내이름}
{상호명}
{다음일정}
```

미지원 변수나 미치환 변수가 남으면 발송을 차단한다.

### 이미지 문자

이미지 템플릿은 수동 문자와 사용자 확인형 예약 문자에 사용한다. 기본 메시지 앱 작성창을 열고 사용자가 최종 전송한다. 콜태그가 확인할 수 없는 실제 전송 완료를 허위로 표시하지 않는다. 자동발송 기본 템플릿과 단체문자는 현재 텍스트 전용이다.

---

## 6. 문자 안전 정책

### 발송 제외

- 자동문자 제외
- 전체 문자 제외
- 수신·발신·부재중·후속 유형별 제외

제외 건은 `FAILED`가 아니라 `SKIPPED`로 기록하고 사유를 남긴다.

### 중복발송 방지

- 같은 통화의 같은 목적 문자 한 번
- 자동발송과 수동발송 충돌 방지
- 같은 일정의 활성 후속문자 한 건
- 같은 캠페인의 같은 번호 한 번
- 최근 동일 템플릿·본문 제한
- 실패·제외·취소는 성공 중복으로 처리하지 않음

### 발송 직전 재검사

예약시각이 됐더라도 다음을 다시 확인한다.

- 문자 이용 권한
- SMS 권한
- 발송 제외
- 중복방지
- 미치환 변수
- 일정 생명주기
- 업무시간
- 회선 유효성

회선 유효성 강화는 12차 패치 범위다.

## 9. 예약 복구 정책

앱 시작, 휴대전화 재부팅, 앱 업데이트 후 미완료 문자 작업을 다시 점검한다.

| 상태 | 복구 기준 |
|---|---|
| 미래 `SCHEDULED` | 원래 예약시각으로 알람 재등록 |
| 30분 이내 지연 `SCHEDULED` | 현재부터 5초 간격 순차 재등록 |
| 30분 초과 지연 `SCHEDULED` | 늦은 오발송 방지를 위해 `SKIPPED` |
| 멈춘 `READY` | `SCHEDULED`로 복구 후 위 기준 적용 |
| 불명확한 `SENDING` | 자동 재발송하지 않고 `FAILED` 전환 |
| `SENT / FAILED / SKIPPED / CANCELLED` | 재등록하지 않음 |

복구 실행은 직렬화한다. 같은 문자 작업 ID의 PendingIntent를 재사용해 중복 알람을 방지한다. 캠페인에 연결된 작업 상태가 변경되면 수신자와 캠페인 집계를 다시 동기화한다.

`SENDING` 자동 재발송을 금지하는 이유는 통신사 전송은 완료됐지만 앱 콜백만 유실됐을 가능성이 있기 때문이다. 사용자가 발송내역을 확인한 뒤 명시적으로 재시도한다.

1. SIM 변경 대응, 캠페인 일시정지·재개, 연속 실패 자동 중단
2. DB 정합성·고아 작업·남은 알람 복구

4. 캠페인 수신자 검색·필터·선택 작업

CSV·엑셀·외부 데이터 내보내기는 위 순서에 포함하지 않는다.

## 13. 성공 기준

- 통화 종료 후 고객관리와 문자를 한 화면에서 처리한다.
- 템플릿과 고객 데이터가 앱 재실행 후 유지된다.
- 미치환 변수·제외 고객·중복 요청이 잘못 발송되지 않는다.
- 일정 변경·완료·삭제가 연결 문자에 반영된다.
- 캠페인은 고객별 상태와 실패 사유를 남긴다.
- 앱 종료·재부팅·업데이트 후 예약 작업을 안전하게 복구한다.
- 늦은 예약과 불명확한 발송을 자동 재발송해 중복문자를 만들지 않는다.
- 기술 진단에서 고객 개인정보를 노출하지 않는다.
- 실제 운영 결제와 권한이 요금제 기준대로 적용된다.
