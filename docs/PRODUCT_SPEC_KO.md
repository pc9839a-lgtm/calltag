# 콜태그 제품 기획서

기준일: 2026-07-30  
저장소: `pc9839a-lgtm/calltag`  
패키지명: `kr.pagero.calltag`  
권장 웹 도메인: `https://calltag.pagero.kr`

## 1. 제품 정의

콜태그는 업무용 Android 휴대폰의 통화 흐름을 기반으로 고객을 식별하고, 통화 종료 직후 상담 결과·다음 행동·재연락 일정을 기록하는 고객관리 서비스다.

Android 앱은 통화 감지와 즉시 입력을 담당하고, 웹은 고객·상담·일정·문자 흐름을 큰 화면에서 관리한다.

제품 설명:

> 통화가 끝나면 신규 고객, 기존 고객, 상담 상태와 다음 할 일이 정리되고 앱과 웹에서 같은 흐름으로 관리됩니다.

## 2. 페이지로 서비스 관계

콜태그와 콜링크는 별도 앱이지만 사용자 관점에서는 같은 페이지로 업무 서비스다.

- `페이지로 콜링크`: 통화 후 문자 발송과 템플릿
- `페이지로 콜태그`: 고객 분류, 상담 이력, 일정, 후속업무
- `페이지로 비즈니스`: 공통 계정, 고객, 통화, 구독, 웹 관리

필수 원칙:

- 같은 페이지로 계정 사용
- 같은 고객 ID와 통화 ID 사용
- 문자 발송 이력과 상담 이력을 한 고객 타임라인에 표시
- 앱별 고객 데이터 중복 생성 금지
- 도메인이 달라도 로그인과 데이터는 동일하게 유지

## 3. 해결할 문제

- 처음 전화한 문의자를 고객목록에 다시 입력해야 한다.
- 기존 고객의 이전 상담 내용을 기억하기 어렵다.
- 다시 연락하기로 한 약속을 놓친다.
- 견적서·소개서·주소 등 보내기로 한 자료를 누락한다.
- 문자 발송 이력과 상담 이력이 서로 분리돼 고객 흐름이 끊긴다.
- 고객과 현재 진행 중인 문의를 하나의 상태로 관리해 분류가 꼬인다.
- 일반 CRM은 입력 단계가 많아 통화 직후 사용하기 어렵다.
- 휴대폰에서 등록한 내용을 PC에서 정리하기 어렵다.

## 4. 핵심 사용자

초기 버전은 전화 상담 비중이 높은 1인 사업자와 개인 영업자를 대상으로 한다.

- 보험설계사
- 부동산 중개인
- 자동차 영업사원
- 광고·홈페이지 제작자
- 학원 상담자
- 인테리어·이사·방문서비스 사업자

## 5. Android MVP 핵심 기능

1. 수신·발신 통화 종료 감지
2. 전화번호 정규화 및 기존 고객 조회
3. 최근 통화 목록에서 신규 고객 추가
4. 미등록 번호의 신규 고객 등록 제안
5. 기존 고객의 마지막 상담 및 다음 할 일 표시
6. 통화 후 상담 결과 빠른 선택
7. 다음 행동과 재연락 날짜 지정
8. 고객별 상담 이력 저장
9. 신규·상담 중·기존·VIP·휴면·제외 고객 분류
10. 오늘 할 일과 기한이 지난 업무 표시
11. 월간 캘린더와 날짜별 일정
12. 일정 추가·변경·완료·다시 열기·삭제
13. 수신거부·개인통화·스팸 제외 처리

## 6. 웹 MVP 핵심 기능

1. 페이지로 공통 계정 로그인
2. 홈 할 일과 미정리 통화
3. 고객 목록·검색·상세
4. 최근 통화 목록에서 고객 추가
5. 고객 상태·메모 수정
6. 월간·주간 캘린더
7. 일정 추가·변경·완료
8. 통화·상담·상태 변경 타임라인
9. 콜링크 문자 발송 이력 조회
10. 연결 기기와 동기화 상태 확인

웹은 통화 감지를 수행하지 않는다. 통화 감지는 Android 앱이 담당한다.

## 7. 콜링크 연동 기능

- 고객 상세에서 문자 발송 이력 확인
- 고객 상태와 일정 종류에 맞는 문자 템플릿 추천
- 웹에서 문자 발송 요청 생성
- 연결된 콜링크 Android 앱에서 사용자 확인 후 발송
- 발송 성공·실패 결과를 고객 타임라인에 기록
- 일정 `자료 보내기`, `방문·미팅`과 문자 템플릿 연결

## 8. 초기 제외 범위

- 통화 녹음과 통화내용 자동 수집
- AI 통화 요약
- 직원·팀 권한
- 복잡한 영업 자동화
- 매출 회계와 세금계산서
- 카카오톡 자동 발송
- 전자계약
- 통신 3사 CTI 직접 연동
- 대규모 콜센터 기능

PC·웹 관리 화면은 제외 범위가 아니며 Android 핵심 흐름 검증 후 순차적으로 개발한다.

## 9. 제품 원칙

- 자동 저장보다 사용자 확인을 우선한다.
- 통화 후 처리는 10초 안에 끝나야 한다.
- 고객과 상담건은 별도 객체로 관리한다.
- 연락처에 저장됐다는 이유만으로 기존 고객으로 확정하지 않는다.
- 사용자가 처리하지 않은 업무는 홈에서 사라지지 않는다.
- 연락 거부 고객에게 다시 연락하지 않도록 경고한다.
- Android 앱은 오프라인에서도 저장 가능해야 한다.
- 연결 시 서버와 양방향 동기화한다.
- 문자와 상담 이력은 고객 중심으로 합쳐서 보여준다.

## 10. 초기 앱 메뉴

- `홈`: 통화 감지 상태, 오늘 연락, 기한 초과, 빠른 메뉴
- `고객`: 최근 통화 고객 추가, 상태별 고객, 고객 상세
- `캘린더`: 월간 일정과 날짜별 업무
- `전체`: 통화 감지, 제외번호, 데이터, 계정

## 12. 기술 기준

### Android

- Android 네이티브 앱
- Java 17
- minSdk 26
- targetSdk 35
- 로컬 SQLite 우선
- 네트워크 연결 시 서버 동기화

### 웹·서버

- 권장 도메인: `calltag.pagero.kr`
- 향후 통합 포털: `app.pagero.kr`
- 공통 API 후보: `api.pagero.kr`
- 공통 `user_id`, `workspace_id`, `customer_id`, `call_event_id` 사용
- 앱·웹 동기화 커서와 레코드 버전 관리
- 민감 데이터 전송 시 인증·암호화 필수

## 13. 성공 기준

- 통화 후 고객 정리가 10초 안에 끝난다.
- 최근 통화에서 고객을 중복 없이 추가한다.
- Android와 웹의 고객 상태와 일정이 일치한다.
- 콜링크 문자 이력이 올바른 고객에게 연결된다.
- 사용자가 고객의 통화·상담·문자·일정을 한 화면에서 이해한다.
