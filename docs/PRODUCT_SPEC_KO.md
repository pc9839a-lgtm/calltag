## 1. 제품 정의

콜태그는 전화가 오기 전 고객 맥락을 확인하고, 통화가 끝난 뒤 고객 상태·메모·일정·문자를 한 번에 처리하며 필요한 시점의 후속문자와 고객 그룹 대상 단체문자까지 연결하는 Android 고객관리 앱이다.

> 전화 한 통을 고객관리 행동으로 끝냅니다.

기본 전화 앱을 교체하지 않으며 통화녹음·AI 요약 앱과 공존한다.

## 4. 전화·고객·일정

### 통화 종료 정리

- 고객명
- 고객 상태
- 통화 결과
- 통화 메모
- 다음 할 일 종류와 시각
- 문자 템플릿과 치환된 문구
- 후속문자 시점
- 저장만 하기
- 저장하고 문자 보내기

### 고객 상세

```text
전화 / 일정 추가 / 문자
```

상태 변경은 고객명 옆 상태 배지에서 처리한다.

### 일정 연결 문자

- 없음
- 지금 안내문자
- 일정 하루 전
- 일정 시간
- 일정 완료 후

일정 변경·완료·삭제·다시 열기와 통화에 의한 자동 완료가 연결 문자의 예약·발송·취소 상태에 반영돼야 한다. 발송 직전에도 현재 일정 상태를 다시 검사한다.

## 5. 문자 자동화

문자 유형:

```text
수신 / 발신 / 부재중 / 후속
```

후속문자 시점:

```text
1일 후 / 3일 후 / 7일 후 / 직접 선택
일정 하루 전 / 일정 시간 / 일정 완료 후
```

### 저장형 템플릿

- 저장·수정·복제·삭제
- 즐겨찾기·최근 사용·검색
- 이미지 첨부
- 수신·발신·부재중·후속 기본 템플릿

지원 변수:

```text
{고객명}
{전화번호}
{통화일자}
{통화시간}
{내이름}
{상호명}
{다음일정}
```

미지원 변수나 미치환 변수가 남으면 발송을 차단한다.

### 이미지 문자

이미지 템플릿은 수동 문자와 사용자 확인형 예약 문자에 사용한다. 기본 메시지 앱 작성창을 열고 사용자가 최종 전송한다. 콜태그가 확인할 수 없는 실제 전송 완료를 허위로 표시하지 않는다. 자동발송 기본 템플릿과 단체문자는 현재 텍스트 전용이다.

---

## 6. 문자 안전 정책

### 발송 제외

- 자동문자 제외
- 전체 문자 제외
- 수신·발신·부재중·후속 유형별 제외

제외 건은 `FAILED`가 아니라 `SKIPPED`로 기록하고 사유를 남긴다.

### 중복발송 방지

- 같은 통화의 같은 목적 문자 한 번
- 자동발송과 수동발송 충돌 방지
- 같은 일정의 활성 후속문자 한 건
- 같은 캠페인의 같은 번호 한 번
- 최근 동일 템플릿·본문 제한
- 실패·제외·취소는 성공 중복으로 처리하지 않음

### 발송 직전 재검사

예약시각이 됐더라도 다음을 다시 확인한다.

- 문자 이용 권한
- SMS 권한
- 발송 제외
- 중복방지
- 미치환 변수
- 일정 생명주기
- 업무시간
- 활성 SIM
- 캠페인 일시정지 상태
- 캠페인 시작 당시 SIM과 현재 선택 SIM 일치 여부

캠페인 문자는 예약 리시버와 실제 `SmsManager` 호출 직전에 회선 상태를 두 번 검사한다.

## 7. 그룹과 단체문자

### 그룹

- 수동 그룹
- 고객 상태 스마트 그룹
- 7일·30일·90일 이상 미접촉 그룹
- 미완료 일정 보유 그룹
- 거래·미거래 고객 그룹

스마트 그룹은 캠페인 실행 직전에 최신 고객 데이터로 다시 계산한다.

### 캠페인

```text
그룹 선택
→ 텍스트 템플릿 선택
→ 고객별 변수 치환
→ 중복·제외·번호·변수 검사
→ 수신자별 순차 예약
→ 상태·사유 확인
→ 필요 시 일시정지·재개
→ 실패 대상 재시도
```

- 캠페인당 최대 500명
- 수신자별 4초 간격 예약
- 예정·진행·일시정지·완료·실패·건너뜀·취소 상태
- 남은 발송 취소
- 실패·건너뜀·취소 고객 재시도

### 캠페인 회선·제어 정책

- 캠페인 생성 시 선택한 활성 SIM ID 저장
- SIM 제거·비활성화·eSIM 해제·선택 회선 변경 시 자동 일시정지
- 일시정지 시 남은 `SCHEDULED/READY` 알람 해제
- 문자 작업과 수신자 정보는 삭제하지 않고 보존
- 재개 시 현재 활성 SIM으로 남은 작업만 4초 간격 재배치
- 통신 오류 3회 연속 발생 시 자동 일시정지
- 성공 발송 시 연속 실패 횟수 초기화
- 한 시점에 하나의 캠페인만 실제 발송
- 재부팅·앱 업데이트 후 `PAUSED` 캠페인 자동 재개 금지

## 8. 예약 복구 정책

앱 시작, 휴대전화 재부팅, 앱 업데이트 후 미완료 문자 작업을 다시 점검한다.

| 상태 | 복구 기준 |
|---|---|
| 미래 `SCHEDULED` | 원래 예약시각으로 알람 재등록 |
| 30분 이내 지연 `SCHEDULED` | 현재부터 5초 간격 순차 재등록 |
| 30분 초과 지연 `SCHEDULED` | 늦은 오발송 방지를 위해 `SKIPPED` |
| 멈춘 `READY` | `SCHEDULED`로 복구 후 위 기준 적용 |
| 불명확한 `SENDING` | 자동 재발송하지 않고 `FAILED` 전환 |
| `SENT / FAILED / SKIPPED / CANCELLED` | 재등록하지 않음 |
| 일시정지 캠페인의 `SCHEDULED/READY` | 알람을 재등록하지 않고 보존 |

같은 문자 작업 ID의 PendingIntent를 재사용해 중복 알람을 방지한다.

## 9. 데이터 정합성·고아 작업 복구

앱 시작·재부팅·앱 업데이트 후 예약 복구가 끝나면 데이터 정합성 검사를 순차 실행한다.

### 캠페인 수신자 연결 누락

- `message_id > 0`인데 문자 작업이 없으면 수신자를 `FAILED`
- `message_id = 0`인데 진행 상태면 수신자를 `FAILED`
- 문자 작업의 `campaign_id`와 수신자 캠페인 ID가 다르면 수신자를 `FAILED`
- 누락 문자 작업을 새로 만들거나 자동 발송하지 않음

### 고아 문자 작업

고아 작업 조건:

- `campaign_id`가 있는데 캠페인이 없음
- 캠페인은 있지만 해당 작업을 참조하는 수신자가 없음

| 작업 상태 | 처리 |
|---|---|
| `SCHEDULED / READY` | PendingIntent 취소 후 `CANCELLED` |
| `SENDING` | 자동 재발송 금지, `FAILED` |
| 최종 상태 | 상태 유지, 남은 PendingIntent 취소 |

### 최종 상태 알람 정리

최근 예약 범위의 `SENT`, `FAILED`, `SKIPPED`, `CANCELLED` 작업 ID로 동일 PendingIntent 취소를 멱등 실행한다.

### 늦은 SMS 콜백 보호

SMS 콜백은 현재 문자 작업이 실제 `SENDING`일 때만 반영한다. 이미 `SENT`, `FAILED`, `SKIPPED`, `CANCELLED`이거나 다른 상태인 작업에 늦게 도착한 콜백은 무시한다.

### 고객·그룹 참조

현재 고객 DB에 없는 `message_group_members.customer_id` 행만 제거한다. 캠페인 수신자 정보는 과거 발송 이력 스냅샷이므로 고객 삭제만으로 제거하지 않는다.

### 캠페인 삭제

- 삭제 전 연결 PendingIntent 취소
- 남은 `SCHEDULED/READY` 문자 작업 `CANCELLED`
- 이미지 예약 구성 정보 정리
- `SENDING` 작업이 있으면 결과 확인 전 삭제 차단
- 개별 문자 발송내역 유지

## 11. 데이터 저장과 보호

```text
calltag.db             고객·통화·상태·일정
calltag_messages.db    문자 작업·발송내역
calltag_groups.db      수동·스마트 그룹
```

기존 데이터를 초기화하거나 파괴하지 않는다. DB 변경 시 보존 마이그레이션과 복구 기준을 작성한다.

### 백업·복원

14차 필수 기능으로 구현한다.

- 고객·상태·메모
- 통화 활동
- 일정
- 문자 템플릿과 이미지
- 발송 제외
- 그룹
- 캠페인과 발송내역
- 자동화·회선 설정

백업은 같은 콜태그 앱에서 장애·기기 변경·데이터 손상을 복구하기 위한 기능이다.

### 외부 데이터 내보내기

현재 구현하지 않는다.

- CSV·XLSX
- 고객 목록 외부 반출
- 캠페인 결과표 외부 반출
- 범용 연락처 파일

데이터 내보내기는 추후 별도 유료 기능으로 기획한다. 백업 파일을 일반 내보내기 파일처럼 만들지 않는다.

## 13. 남은 개발 우선순위

1. 앱 데이터 백업·복원
2. 캠페인 수신자 검색·상태 필터·선택 재시도·선택 취소
3. 캠페인 작성 미리보기와 중복 시작 방지 UX
4. 결제·구독·운영 권한 검증
5. Android 8~15 전체 QA와 릴리스 AAB 검증

CSV·엑셀·외부 데이터 내보내기는 위 순서에 포함하지 않는다. 별도 유료 기능으로 보류한다.

세부 범위와 다음 작업자의 규칙은 [`DEVELOPMENT_STATUS_AND_ROADMAP_KO.md`](DEVELOPMENT_STATUS_AND_ROADMAP_KO.md)를 따른다.

## 14. 성공 기준

- 통화 종료 후 큰 정리창에서 고객관리와 문자를 함께 처리한다.
- 템플릿은 앱 재실행 후에도 유지된다.
- 모든 변수는 실제 값으로 치환된다.
- 제외 고객에게 잘못 발송되지 않는다.
- 같은 통화·일정·캠페인에서 중복 발송되지 않는다.
- 일정 변경·완료·삭제가 연결 문자에 반영된다.
- 단체문자는 중복·제외·오류 번호를 개별 처리한다.
- SIM 변경 시 잘못된 회선으로 남은 캠페인을 계속 발송하지 않는다.
- 캠페인을 안전하게 일시정지·재개할 수 있다.
- 고아 예약 작업이 실제 발송되지 않는다.
- 늦은 SMS 콜백이 취소·실패 상태를 덮어쓰지 않는다.
- 캠페인 삭제 후 남은 알람이 실행되지 않는다.
- 전화·메모·상태·일정·문자가 같은 고객 흐름으로 연결된다.
- 진단 정보는 개인정보를 노출하지 않고 기술 상태를 확인할 수 있다.
- 실제 운영 결제와 권한이 요금제 기준대로 적용된다.
