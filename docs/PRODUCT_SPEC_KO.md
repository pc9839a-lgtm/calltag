---

## 1. 제품 정의

콜태그는 전화가 오기 전 고객 맥락을 확인하고, 통화가 끝난 뒤 고객 상태·메모·일정·문자를 한 번에 처리하며 필요한 시점의 후속문자와 고객 그룹 대상 단체문자까지 연결하는 Android 고객관리 앱이다.

> 전화 한 통을 고객관리 행동으로 끝냅니다.

기본 전화 앱을 교체하지 않으며 통화녹음·AI 요약 앱과 공존한다.

---

| 상품 | 월 가격 | 기능 |
|---|---:|---|
| 전화관리 | 1,900원 | 고객·통화·상태·메모·일정·통계 |
| 문자자동화 | 990원 | 템플릿·자동·수동·예약·그룹·단체문자 |

현재 개발 권한과 실제 결제·영수증·구독 만료·복원·환불 처리는 구분한다.

## 3. 핵심 흐름

```text
전화 수신 전 고객 맥락 확인
→ 통화
→ 통화 종료 큰 정리창
→ 고객 상태·메모·다음 할 일 저장
→ 즉시 문자 또는 후속문자
→ 고객 타임라인 반영
```

사용자에게 내부 기술 용어와 긴 설정 절차를 핵심 화면으로 노출하지 않는다.

## 4. 전화·고객·일정

### 통화 종료 정리

- 고객명
- 고객 상태
- 통화 결과
- 통화 메모
- 다음 할 일 종류와 시각
- 문자 템플릿과 치환된 문구
- 후속문자 시점
- 저장만 하기
- 저장하고 문자 보내기

### 고객 상세

```text
전화 / 일정 추가 / 문자
```

상태 변경은 고객명 옆 상태 배지에서 처리한다.

### 일정 연결 문자

- 없음
- 지금 안내문자
- 일정 하루 전
- 일정 시간
- 일정 완료 후

일정 변경·완료·삭제·다시 열기와 통화에 의한 자동 완료가 연결 문자의 예약·발송·취소 상태에 반영돼야 한다. 발송 직전에도 현재 일정 상태를 다시 검사한다.

## 5. 문자 자동화

문자 유형:

```text
수신 / 발신 / 부재중 / 후속
```

후속문자 시점:

```text
1일 후 / 3일 후 / 7일 후 / 직접 선택
일정 하루 전 / 일정 시간 / 일정 완료 후
```

### 저장형 템플릿

- 저장·수정·복제·삭제
- 즐겨찾기·최근 사용·검색
- 이미지 첨부
- 수신·발신·부재중·후속 기본 템플릿

지원 변수:

```text
{고객명}
{전화번호}
{통화일자}
{통화시간}
{내이름}
{상호명}
{다음일정}
```

미지원 변수나 미치환 변수가 남으면 발송을 차단한다.

### 이미지 문자

이미지 템플릿은 수동 문자와 사용자 확인형 예약 문자에 사용한다. 기본 메시지 앱 작성창을 열고 사용자가 최종 전송한다. 콜태그가 확인할 수 없는 실제 전송 완료를 허위로 표시하지 않는다. 자동발송 기본 템플릿과 단체문자는 현재 텍스트 전용이다.

---

## 6. 문자 안전 정책

### 발송 제외

- 자동문자 제외
- 전체 문자 제외
- 수신·발신·부재중·후속 유형별 제외

제외 건은 `FAILED`가 아니라 `SKIPPED`로 기록하고 사유를 남긴다.

### 중복발송 방지

- 같은 통화의 같은 목적 문자 한 번
- 자동발송과 수동발송 충돌 방지
- 같은 일정의 활성 후속문자 한 건
- 같은 캠페인의 같은 번호 한 번
- 최근 동일 템플릿·본문 제한
- 실패·제외·취소는 성공 중복으로 처리하지 않음

### 발송 직전 재검사

예약시각이 됐더라도 다음을 다시 확인한다.

- 문자 이용 권한
- SMS 권한
- 발송 제외
- 중복방지
- 미치환 변수
- 일정 생명주기
- 업무시간
- 활성 SIM
- 캠페인 일시정지 상태
- 캠페인 시작 당시 SIM과 현재 선택 SIM 일치 여부

캠페인 문자는 예약 리시버와 실제 `SmsManager` 호출 직전에 회선 상태를 두 번 검사한다.

## 7. 그룹과 단체문자

### 그룹

- 수동 그룹
- 고객 상태 스마트 그룹
- 7일·30일·90일 이상 미접촉 그룹
- 미완료 일정 보유 그룹
- 거래·미거래 고객 그룹

스마트 그룹은 캠페인 실행 직전에 최신 고객 데이터로 다시 계산한다.

### 캠페인 기본 흐름

```text
그룹 선택
→ 텍스트 템플릿 선택
→ 고객별 변수 치환
→ 중복·제외·번호·변수 검사
→ 수신자별 순차 예약
→ 상태·사유 확인
→ 필요 시 일시정지·재개
→ 실패 대상 재시도
```

- 캠페인당 최대 500명
- 수신자별 4초 간격 예약
- 예정·진행·일시정지·완료·실패·건너뜀·취소 상태
- 남은 발송 취소
- 실패·건너뜀·취소 고객 재시도

### 캠페인 회선 정책

캠페인 생성 시 현재 선택한 활성 SIM ID를 캠페인에 저장한다.

다음 상황에서는 남은 발송을 자동 일시정지한다.

- 지정 SIM 제거
- 지정 SIM 비활성화
- eSIM 프로필 비활성화
- 문자 설정에서 다른 SIM 선택
- 캠페인 회선 정보 없음

수신자별 작업을 실패로 소진하지 않고 캠페인을 `PAUSED`로 보존한다. 사용자는 회선을 확인한 뒤 현재 선택 SIM으로 남은 작업을 재개한다.

### 일시정지·재개

일시정지:

- 남은 `SCHEDULED/READY` 예약 알람 해제
- 문자 작업과 수신자 정보는 삭제하지 않음
- 문자 작업은 `SCHEDULED`로 보존
- 중단 사유 표시
- 이미 `SENDING`인 한 건은 강제로 되돌리지 않음

재개:

- 활성 SIM 필수
- 현재 선택 SIM을 캠페인 회선으로 저장
- 남은 `SCHEDULED/READY`만 현재 시각부터 4초 간격으로 재배치
- 연속 통신 실패 횟수 초기화
- 완료·실패·건너뜀·취소 작업은 자동 재개하지 않음

### 연속 실패 자동 중단

다음 오류가 캠페인에서 3회 연속 발생하면 남은 발송을 자동 일시정지한다.

- 통신 서비스 없음
- 무선 통신 기능 꺼짐
- 통신사 일반 발송 실패

성공 발송이 발생하면 연속 실패 횟수를 초기화한다. 번호 오류·변수 오류·발송 제외는 통신 연속 실패에 포함하지 않는다.

### 동시 캠페인 방지

- 미완료 또는 일시정지 캠페인이 있으면 새 캠페인 시작 차단
- 캠페인 재개 전 다른 미완료 캠페인 확인
- 동시에 실행되는 구버전 캠페인이 감지되면 후순위 캠페인 일시정지
- 한 시점에 하나의 캠페인만 실제 발송 진행

## 9. 예약 복구 정책

앱 시작, 휴대전화 재부팅, 앱 업데이트 후 미완료 문자 작업을 다시 점검한다.

| 상태 | 복구 기준 |
|---|---|
| 미래 `SCHEDULED` | 원래 예약시각으로 알람 재등록 |
| 30분 이내 지연 `SCHEDULED` | 현재부터 5초 간격 순차 재등록 |
| 30분 초과 지연 `SCHEDULED` | 늦은 오발송 방지를 위해 `SKIPPED` |
| 멈춘 `READY` | `SCHEDULED`로 복구 후 위 기준 적용 |
| 불명확한 `SENDING` | 자동 재발송하지 않고 `FAILED` 전환 |
| `SENT / FAILED / SKIPPED / CANCELLED` | 재등록하지 않음 |
| 일시정지 캠페인의 `SCHEDULED/READY` | 알람을 재등록하지 않고 보존 |

복구 실행은 직렬화한다. 같은 문자 작업 ID의 PendingIntent를 재사용해 중복 알람을 방지한다. 캠페인 상태가 변경되면 수신자와 캠페인 집계를 동기화한다.

## 14. 성공 기준

- 통화 종료 후 큰 정리창에서 고객관리와 문자를 함께 처리한다.
- 템플릿은 앱 재실행 후에도 유지된다.
- 모든 변수는 실제 값으로 치환된다.
- 제외 고객에게 잘못 발송되지 않는다.
- 같은 통화·일정·캠페인에서 중복 발송되지 않는다.
- 일정 변경·완료·삭제가 연결 문자에 반영된다.
- 단체문자는 중복·제외·오류 번호를 개별 처리한다.
- 앱 종료·재부팅 후 예약 상태가 안전하게 복구된다.
- 일시정지 캠페인은 재부팅 후 자동 재개되지 않는다.
- SIM이 변경되면 잘못된 회선으로 계속 발송하지 않는다.
- 반복 통신 오류가 발생하면 남은 대량 발송을 자동 중단한다.
- 실제 운영 결제와 권한이 요금제 기준대로 적용된다.
