## 1. 이번 작업의 최종 결정

이번 작업은 단순히 기존 정산 화면을 꾸미는 작업이 아니다. 아래 네 가지를 하나의 계정·결제·파트너 체계로 다시 설계해야 한다.

1. 정산은 앱 내부 입력 화면이 아니라 **별도 파트너 정산 웹사이트**에서 처리한다.
2. 앱 더보기의 **내 추천인 코드가 모든 설정 메뉴보다 위에 먼저 보여야 한다.**
3. 마스터 계정을 제외한 일반 회원은 가입 시 **3일 무료 이용**을 받고, 홈 최상단에서 남은 이용시간을 항상 확인한다.
4. 월 결제 회원도 같은 위치에서 다음 결제일까지 남은 기간과 구독 상태를 확인한다.
5. 추천인 코드를 아직 등록하지 않은 무료체험 회원에게는 **코드 등록 시 5일 추가**를 자연스럽게 유도한다.
6. 문자 첨부는 아무 파일이나 받지 않고, 실제 휴대전화 MMS에서 전송 가능한 형식만 허용한다.

정산 웹사이트 완성 후 사용자가 최종 URL을 제공하면 앱의 `정산` 메뉴를 해당 URL로 연결한다. URL이 확정되기 전까지 임의의 운영 주소를 코드에 하드코딩하지 않는다.

## 2. 현재 코드에서 확인된 상태

### 2.1 이용권 정보

`FeatureEntitlementStore`에는 이미 다음 값이 존재한다.

- `status`
- `active`
- `endsAt`
- `nextBillingAt`
- `remainingDays`
- `channel`
- 서버 시각 기준 만료 계산

따라서 남은 기간 UI는 새 결제 로직을 로컬에서 만들지 말고 이 서버 응답을 사용해야 한다. 단, 현재는 마스터 계정 여부를 명확히 저장하는 필드가 없으므로 서버 계약을 확장해야 한다.

### 2.2 추천인 메뉴 위치

현재 `MoreSettingsHubView`는 검색창이 가장 위에 있고, 통화·페이지로 섹션 뒤에 친구 초대·파트너 섹션이 나온다. 사용자가 요구한 구조와 반대다. 내 추천인 코드는 검색 가능한 설정 목록 안의 한 줄이 아니라 더보기 화면 상단의 독립 카드가 되어야 한다.

### 2.3 문자 첨부

현재 앱은 이미 갤러리 이미지를 앱 내부로 가져와 JPEG로 압축하고, 시스템 메시지 앱 작성창을 여는 방식이 있다. 하지만 앱이 MMS를 직접 전송하는 것이 아니라 사용자가 기본 메시지 앱에서 최종 전송을 눌러야 한다. 예약 이미지 문자도 예약시간에 알림을 띄운 뒤 메시지 앱을 열도록 되어 있다.

즉, 현 상태를 “자동 이미지 문자 발송 완료”라고 표현하면 안 된다.

# PART A. 별도 파트너 정산 웹사이트

## 3. 웹사이트 목적

별도 웹사이트는 추천 파트너가 자신의 추천 실적, 예상 수익, 확정 수익, 지급 내역, 계좌·세금 정보를 관리하는 전용 파트너 센터다.

앱은 정산정보의 원본 저장소가 아니다. 앱에서는 요약만 보여주고, 계좌번호·사업자정보·정산 신청은 웹사이트에서만 처리한다.

권장 명칭:

- 서비스명: `CallTag Partner`
- 메뉴명: `파트너 정산`
- 임시 URL 변수: `SETTLEMENT_WEB_URL`
- 최종 URL: 사용자가 별도로 제공

도메인 예시는 설명용일 뿐 확정하지 않는다.

- `partner.pagero.kr`
- `settlement.pagero.kr`

## 4. 웹사이트 정보 구조

### 4.1 대시보드

최상단에 다음 정보를 보여준다.

- 내 추천인 코드
- 코드 복사
- 초대 링크 복사
- 추천 회원 수
- 유료 전환 회원 수
- 이번 달 예상 수익
- 정산 가능 금액
- 누적 지급 금액
- 다음 정산 예정일

추천인 코드는 대시보드에서도 가장 먼저 노출한다.

### 4.2 추천 회원

개인정보를 과도하게 노출하지 않는다.

표시 항목:

- 마스킹된 회원명
- 마스킹된 이메일
- 가입일
- 무료체험 상태
- 첫 유료 결제일
- 현재 구독 상태
- 수익 발생 여부
- 이번 달 인정 금액

전화번호·전체 이메일·결제수단 정보는 노출하지 않는다.

### 4.3 수익 내역

수익은 결제 한 건마다 원장 형식으로 남긴다.

필수 항목:

- 발생일
- 추천 회원 식별값
- 상품명
- 결제 금액
- 부가세 제외 금액
- 할인 제외 금액
- 환불 차감 금액
- 인정 매출
- 파트너 수익률
- 파트너 수익
- 상태

수익률 정책은 기존 결정대로 **직접 추천 회원의 확정 구독 매출 20%를 평생 지급**하는 구조를 기본으로 한다.

계산 기준:

`파트너 수익 = 환불·할인·부가세를 제외한 확정 결제금액 × 20%`

환불, 결제 취소, 차지백, 무료 이용기간, 쿠폰 전액 결제는 수익으로 확정하지 않는다.

### 4.4 정산 내역

상태값:

- `ESTIMATED`: 예상
- `PENDING_CONFIRMATION`: 확정 대기
- `CONFIRMED`: 정산 가능
- `REQUESTED`: 지급 요청
- `PROCESSING`: 지급 처리 중
- `PAID`: 지급 완료
- `HELD`: 보류
- `REVERSED`: 환불·취소로 차감

화면에서 상태를 한국어로 명확히 설명한다.

### 4.5 계좌·세금정보

개인과 사업자를 나눈다.

공통 필드:

- 정산 유형: 개인 / 개인사업자 / 법인
- 예금주
- 은행
- 계좌번호
- 정산 이메일
- 휴대전화번호

개인:

- 실명
- 생년월일 또는 본인확인 완료 상태
- 원천징수 안내 동의

개인사업자·법인:

- 상호 또는 법인명
- 대표자명
- 사업자등록번호
- 사업자등록증 파일
- 업태
- 종목
- 사업장 주소
- 세금계산서 이메일

민감정보를 브라우저 LocalStorage에 원문 저장하지 않는다.

## 5. 아직 확정하지 말아야 할 정책

다음 항목은 사용자가 별도로 결정하기 전까지 AI가 임의로 확정하지 않는다.

- 최소 정산 가능 금액
- 월 정산 마감일
- 실제 지급일
- 개인 원천징수 방식
- 세금계산서 발행 주체
- 휴면 파트너 처리
- 추천 관계 해지 조건

웹사이트는 이 값을 서버 환경설정으로 바꿀 수 있게 만들고, 화면 문구도 서버 정책값을 사용한다.

## 6. 인증 방식

별도 회원가입을 다시 만들지 않는다. 페이지로·콜태그 통합 계정을 사용한다.

권장 흐름:

1. 앱에서 `파트너 정산`을 누른다.
2. 앱이 서버에 1회용 SSO 티켓을 요청한다.
3. 서버는 1~3분 이내 만료되는 단일 사용 티켓을 반환한다.
4. 앱은 Custom Tab으로 정산 웹사이트를 연다.
5. 웹사이트가 티켓을 서버와 교환해 웹 세션을 만든다.
6. 티켓은 즉시 폐기한다.

금지:

- 앱 세션 토큰을 URL에 그대로 붙이기
- 이메일만 URL 파라미터로 넘겨 로그인 처리
- 계좌번호를 앱에서 웹으로 쿼리스트링 전달
- WebView 안에 장기 로그인 토큰 저장

## 7. 정산 웹 API 초안

외부 AI는 아래 계약을 기준으로 서버와 웹을 분리한다.

- `POST /api/partner/sso-ticket`
- `POST /api/partner/sso-exchange`
- `GET /api/partner/me`
- `GET /api/partner/dashboard`
- `GET /api/partner/referrals`
- `GET /api/partner/earnings`
- `GET /api/partner/settlements`
- `GET /api/partner/payout-profile`
- `PUT /api/partner/payout-profile`
- `POST /api/partner/payout-profile/verify`
- `POST /api/partner/settlements/request`
- `GET /api/partner/policies`

모든 금액 계산은 서버가 담당한다. 앱이나 프론트엔드에서 예상 수익을 재계산해 확정값처럼 저장하지 않는다.

## 8. 웹 보안 요구

- 계좌번호 서버 암호화 저장
- 응답에서는 마지막 4자리만 기본 노출
- 전체 계좌번호 재조회 시 재인증
- 사업자등록증은 비공개 객체 저장소 사용
- 다운로드 URL은 짧은 만료시간의 서명 URL 사용
- 관리자 변경 이력과 지급 이력 감사 로그 저장
- 정산정보 변경 시 이메일 또는 앱 알림
- 계정 변경 직후 일정 시간 지급 요청 잠금
- CSRF, XSS, 세션 고정 공격 방어
- 관리자와 파트너 권한 완전 분리

# PART B. 앱 추천인 코드 최상단 배치

## 9. 더보기 화면 최종 순서

더보기 화면은 다음 순서를 지킨다.

1. 화면 제목 `더보기`
2. **내 추천인 코드 카드**
3. 추천인 등록 유도 영역 또는 등록 완료 상태
4. 설정 검색
5. 페이지로
6. 통화·외부 연동
7. 앱·계정
8. 파트너 정산 링크

현재처럼 `친구 초대·파트너` 섹션 안에 추천인 코드를 묻어두지 않는다.

## 10. 내 추천인 코드 카드

필수 표시:

- `내 추천인 코드`
- 실제 코드
- `복사`
- `공유`
- 추천 회원 수
- 이번 달 예상 수익
- `파트너 정산 보기`

코드를 아직 서버에서 받지 못한 경우:

- `추천인 코드 확인 중`
- 새로고침 버튼
- 임의의 로컬 코드를 만들지 않음

카드 높이는 과도하게 키우지 않는다. 핵심 코드와 복사·공유가 첫 화면 안에 보여야 한다.

## 11. 추천인 코드 등록 유도

등록 자격은 서버가 반환한다.

권장 필드:

```json
{
  "referral": {
    "eligible": true,
    "applied": false,
    "bonusDays": 5,
    "eligibilityEndsAt": "ISO-8601",
    "ineligibleReason": ""
  }
}
```

표시 조건:

- 자격 있음 + 미등록: `추천인 코드 등록하고 무료 이용 5일 더 받기`
- 등록 완료: `추천 혜택 +5일 적용 완료`
- 첫 유료 결제 후 등록 불가: 입력 UI를 숨기고 사유 표시
- 본인 코드 입력: 서버에서 차단

추천 혜택은 로컬에서 5일을 더하지 않는다. 서버가 `trial.endsAt`을 갱신하고 앱은 새 이용권 응답을 다시 받아야 한다.

# PART C. 일반회원 3일 무료체험과 홈 남은시간

## 12. 계정 구분

이메일 주소를 코드에 하드코딩해 마스터를 구분하지 않는다.

서버 프로필 또는 이용권 응답에 다음 중 하나를 추가한다.

```json
{
  "accountRole": "master",
  "billingExempt": true
}
```

권장 역할:

- `master`: 운영자, 무료체험·결제 제한 없음
- `member`: 일반 회원
- `partner_admin`: 정산 관리자이며 앱 마스터와는 별도 권한

마스터 계정:

- 무료체험 배너 숨김
- 결제 만료로 핵심 기능 차단 금지
- 추천인 등록 유도 숨김
- 파트너 수익 테스트 데이터와 운영 사용자 데이터 분리

## 13. 무료체험 규칙

일반 회원은 서버 계정 생성 시점부터 3일 무료 이용을 받는다.

중요:

- 앱 설치일이 아니라 서버 계정 생성일 기준
- 앱 삭제·재설치로 재발급 금지
- 다른 기기 로그인 시 같은 종료시각 사용
- 무료체험 전체 기능 범위는 서버 `scope`로 결정
- 추천인 등록 성공 시 5일 추가
- 기본 3일 + 추천 혜택 5일 = 최대 8일
- 추가 혜택은 계정당 1회

서버 응답 예시:

```json
{
  "entitlement": {
    "active": true,
    "status": "trial",
    "productCode": "all_monthly",
    "serverNow": "ISO-8601",
    "trial": {
      "active": true,
      "baseDays": 3,
      "bonusDays": 0,
      "startedAt": "ISO-8601",
      "endsAt": "ISO-8601",
      "remainingSeconds": 259200
    },
    "nextBillingAt": ""
  }
}
```

`remainingDays`만으로는 “남은시간” 표현이 부족하므로 서버는 `remainingSeconds` 또는 정확한 `endsAt`을 반드시 제공한다.

## 14. 홈 상단 이용권 스트립

위치:

- 홈 화면 스크롤 영역의 가장 위
- 기존 `통화 감지` 카드보다 위
- 상태바 바로 아래 앱 제목과 콘텐츠 사이

형태:

- 높이 약 38~44dp
- 한 줄 중심
- 큰 광고 배너 금지
- 닫기 버튼 금지
- 탭하면 이용권·결제 화면으로 이동

표시 문구:

### 무료체험 중

- 24시간 이상: `무료 이용 2일 14시간 남음`
- 1시간 이상 24시간 미만: `무료 이용 6시간 20분 남음`
- 1시간 미만: `무료 이용 42분 남음`

오른쪽 CTA:

- 추천인 미등록·자격 있음: `+5일 받기`
- 추천인 등록 완료: `혜택 적용됨`
- 등록 자격 없음: `이용권 보기`

초 단위 카운트다운은 배터리와 시각적 피로 때문에 사용하지 않는다. 화면이 보이는 동안 1분 단위로 갱신한다.

# PART D. 실제 전송 가능한 문자 첨부

## 17. 제품 용어

현재 1차 범위에서는 메뉴명을 `파일 첨부`보다 **사진 첨부**로 표시하는 것이 정확하다.

일반 PDF, 문서, ZIP, APK를 이동통신사 MMS 첨부처럼 취급하지 않는다. 기기·통신사·메시지 앱에 따라 전송되지 않을 수 있기 때문이다.

PDF·문서가 필요하면 별도의 `파일 링크 전송` 기능으로 만든다. 파일을 서버에 업로드하고 만료되는 다운로드 링크를 일반 문자에 넣는 방식이며 MMS 첨부와 혼합하지 않는다.

## 18. 1차 허용 형식

선택 입력 허용:

- `image/jpeg`
- `image/png`
- `image/webp`
- 기기에서 정상 디코딩 가능한 `image/heic`, `image/heif`

앱 내부 최종 저장:

- `image/jpeg`
- 첨부 1장
- 애니메이션 GIF 제외
- 투명 배경은 흰색으로 합성
- EXIF 위치정보 제거
- 파일명은 사용자 원본명을 그대로 저장하지 않음

차단:

- PDF
- HWP
- DOC·DOCX
- XLS·XLSX
- PPT·PPTX
- ZIP·RAR·7Z
- APK
- 실행파일
- 오디오·동영상
- MIME이 이미지라고 속인 비이미지 파일

파일 확장자만 보지 말고 MIME, 이미지 디코딩 성공 여부, 파일 시그니처를 함께 검사한다.

## 19. 통신사별 크기 제한

고정 900KB만 사용하지 않는다.

선택한 SIM의 `SmsManager` carrier config에서 다음 값을 확인한다.

- MMS 사용 가능 여부
- 최대 메시지 크기
- 최대 이미지 너비
- 최대 이미지 높이
- 최대 텍스트 크기

최종 이미지 목표 크기:

`min(통신사 최대 MMS 크기의 75%, 앱 안전 상한)`

carrier config를 읽지 못하면 보수적인 기본값을 사용하고, 실제 SKT·KT·LG U+ 기기 테스트로 확정한다.

이미지 크기 제한을 넘으면 자동 축소·재압축한다. 그래도 기준을 넘으면 선택 즉시 거절하고 이유를 보여준다.

## 20. 전송 모드 구분

### 모드 A. 시스템 메시지 앱 작성창

현재 구현과 같은 안정 우선 방식이다.

- 받는 번호 입력
- 본문 입력
- 이미지 첨부
- 기본 메시지 앱 열기
- 사용자가 최종 전송

장점:

- 삼성 메시지·Google 메시지의 통신사 처리 사용
- 제조사·통신사 호환성이 상대적으로 높음

제한:

- 자동문자라고 부를 수 없음
- 예약시간에 앱이 완전히 자동 전송할 수 없음
- 최종 전송 결과를 콜태그가 확실히 알 수 없음

UI 문구는 `메시지 앱에서 보내기`로 표시해야 한다.

### 모드 B. 앱 직접 MMS 전송

직접 자동 전송이 필요하면 별도 구현한다.

필요 작업:

1. 텍스트와 JPEG를 포함한 MMS PDU 생성
2. PDU를 앱 전용 Content URI에 기록
3. 선택한 SIM용 `SmsManager` 사용
4. `sendMultimediaMessage` 호출
5. 전송 PendingIntent 결과 저장
6. 통신사 MMS 오류코드 사용자 문구 변환
7. 모바일 데이터 꺼짐, MMS 차단, 잘못된 APN, 비활성 SIM 처리
8. 발송 성공·실패·재시도 정책 구현

주의:

`sendMultimediaMessage`의 `contentUri`는 이미지 파일 URI가 아니라 완성된 MMS PDU를 읽는 URI다. 이미지만 넘기는 방식으로 구현하면 안 된다.

## 21. 자동문자 첨부 정책

직접 MMS 전송이 실기기에서 검증되기 전에는 아래 원칙을 지킨다.

- 수동 문자: 사진 첨부 허용, 시스템 메시지 앱에서 최종 전송
- 예약 후속문자: 전송시간에 알림 후 메시지 앱 열기
- 통화 후 완전 자동문자: 텍스트만 자동 전송
- 이미지 포함 자동 템플릿: 직접 MMS 기능 검증 전 자동 발송 금지

직접 MMS가 SKT·KT·LG U+에서 검증된 후에만 이미지 자동문자를 활성화한다.

## 22. 파일 링크 전송 후속 기능

MMS가 아닌 문서 전송 요구가 생기면 다음 기능을 별도 개발한다.

- 허용 문서 형식 선택
- 악성파일 검사
- 서버 암호화 저장
- 1회용 또는 만료 링크 발급
- 문자 본문에 링크 삽입
- 다운로드 횟수·만료 관리
- 고객별 접근 로그
- 사용자가 파일 삭제 가능

문서 링크는 문자 첨부로 오해하지 않도록 `파일 링크`라고 표기한다.

# PART F. 검수 기준

## 24. 앱 검수

- 더보기 진입 즉시 추천인 코드가 첫 화면에 보인다.
- 설정 검색보다 추천인 카드가 위에 있다.
- 일반 신규 계정은 정확히 3일로 시작한다.
- 추천인 등록 후 서버 종료시각이 5일 늘어난다.
- 재설치해도 무료체험이 재발급되지 않는다.
- 마스터 계정에는 무료체험·결제 스트립이 나오지 않는다.
- 홈의 남은시간은 1분 단위로 감소한다.
- 월 결제 후 동일 위치에서 다음 결제일까지 남은 기간이 보인다.
- 해지 예약·결제 실패·만료 상태 문구가 서로 구분된다.
- `정산`을 누르면 최종 정산 웹 URL이 외부 Custom Tab으로 열린다.

## 25. 정산 웹 검수

- 콜태그 계정으로 별도 가입 없이 로그인된다.
- SSO 티켓은 한 번 사용 후 재사용되지 않는다.
- 추천 회원의 개인정보가 마스킹된다.
- 수익 계산을 프론트에서 조작할 수 없다.
- 환불 발생 시 확정 전 수익이 자동 차감된다.
- 계좌번호는 기본 화면에서 마지막 4자리만 보인다.
- 정산정보 수정 이력이 감사 로그에 남는다.
- 모바일 화면에서 모든 기능을 사용할 수 있다.

## 26. MMS 검수

- PDF·ZIP·APK는 선택 단계에서 거절된다.
- PNG·WebP·HEIC는 최종 JPEG로 안전 변환된다.
- EXIF 위치정보가 제거된다.
- 선택 SIM 기준 최대 크기를 초과하지 않는다.
- 삼성 메시지와 Google 메시지 작성창에서 이미지·번호·본문이 모두 들어간다.
- 직접 MMS 기능은 SKT·KT·LG U+ 각각 성공·실패 결과가 기록된다.
- 모바일 데이터 OFF, MMS 차단, 비활성 SIM, 듀얼 SIM 미선택 상태에서 명확한 오류가 나온다.
- 직접 MMS 검증 전에는 이미지 자동발송으로 표시하지 않는다.
