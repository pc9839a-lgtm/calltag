# 콜태그 통합 제품 기획서

기준일: 2026-07-31  
제품명: **콜태그(CallTag)**  
Android 패키지: `kr.pagero.calltag`  
저장소: `pc9839a-lgtm/calltag`  
문자 기능 원본 저장소: `pc9839a-lgtm/call-auto-sms-android`

---

## 1. 최종 제품 정의

콜태그는 단순 리마인더나 전화번호부가 아니다.

> **전화가 오기 전 고객 맥락을 보여주고, 통화가 끝난 뒤 고객 상태·메모·일정·문자 발송까지 자동으로 이어주는 전화 기반 고객관리 앱**

콜링크라는 별도 제품명과 별도 앱은 사용하지 않는다. 기존 콜링크의 검증된 통화 후 문자 기능을 콜태그 안으로 이전하여 하나의 앱, 하나의 고객, 하나의 통화 이력으로 통합한다.

핵심 흐름은 다음과 같다.

```text
전화 수신 전
→ 연락처 이름에서 고객명 + 핵심 메모 확인
→ 통화
→ 통화 종료 감지
→ 고객 상태·메모·다음 할 일 저장
→ 즉시 문자 또는 예약 문자 발송
→ 후속 연락 일정과 고객 타임라인 자동 연결
```

콜태그의 경쟁 기준은 “리마인더를 더 잘 만드는가”가 아니다. **전화 한 통을 실제 고객관리 행동으로 얼마나 짧고 정확하게 전환하는가**다.

## 2. 기획 판단 프레임

### 2.1 문제 재정의

기존 문제를 “통화 후 메모를 남기기 어렵다”로 정의하면 삼성 리마인더·캘린더·메모 앱과 직접 경쟁하게 된다. 이 정의는 제품 가치를 약하게 만든다.

문제를 다음과 같이 다시 정의한다.

> 사용자는 전화를 잊는 것이 아니라, 전화 이후 해야 할 여러 업무가 서로 분리돼 있어 고객을 놓친다.

전화 한 통 이후 실제로 발생하는 업무는 다음처럼 연결돼 있다.

- 누구와 통화했는지 확인
- 이전 상담 내용 확인
- 신규·진행 중·완료 상태 판단
- 상담 메모 저장
- 견적·주소·자료 문자 발송
- 3일 뒤 후속 문자 예약
- 다시 전화할 일정 등록
- 부재중 전화에 자동 안내
- 발송 여부와 후속 처리 확인

일반 리마인더는 이 중 “나중에 알려주기”만 담당한다. 콜태그는 **전화 이벤트를 기준으로 고객·메모·문자·일정·상태를 하나의 자동화 흐름으로 묶는다.**

### 2.2 다차원 분석

#### 시간 차원

- 통화 전: 연락처 표시명에 핵심 메모 표시
- 통화 직후: 상태·메모·문자·일정 빠른 처리
- 며칠 후: 사용자가 설정한 예약 문자와 재연락 알림
- 장기: 고객별 전체 통화·문자·일정 타임라인

#### 기능 차원

- 전화관리: 고객 분류, 통화 이력, 메모, 일정, 관리공백
- 문자자동화: 템플릿, 즉시·자동·예약 발송, 발송내역
- 통합: 통화 결과에 따라 상태·일정·문자를 동시에 실행

#### 사용자 차원

- 1인 사업자: 고객을 놓치지 않는 최소 CRM
- 영업자: 상태·후속 연락·견적 발송 자동화
- 예약 업종: 통화 후 안내 및 예약 전 재안내
- 현장 서비스: 주소·준비물·방문 일정 자동 발송

#### 경쟁 차원

- 삼성 리마인더: 사용자가 직접 만드는 개인 할 일
- 문자 앱: 메시지 작성과 예약 발송
- 일반 CRM: 고객 DB와 영업 단계 관리
- 콜태그: **통화 이벤트가 고객관리와 문자자동화를 직접 실행**

## 3. 브랜드와 앱 구조

### 3.1 제품명

- 최종 앱명: **콜태그**
- 콜링크 명칭: 통합 이후 제품 화면과 결제 상품에서 사용하지 않음
- 기존 콜링크 코드는 문자자동화 모듈의 기술 자산으로만 이전
- 아직 스토어 등록 전이므로 신규 앱 패키지 `kr.pagero.calltag`를 최종 기준으로 유지

### 3.2 하나의 앱, 세 가지 이용 상태

콜태그는 APK를 여러 개 만들지 않는다. 하나의 앱 안에서 구독 권한만 다르게 적용한다.

| 상품 | 월 구독료 | 핵심 목적 |
|---|---:|---|
| 전화관리 | 1,900원 | 통화 기반 고객·메모·상태·일정 관리 |
| 문자자동화 | 990원 | 자동·수동·예약 문자와 템플릿 관리 |
| 통합 이용 | 2,500원 | 전화관리와 문자자동화를 하나의 흐름으로 사용 |

개별 상품 합계는 2,890원이며 통합 상품은 2,500원이다. 통합 상품은 단순 할인이 아니라 **통화 결과 저장과 문자 발송을 한 번에 처리하는 완성형 이용 방식**으로 설계한다.

### 3.3 내부 권한 코드

```text
PHONE_CRM_MONTHLY_1900
MESSAGE_AUTOMATION_MONTHLY_990
CALLTAG_BUNDLE_MONTHLY_2500
```

서버에서는 가격이 아니라 기능 권한으로 판정한다.

```text
PHONE_CRM_ENABLED
MESSAGE_AUTOMATION_ENABLED
WEB_SYNC_ENABLED
```

`CALLTAG_BUNDLE_MONTHLY_2500` 구매자는 전화관리와 문자자동화 권한을 모두 가진다.

## 4. 구독별 기능 경계

### 4.1 전화관리 월 1,900원

제공 기능:

- 수신·발신·부재중·거절·미연결 통화 감지
- 전화번호 기준 기존 고객 조회
- 연락처 이름에 `고객명 · 핵심 메모` 표시
- 이름 없는 고객을 `고객 4396`처럼 번호 끝 네 자리로 구분
- 고객 상태 `신규 / 진행 중 / 완료` 및 사용자 상태 편집
- 통화 종료 후 결과·메모 저장
- 다음 할 일과 일정 등록
- 신규 고객에게 첫 일정을 추가하면 자동으로 `진행 중` 변경
- 부재중·거절·미연결 통화 관리
- 고객별 통화·상태·메모·일정 타임라인
- 1일·7일·14일·30일 통계
- 관리공백 행동 목록
- 캘린더와 일정 종류 관리

제외 기능:

- SMS/MMS 실제 발송
- 문자 템플릿
- 자동·예약 문자
- 문자 발송내역

### 4.2 문자자동화 월 990원

제공 기능:

- 템플릿으로 시작하기
- 자유롭게 작성하기
- SMS·LMS·이미지 MMS
- 수동 발송
- 통화 종료 후 자동 발송
- 부재중·거절 후 자동 발송
- 연결된 발신 통화 종료 후 발송
- 사용자가 지정한 시간 뒤 예약 발송
- 예: 통화 종료 3일 뒤 후속 문자 자동 발송
- 특정 날짜·시간 예약 발송
- 업무시간 제한
- SIM·eSIM 회선 선택
- 회선별 메시지와 발송 규칙
- 중복 발송 방지
- 수신거부·제외번호 차단
- 발송 성공·실패·건너뜀 기록
- 단체 발송과 순차 발송

문자 상품만 구매해도 자동 발송 트리거를 위해 최소한의 통화 종료·부재중 감지는 동작한다. 다만 고객 상태·통계·관리공백·상세 CRM은 제공하지 않는다.

### 4.3 통합 이용 월 2,500원

전화관리와 문자자동화 전체 기능을 제공하며, 두 모듈이 연결된 다음 기능을 활성화한다.

- 통화 종료 화면에서 상태·메모·일정·문자를 한 번에 처리
- 상담 결과별 템플릿 자동 추천
- 고객 상태별 자동 문자 규칙
- 다음 할 일에 연결된 예약 문자
- 문자 발송 완료 시 관련 일정 자동 완료
- 3일 뒤 후속 문자 발송과 동시에 재연락 일정 생성
- 고객 타임라인에서 통화·문자·일정을 시간순으로 통합 표시
- 관리공백 화면에서 전화·문자·일정 바로 실행

## 5. 초기 실행과 권한 UX

현재의 긴 `전화 고객정보 표시` 설명 화면은 제거한다.

### 5.1 최초 실행 흐름

```text
앱 실행
→ 로그인 또는 회원가입
→ 필요한 Android 시스템 권한창을 순서대로 표시
→ 사용자가 허용
→ 연락처 메모 표시 자동 활성화
→ 홈 진입
```

앱이 권한을 자동 승인할 수는 없다. 앱은 시스템 권한창을 자동으로 열고 사용자는 `허용`만 누른다.

전화관리 구매자에게 필요한 권한:

- 연락처 읽기
- 연락처 수정
- 전화 상태
- 통화기록
- 알림

문자자동화 구매자에게 추가로 필요한 권한:

- 문자 발송
- SIM·전화 상태
- 알림
- 이미지 첨부 시 Android Photo Picker 사용

### 5.2 권한 거절 처리

별도 복잡한 설정 페이지로 강제 이동하지 않는다. 홈 상단에 필요한 기능만 표시한다.

```text
전화 고객관리를 사용하려면 연락처와 통화 권한이 필요합니다.
[권한 허용]
```

`다시 묻지 않음` 상태에서는 앱 상세 설정으로 연결한다.

### 5.3 사용자 설정에 남길 항목

- 전화 화면에 핵심 메모 표시 켜기·끄기
- 연락처 이름 원래대로 복원
- 통화 종료 후 정리창 사용
- 자동 문자 규칙 켜기·끄기
- 업무시간
- 기본 발송 회선
- 중복 발송 제한
- 제외번호·수신거부

수신정보 앱 역할, 오버레이 테스트, 잠금화면 표시 범위는 일반 사용자 핵심 설정에서 제거한다.

## 6. 메인 정보 구조

하단 메뉴는 네 개로 고정한다.

### 6.1 홈

오늘 사용자가 실제로 처리해야 할 항목만 표시한다.

- 정리하지 않은 통화
- 다시 전화해야 하는 고객
- 오늘 일정
- 기한 초과 일정
- 발송 대기 문자
- 발송 실패 문자
- 후속 처리가 없는 고객

설명형 카드와 의미 없는 숫자 나열은 제거한다.

### 6.2 고객

- 고객 목록
- 고객 통계
- 고객명·전화번호 검색
- 상태 필터
- 기간 필터
- 상태 편집
- 고객 상세
- 통화·메모·문자·일정 통합 타임라인

상단 구조:

- `목록 / 통계` 탭은 충분히 크게 표시
- 제목·검색은 스크롤 시 사라짐
- `상태 / 기간 / 편집`만 상단 고정
- 상태·기간 선택은 작은 버튼 묶음이 아니라 단일 드롭다운

통계 기간:

```text
1일 / 7일 / 14일 / 30일
```

통계 설명문은 제거하고 숫자·증감·처리 목록만 표시한다.

### 6.3 메시지

첫 화면에서 작성 방식을 명확히 나눈다.

```text
[템플릿으로 시작]
[자유롭게 작성]
```

하위 기능:

- 자동 발송 규칙
- 예약 발송
- 템플릿
- 이미지 첨부
- 발송 대기
- 발송 완료
- 실패·재시도
- 단체 발송

### 6.4 일정

- 월간 캘린더
- 오늘 할 일
- 기한 초과
- 일정 종류 필터
- 고객별 일정
- 완료·다시 열기·변경·삭제

일정에는 점만 표시하지 않고 실제 일정 제목을 표시한다.

## 7. 통화 종료 통합 정리 화면

통합 구독의 핵심 화면이다.

```text
김민수
수신 통화 · 2분 14초

통화 결과
[관심 있음] [견적 발송] [다시 연락]
[계약 완료] [보류] [종료]

고객 상태
[진행 중 ▾]

통화 메모
[견적서를 수정해 다시 보내달라고 요청]

다음 할 일
[자료 보내기 ▾] [7월 31일 오전 10:00]

고객에게 보낼 문자
[견적 발송 템플릿 ▾]
[이미지 추가]

후속 문자
[3일 뒤 자동 발송 ▾]

[저장만 하기]
[저장하고 문자 보내기]
```

저장 시 하나의 작업으로 처리한다.

1. 고객 생성 또는 기존 고객 연결
2. 통화 결과 저장
3. 고객 상태 저장
4. 메모 저장
5. 다음 할 일 생성
6. 즉시 문자 발송
7. 예약 문자 작업 생성
8. 고객 연락처 표시명 갱신
9. 고객 타임라인 반영

중간 단계가 실패하면 성공한 항목과 실패한 항목을 분리해 표시하고 재시도할 수 있어야 한다.

```text
CUSTOMER_CREATED
CUSTOMER_STATUS_CHANGED
TASK_CREATED
TASK_DUE

MANUAL_SEND
```

### 8.2 조건

- 수신·발신·부재중·거절 구분
- 통화 연결 여부와 통화시간

- 선택 SIM·eSIM
- 제외번호·수신거부 여부
- 같은 번호 최근 발송 여부
- 동일 템플릿 중복 여부
- 사용자 수동 처리 여부

### 8.3 실행 작업

- 즉시 SMS/LMS 발송
- 이미지 MMS 발송
- N분·N시간·N일 후 예약
- 다음 할 일 생성
- 고객 상태 변경
- 담당 메모 추가
- 발송 실패 알림

### 8.4 대표 자동화 예시

#### 통화 종료 즉시 안내

```text
조건: 연결된 수신 통화 종료
동작: 감사 안내 템플릿 즉시 발송
```

#### 부재중 자동응답

```text
조건: 부재중 또는 거절 + 업무시간
동작: “통화가 어려워 확인 후 연락드리겠습니다” 자동 발송
```

#### 업무시간 외 부재중

```text
조건: 부재중 + 업무시간 외
동작: 영업시간 안내 템플릿 발송
```

#### 3일 뒤 후속 문자

```text
조건: 통화 결과가 견적 발송
동작: 3일 뒤 검토 여부 확인 템플릿 발송
취소: 고객 상태가 완료로 변경되거나 사용자가 취소
```

#### 일정 연동

```text
조건: 자료 보내기 일정 생성
동작: 일정 1시간 전 준비 안내 또는 일정 완료 후 자료 문자 발송
```

### 8.5 예약 작업 상태

```text
DRAFT
SCHEDULED
READY
SENDING
SENT
FAILED
SKIPPED
CANCELLED
```

예약 문자에는 반드시 생성 이유와 취소 조건을 보여준다.

```text
3일 뒤 발송 예정
이유: 7월 31일 견적 발송 통화
[내용 확인] [시간 변경] [취소]
```

### 8.6 자동 취소 조건

- 사용자가 같은 템플릿을 이미 수동 발송
- 예약 전에 고객과 다시 통화
- 고객 상태가 완료·종료로 변경
- 고객이 제외번호 또는 수신거부로 변경
- 해당 후속 일정이 취소
- 사용자가 자동화 규칙을 끔

## 9. 삼성 리마인더와의 명확한 차별점

삼성 리마인더는 시간·장소·전화·메시지와 연결된 개인 알림을 만들 수 있고, 통화 거절 시 나중에 전화할 알림을 만들거나 메시지를 리마인더로 보낼 수 있다. 콜태그가 단순히 “전화 다시 하기 알림”만 제공하면 무료 기본 앱보다 선택할 이유가 없다.

| 구분 | 삼성 리마인더 | 콜태그 |
|---|---|---|
| 목적 | 개인 할 일 기억 | 전화 기반 고객업무 실행 |
| 생성 방식 | 사용자가 직접 등록 | 통화 이벤트로 자동 생성 |
| 고객 상태 | 없음 | 신규·진행 중·완료 및 사용자 상태 |
| 통화 메모 | 일반 메모 | 고객·통화와 연결된 상담 이력 |
| 수신 전 정보 | 일반 연락처명 | 고객명 + 핵심 메모 |
| 부재중 처리 | 다시 전화 알림 | 자동 문자 + 재연락 일정 + 미처리 관리 |
| 문자 템플릿 | 없음 | 상황·상태별 템플릿 |
| 자동 문자 | 없음 | 통화 종료·부재중·지연 자동 발송 |
| 3일 뒤 후속 | 수동 리마인더 | 조건부 자동 발송 및 자동 취소 |
| 고객 타임라인 | 없음 | 통화·문자·메모·일정 통합 |
| 관리공백 | 없음 | 실제 누락 원인별 행동 목록 |
| 통계 | 개인 완료 내역 중심 | 통화·신규고객·문자·일정·상태 전환 |
| 웹 관리 | 개인 동기화 중심 | 고객·템플릿·통계·대량 관리 |

콜태그의 포지셔닝 문장:

> **리마인더는 할 일을 알려줍니다. 콜태그는 전화가 끝난 뒤 해야 할 일을 실제로 처리합니다.**

## 10. 관리공백 재설계

`30일 동안 연락하지 않은 고객` 같은 단순 숫자는 제거한다. 관리공백은 사용자가 바로 처리할 수 있는 누락 목록이어야 한다.

- 통화했지만 메모가 없는 고객
- 통화 후 상태가 미지정인 고객
- 견적 문자를 보냈지만 다음 할 일이 없는 고객
- 신규 고객인데 일정이 없는 고객
- 일정 기한이 지났지만 미완료인 고객
- 부재중 이후 다시 연락하지 않은 고객
- 자동 문자 발송에 실패한 고객
- 3일 뒤 후속 문자가 취소·건너뜀 처리된 고객
- 마지막 통화 이후 장기간 후속 행동이 없는 진행 중 고객

각 항목에서 다음 행동을 바로 실행한다.

```text
[전화] [문자] [일정 추가] [처리 완료]
```

## 11. 핵심 고도화 아이디어 15개

### 11.1 전화 화면용 핵심 메모 고정

일반 최근 메모와 별도로 `전화 올 때 표시` 문구를 고정한다. 오래된 메모가 자동으로 노출되는 문제를 막는다.

### 11.2 핵심 메모 자동 우선순위

고정 문구가 없으면 `가장 임박한 미완료 일정 → 최근 미완료 행동 → 최근 메모 → 고객 상태` 순서로 표시한다.

### 11.3 메모 만료

`금요일 오전 연락` 같은 문구는 일정 완료 또는 날짜 경과 후 자동 제거하고 다음 중요 정보로 교체한다.

### 11.4 연락처 표시 미리보기

메모 저장 전 실제 수신 화면 표시 형태를 보여준다.

```text
전화 화면 표시
김민수 · 견적서 재발송
```

### 11.5 결과별 문자 추천

`견적 발송`, `다시 연락`, `계약 완료`, `부재중` 등 통화 결과에 맞는 템플릿을 자동으로 추천한다.

### 11.6 통화 후 원터치 완료

상태·메모·일정·문자를 미리 추천하고 사용자는 `저장하고 보내기` 한 번만 누른다.

### 11.7 후속 문자 시퀀스

한 번의 예약이 아니라 사용자가 정의한 단계형 후속 흐름을 제공한다.

```text
통화 직후 안내
→ 3일 뒤 확인
→ 7일 뒤 마지막 확인
```

각 단계는 고객이 응답하거나 상태가 변경되면 자동 중단한다.

### 11.8 문자 발송 전 스마트 중복 방지

같은 번호·비슷한 문구·짧은 시간 내 중복 발송을 감지해 자동으로 건너뛴다.

### 11.9 신규 고객 자동 진행 전환

신규 고객에게 첫 일정, 첫 상담 결과 또는 첫 문자 후속 작업이 생성되면 자동으로 `진행 중`으로 바꾼다.

### 11.10 고객별 선호 회선

듀얼 SIM 사용자는 고객 또는 그룹별 기본 발송 회선을 저장한다.

### 11.11 에이닷 요약 공유 가져오기

에이닷 통화요약을 Android 공유 기능으로 콜태그에 보내면 고객을 선택하고 메모로 저장하며 다음 할 일을 제안한다.

### 11.12 상태별 자동화 묶음

예: 고객 상태가 `견적 검토`가 되면 견적 안내 문자와 3일 뒤 후속 작업을 동시에 생성한다.

### 11.13 고객 타임라인 재생

통화·메모·문자·일정을 시간순으로 묶어 “이 고객에게 지금까지 무슨 일이 있었는지” 한 화면에서 이해하게 한다.

### 11.14 실패 중심 홈

정상 처리된 항목보다 `미정리 통화`, `발송 실패`, `기한 초과`, `후속 없음`을 우선 노출한다.

### 11.15 웹 대량 운영

앱은 통화 직전·직후 빠른 처리에 집중하고, 웹은 고객 대량 편집·템플릿 관리·통계·예약문자 확인을 담당한다.

```text
3일 뒤 후속 문자 자동 발송
```

```text
전화관리와 문자자동화를 각각 이용하면 월 2,890원
통합 이용은 월 2,500원
[통합 이용 시작]
```

## 14. Android 및 스토어 정책 게이트

콜태그의 자동 문자와 통화기록 기능은 Android의 민감 권한을 사용한다. Google Play는 SMS·통화기록 권한을 엄격하게 제한하며, 기본 전화·문자 앱이 아니면 허용된 예외 사용 사례와 권한 선언 심사를 통과해야 한다.

콜태그는 기본 전화 앱이 되면 에이닷의 통화녹음·AI 요약 사용에 영향을 줄 수 있으므로 기본 전화 앱 전환을 핵심 요구로 삼지 않는다.

출시 경로는 다음처럼 분리 검토한다.

### 14.1 1차 권장 경로

- 원스토어 또는 직접 배포 APK
- 기존 콜링크에서 실기기 검증된 자동 SMS 로직 이전
- 자동 발송·부재중 발송·백그라운드 동작 우선 검증

### 14.2 Google Play 경로

- SMS·Call Log Permissions Declaration 제출
- 핵심 기능을 `사용자가 정의한 조건에 따른 기기 자동화`로 명확히 설명
- 자동 문자와 통화 감지가 앱의 핵심 기능임을 스토어 설명에 명시
- 심사 불승인 시 수동 SMS Intent 기반 별도 변형 검토

정책 승인을 받지 않은 상태에서 Google Play 등록 가능성을 확정적으로 표현하지 않는다.

### 14.3 연락처 권한

연락처 이름에 핵심 메모를 표시하려면 연락처 읽기·수정 권한이 필요하다. 콜태그는 CRM과 수신 전 고객 인식이라는 핵심 기능에 필요한 범위만 사용하고, 연락처 정보를 광고·프로파일링 목적으로 사용하지 않는다.

## 17. MVP 완료 기준

- 앱명이 모든 화면에서 콜태그로 통일된다.
- 최초 실행 시 별도 설명 화면 없이 필요한 권한창이 순서대로 열린다.
- 연락처에서 `고객명 · 핵심 메모`를 확인할 수 있다.
- 연결 통화 종료 후 자동 또는 수동 문자를 보낼 수 있다.
- 부재중·거절 전화에 규칙에 따라 문자를 보낼 수 있다.
- 통화 종료 3일 뒤 예약 문자가 재부팅 후에도 유지된다.
- 고객 상태가 바뀌거나 사용자가 처리하면 예약 문자가 자동 취소된다.
- 전화·문자·메모·일정이 같은 고객 타임라인에 연결된다.
- 전화관리·문자자동화·통합 구독의 기능 잠금이 정확하다.
- 무료 삼성 리마인더와 달리 사용자가 직접 여러 앱을 오가지 않고 통화 이벤트에서 업무 처리가 끝난다.

## 18. 제품 원칙

1. 콜태그는 기본 전화 앱을 대체하지 않는다.
2. 에이닷 통화녹음·AI 요약과 공존한다.
3. 수신 전 정보는 연락처 표시명 동기화를 기본으로 한다.
4. 통화 후 정리는 10초 안에 끝나야 한다.
5. 자동 문자는 사용자가 직접 규칙과 템플릿을 설정한 경우에만 실행한다.
6. 예약 발송은 이유·예정시각·취소 방법을 항상 보여준다.
7. 고객 상태·메모·일정·문자는 하나의 고객 타임라인을 사용한다.
8. 이름 없는 고객을 동일한 이름으로 저장하지 않는다.
9. 관리공백은 숫자가 아니라 처리 가능한 행동 목록으로 제공한다.
10. 전화관리와 문자자동화는 각각 결제할 수 있어야 한다.
11. 두 기능을 함께 이용할 때는 하나의 통화 종료 화면에서 연결돼야 한다.
12. 통신사 문자 요금과 콜태그 구독료를 명확히 구분한다.
13. 민감 권한과 스토어 정책 승인을 출시 전 필수 게이트로 관리한다.
14. 기존 검증된 콜링크 발송 로직을 불필요하게 재작성하지 않는다.
15. 사용자가 누르지 못하는 텍스트를 버튼처럼 보이게 만들지 않는다.
