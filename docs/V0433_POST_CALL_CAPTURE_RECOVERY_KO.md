# CallTag v0.43.3 통화 종료 고객등록·팝업 복구

## 문제

일부 내부 테스트 기기에서 통화를 종료해도 신규 번호가 고객목록에 나타나지 않고 통화 종료 정리 팝업도 표시되지 않았다.

원인은 다음 두 경로가 동시에 존재한 것이다.

1. 앱 재실행 뒤 통화 감시 서비스 시작이 연락처 이름 동기화 완료 상태에 묶여 있었다.
2. 삼성전화·T전화 등 제조사 전화 앱이 전화 상태 콜백을 누락하면 통화기록 변경 알림도 조회 중인 경우에만 사용하고 있어 종료 통화를 놓칠 수 있었다.
3. 통화 종료 화면에서 저장하기 전에는 신규 번호가 고객 DB에 생성되지 않았다.
4. Android가 백그라운드 Activity 실행 요청을 수락한 것처럼 반환하고 실제 화면은 표시하지 않는 동안 알림 fallback이 늦게 동작했다.

## 수정

- 로그인과 `READ_PHONE_STATE`·`READ_CALL_LOG` 권한이 있으면 앱 시작·화면 복귀·재부팅·앱 업데이트 후 통화 감시를 자동 복구한다.
- 전화 상태 콜백과 CallLog ContentObserver를 독립적인 이중 감지 경로로 운영한다.
- 긴 통화도 시작 시각이 아니라 계산된 종료 시각으로 최근 통화를 찾는다.
- 통화가 확인되는 즉시 신규 번호를 `신규` 고객으로 자동 등록한다.
- 연락처 이름이 있으면 해당 이름을 사용하고 없으면 `고객 1234` 형식으로 생성한다.
- 자동 등록된 고객을 통화 종료 정리 화면과 자동문자 치환에 즉시 전달한다.
- 통화 종료 정리 알림/full-screen intent를 먼저 등록하고 1.2초 뒤 Activity 직접 실행을 재시도한다.
- 통화 상태 처리와 실패 원인을 진단 이벤트에 기록한다.

## 기대 동작

1. 수신·발신·부재중·거절 통화 종료
2. CallTag가 전화 상태 또는 통화기록 변경 중 하나로 종료 통화를 확인
3. 등록되지 않은 번호면 고객목록에 즉시 신규 등록
4. 큰 통화 종료 정리 화면 표시
5. 백그라운드 화면 실행이 제한된 기기에서는 동일 화면을 여는 heads-up 알림 유지
6. 메모·상태·다음 할 일을 저장하면 기존 자동 등록 고객에 상담이력 추가

## 검수

- 기존 고객과 통화 후 중복 고객이 생성되지 않는지 확인
- 신규 번호 통화 직후 고객목록에 나타나는지 확인
- 삼성전화·Google 전화·T전화에서 각각 확인
- 앱을 강제 종료 후 다시 실행한 뒤 통화 감지가 복구되는지 확인
- 앱 업데이트 및 휴대전화 재부팅 뒤 통화 감지가 복구되는지 확인
- 수신·발신·부재중·거절 통화에서 정리 화면이 뜨는지 확인
- Android 14~16에서 큰 팝업 또는 heads-up 알림 중 하나가 반드시 남는지 확인
