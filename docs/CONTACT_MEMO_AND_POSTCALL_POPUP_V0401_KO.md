# 콜태그 v0.40.3 전화 수신 메모 표시 기준

> v0.40.1의 연락처 별칭 동기화 방식은 폐기됐다. 이 문서는 현재 구현 기준이다.

## 절대 기준

콜태그는 휴대전화 연락처를 생성하거나 연락처 이름을 수정하지 않는다.

- `ContactNameSyncManager`는 과거 버전이 만든 콜태그 연락처와 계정을 정리하는 용도로만 남긴다.
- 신규 설치와 업데이트 설치 모두 연락처 수정 권한을 요청하지 않는다.
- 앱 실행 중 주기적인 연락처 동기화를 수행하지 않는다.
- 수신 순간 전달받은 전화번호를 콜태그 DB에서 조회하고 화면 위 오버레이로 메모를 표시한다.

## 번호별 표시

### 휴대전화에 저장된 번호

1. Android 연락처에서 기존 표시 이름을 읽는다.
2. 기존 연락처 이름은 그대로 유지한다.
3. 전화 화면 위 콜태그 카드에 기존 연락처 이름과 최근 메모를 표시한다.

### 휴대전화에 저장되지 않은 번호

1. 새 연락처를 만들지 않는다.
2. 콜태그 고객명도 전화 화면에 대신 노출하지 않는다.
3. 전화 앱의 번호 표시 위에 콜태그 메모만 추가 표시한다.

## 수신 처리 순서

1. `CallTagScreeningService`가 수신 번호를 전달받는다.
2. 제외번호 여부를 확인한다.
3. `CallTagDbHelper.findByPhone()`으로 콜태그 고객을 조회한다.
4. `CustomerInsightResolver.latestMemo()`로 최근 메모를 조회한다.
5. `SystemContactLookup`으로 시스템 연락처 저장 여부와 기존 이름을 읽는다.
6. `CallerOverlayManager`가 저장 여부에 맞는 오버레이를 표시한다.
7. 오버레이 실패 시 알림으로 동일한 표시 원칙을 유지한다.

## 필수 설정

- 연락처 읽기
- 전화 상태와 전화번호
- 통화기록
- 알림
- Android 수신정보 앱 역할
- 다른 앱 위에 표시
- 문자 상품 사용 시 SMS

`WRITE_CONTACTS`는 과거 생성 데이터 정리를 위해 Manifest에 일시적으로 남을 수 있지만 사용자에게 요청하지 않으며 수신 메모 기능의 필수 권한이 아니다.

## 우선순위 분리

통화 종료 팝업은 전화 수신 메모 표시의 필수 조건이 아니다. 통화 종료 알림 채널이 꺼져 있어도 수신 번호 조회와 메모 오버레이 설정을 완료할 수 있어야 한다.

## 테스트 기준

`등록 고객 수신 테스트`는 가짜 고객을 만들지 않는다.

1. 콜태그 DB의 첫 번째 실제 등록 고객을 선택한다.
2. 해당 번호가 휴대전화 연락처에 저장됐는지 조회한다.
3. 저장 번호면 기존 연락처 이름과 실제 최근 메모를 표시한다.
4. 미저장 번호면 실제 최근 메모만 표시한다.
5. 연락처 앱에 새 고객이 생기거나 기존 이름이 바뀌면 실패다.

## 실기기 QA

1. 저장 고객의 실제 수신 전화에서 기존 연락처 이름과 메모가 함께 보이는지 확인
2. 미저장 고객의 실제 수신 전화에서 메모만 보이는지 확인
3. 앱 설치·실행 후 연락처 앱에 콜태그 연락처가 생성되지 않는지 확인
4. 기존 v0.40.1·v0.40.2가 만든 콜태그 연락처가 업데이트 후 제거되는지 확인
5. 메모 변경 후 다음 수신 전화에 최신 메모가 반영되는지 확인
6. 화면 잠금·홈 화면·다른 앱 사용 중·삼성 전화 앱 위에서 확인
7. 통화 종료 알림을 꺼도 수신 메모 기능을 설정하고 사용할 수 있는지 확인

APK 컴파일 성공은 삼성 전화 화면 실기기 성공을 의미하지 않는다. 실제 수신 전화 QA 결과를 별도로 기록한다.
