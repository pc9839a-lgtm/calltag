# CallTag v0.42.6 연결 기기·서버 복구본 관리

최종 갱신: 2026-08-05

## 목적

데이터 보호를 사용하는 사용자가 다음 작업을 앱 안에서 직접 처리할 수 있게 한다.

- 계정에 연결된 기기 확인
- 분실·미사용 기기의 데이터 보호 권한 원격 해제
- 데이터 보호 OFF와 서버 복구본 삭제의 차이 확인
- 서버 복구본 전체 삭제
- 서버 삭제 후 현재 휴대폰 데이터 유지
- 이후 데이터 보호 재활성화 가능

## 사용자 화면

더보기 → 데이터 보호·복구에서 다음 기능을 제공한다.

1. 데이터 보호 켜기·끄기
2. 지금 동기화
3. 연결된 기기 관리
4. 서버 복구본 삭제

### 데이터 보호 끄기

- 이후 자동 동기화를 중단한다.
- 서버에 이미 보관된 복구본은 유지한다.
- 휴대폰의 고객·상담 데이터는 유지한다.

### 서버 복구본 삭제

- 서버의 동기화 레코드와 변경 이력을 삭제한다.
- 연결된 서버 기기 권한을 모두 해제한다.
- 휴대폰의 `calltag.db` 고객 데이터는 삭제하지 않는다.
- 현재 계정의 로컬 동기화 매핑·cursor만 초기화한다.
- 현재 기기의 보안 식별자를 새 값으로 교체한다.
- 다시 데이터 보호를 켜면 휴대폰 데이터로 새로운 서버 복구본을 생성할 수 있다.

삭제는 두 단계 확인창을 통과해야 실행된다.

## 연결된 기기 관리

서버의 `/api/calltag-sync/devices`를 사용한다.

표시 항목:

- 기기 이름
- 현재 기기 여부
- 연결·해제 상태
- 앱 버전
- 마지막 접속 시각

현재 기기는 목록에서 원격 해제 버튼을 제공하지 않는다. 다른 활성 기기만 `REVOKE_CALLTAG_SYNC_DEVICE` 확인값과 함께 해제 요청을 전송한다.

기기 원문 ID는 서버 응답에 노출하지 않고 HMAC 기반 `deviceKey`만 사용한다.

## 서버 API

```text
GET  /api/calltag-sync/devices
POST /api/calltag-sync/devices
POST /api/calltag-sync/erase
```

앱 요청에는 기존과 동일하게 다음 헤더를 사용한다.

```text
X-Inlet-Session
X-CallTag-Device
X-CallTag-Device-Label
X-CallTag-App-Version
```

서버 복구본 삭제 확인값:

```text
DELETE_CALLTAG_SYNC_DATA
```

## 안전 조건

- 로그인하지 않은 상태에서는 기기 관리·서버 삭제 실행 불가
- 서버 기능 flag가 OFF이면 준비 중으로 표시하고 로컬 데이터 유지
- 서버 삭제 요청 실패 시 동기화 설정과 로컬 mapping을 변경하지 않음
- 서버 삭제 성공 응답 후에만 opt-in OFF·mapping 초기화·기기 ID 교체
- 서버 삭제와 앱 고객 데이터 삭제를 결합하지 않음
- 현재 기기 원격 해제 UI 제공 금지
- 통화 녹음·전체 연락처·전체 문자함 업로드 없음

## 운영 상태

현재 서버 동기화 운영 flag는 계속 OFF다. 앱 화면과 API client가 포함돼도 서버 준비 전에는 고객 데이터가 전송·삭제되지 않는다.
