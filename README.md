## 14차 백업·복원

경로:

```text
계정 및 개인정보
→ 백업 및 복원
```

- `.ctbackup` 전용 파일
- PBKDF2-HMAC-SHA256 키 파생
- AES-256-GCM 암호화
- manifest 형식·패키지·버전 검사
- 파일별 크기와 SHA-256 검증
- ZIP 경로 탈출 및 과도한 압축 해제 차단
- 고객·통화·일정·문자·그룹·캠페인·일정 종류·미정리 통화 DB 포함
- 문자자동화 설정·템플릿·발송 제외·일정 문자 연결·템플릿 이미지 포함
- 로그인 세션·결제·구독 권한 제외
- 복원 전 현재 데이터를 내부 롤백 스냅샷으로 보존
- 복원 실패 시 기존 데이터 자동 복구
- 복원 후 DB 마이그레이션·`PRAGMA quick_check`·정합성 복구·예약 복구 실행

복원은 병합이 아니라 백업 시점 데이터로 교체합니다. 고객·문자·캠페인 ID를 임의로 합치거나 중복 생성하지 않습니다.

## 데이터 정책

백업·복원은 같은 콜태그 앱에서 장애·기기 변경·데이터 손상을 복구하는 기능입니다.

현재 구현 금지:

- CSV·XLSX 내보내기
- 고객 목록 외부 반출
- 캠페인 결과표 외부 반출
- 범용 연락처 파일
- 외부 CRM 이전용 데이터

데이터 내보내기는 추후 별도 유료 기능으로만 기획합니다. `.ctbackup`을 일반 업무 데이터 파일로 변환하는 기능도 넣지 않습니다.

## 작업 규칙

- 사용자 지시 전 `main`에 병합하지 않습니다.
- 개발 PR은 Draft 상태를 유지합니다.
- 기존 데이터를 초기화하지 않습니다.
- DB 변경 시 보존 마이그레이션을 작성합니다.
- 불명확한 `SENDING` 작업은 자동 재발송하지 않습니다.
- 일시정지 캠페인은 자동 재개하지 않습니다.
- 누락 작업을 자동 생성하거나 고아 작업을 자동 발송하지 않습니다.
- Build 성공과 실제 단말 검증 성공을 구분합니다.
- 백업·복원과 외부 데이터 내보내기를 합치지 않습니다.
