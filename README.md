# 콜태그 (CallTag)

전화가 오면 고객의 현재 상태와 최근 메모를 먼저 보여주고, 통화가 끝나면 발신·수신·부재중·거절 통화를 다음 행동까지 정리하는 페이지로 업무 서비스입니다.

## 제품 한 문장

> 전화 전에는 고객 상황을 보여주고, 전화 후에는 놓친 통화와 다음 행동을 남긴다.

## 페이지로 서비스 관계

콜태그와 콜링크는 서로 다른 앱이지만 같은 페이지로 업무 서비스다.

- `페이지로 콜링크`: 통화 후 문자 작성·발송·템플릿
- `페이지로 콜태그`: 고객 상태·상담 이력·캘린더·후속업무
- `페이지로 비즈니스`: 공통 계정·고객·통화·결제·웹 관리 체계

앱과 도메인이 달라도 같은 페이지로 계정과 고객 데이터를 사용하도록 개발한다.

## 권장 웹 도메인

- 콜태그 웹: `https://calltag.pagero.kr`
- 향후 통합 포털: `https://app.pagero.kr`
- 공통 API: `https://api.pagero.kr`

초기 공개 주소는 `calltag.pagero.kr`을 사용한다.

## 현재 단계

- Android MVP 기능 개발
- 통화 종료 후 고객 분류·상담 결과 저장
- 고객 상세·메모·상태 변경·활동 이력
- 월간 캘린더와 날짜별 일정 관리
- 일정 추가·변경·완료·다시 열기·삭제
- 고객 추가 시 최근 통화 목록에서 번호·이름 불러오기
- 콜링크와 동일한 로그인·회원가입·이메일 인증·비밀번호 재설정
- 회원가입 필수 개인정보 수집·이용 및 이용약관 동의
- 계정정보·개인정보처리방침·로그아웃·2단계 회원탈퇴
- 통화 후 중복 저장·버튼 연타·권한 누락·서비스 재시작 안정화
- 기본 고객 상태를 `신규 / 진행 중 / 완료` 3개로 단순화
- 기본 3개와 사용자 상태의 이름·색상 수정
- 사용자 상태 추가·삭제
- 고객 목록에서 상태 즉시 변경
- 고객 카드 테두리와 상태 버튼에 동일한 색상 적용
- 카드 전체 숨은 클릭 제거 및 상세 이동 버튼 분리
- 캘린더 날짜 셀 내부 일정명 색상 배지 표시
- VIP 기본 상태와 고객 유입경로 입력 제거
- 수신 전화 시 고객명·고객 상태·최근 메모 알림
- 발신·수신·부재중·거절 통화 미처리 대기열
- 발신 0초 통화를 `연결 안 됨`으로 분류
- 홈에서 미처리 통화 `전화 / 정리 / 완료` 처리
- 통화 정리 저장 시 미처리 목록 자동 제거
- 콜링크 연동형 웹 서비스 구조 문서화
- 패키지명: `kr.pagero.calltag`
- 최소 Android: API 26
- 수신 고객정보 표시: Android 10 이상 권장
- 개발 브랜치: `agent/calltag-foundation`
- 최근 개발 버전: `v0.11.0`

## 통화 흐름

### 전화가 올 때

홈의 `수신 고객정보 표시 켜기`에서 연락처 권한과 Android 수신정보 앱 역할을 설정한다.

등록된 고객 전화에는 다음 정보가 상단 알림으로 표시된다.

- 고객명
- 현재 사용자 지정 고객 상태
- 최근 통화 메모
- 고객 상세 바로가기

### 전화가 끝난 뒤

수신·발신·부재중·거절 통화는 홈의 `처리할 통화`에 남는다.

- `전화`: 해당 번호로 전화
- `정리`: 통화 결과·메모·다음 연락 입력
- `완료`: 별도 기록 없이 목록에서 제거

부재중·거절·연결되지 않은 발신 통화는 정리 화면을 강제로 열지 않고 알림과 홈 목록으로 관리한다.

## 고객 상태 기준

기본 상태는 3개만 제공한다.

1. 신규
2. 진행 중
3. 완료

기본 3개도 이름과 색상을 수정할 수 있다.

기본 3개 외 상태는 사용자가 직접 추가한다. 추가 상태는 이름·색상 수정과 삭제가 가능하다.

순서 변경 기능은 제공하지 않는다. 기본 3개 뒤에 추가한 순서대로 표시한다.

상태 색상은 고객 목록 상태 버튼, 고객 카드 테두리, 선택 필터, 고객 상세, 캘린더 일정 배지에 동일하게 적용한다.

고객 상태는 고객 등급이 아니라 현재 진행 상황을 의미한다. `VIP`처럼 기준이 불명확한 고객 등급은 기본 상태로 사용하지 않는다.

고객 등록 시 유입경로를 묻지 않는다. 향후 시스템에서 자동 확인할 수 있는 경우에만 내부 데이터로 저장한다.

## 캘린더 기준

일정이 있는 날짜를 점으로 표시하지 않는다.

날짜 셀 안에 `고객명 + 일정명`을 작은 색상 배지로 표시한다.

- 날짜당 최대 2줄 표시
- 초과 일정은 `+N개 일정`으로 축약
- 배지 색상은 고객 상태 색상과 동일
- 완료 일정은 회색
- 선택 날짜와 오늘 날짜는 테두리로 구분
- 긴 일정명은 말줄임하고 선택 날짜 아래 목록에서 전체 내용 확인

## 계정과 회원탈퇴

- 콜태그는 페이지로 콜링크와 같은 회원가입·로그인 서버를 사용한다.
- 회원가입 시 이름, 휴대폰번호, 이메일, 브랜드명, 업종을 수집한다.
- 개인정보 수집·이용과 서비스 이용약관에 각각 필수 동의해야 가입할 수 있다.
- 로그인 세션은 Android Keystore 기반 AES-GCM으로 암호화해 저장한다.
- 로그아웃하면 통화 감지는 중지하지만 휴대전화의 고객·일정 데이터는 유지한다.
- 회원탈퇴는 두 번 확인하며, 공유 페이지로 계정과 콜태그의 로컬 고객·상담·일정 데이터를 삭제한다.
- 같은 계정을 사용하는 콜링크도 탈퇴한 계정으로 다시 로그인할 수 없다.

## 핵심 원칙

1. 고객과 상담건을 분리한다.
2. 고객 상태는 고객 등급이 아니라 현재 진행 상황을 의미한다.
3. 기본 상태는 3개만 제공하고 이름과 색상을 모두 수정할 수 있어야 한다.
4. 추가 상태는 사용자가 직접 만들고 수정·삭제할 수 있어야 한다.
5. 상태 순서 변경 기능으로 화면을 복잡하게 만들지 않는다.
6. 고객 상태는 고객 목록과 상세 화면에서 즉시 변경할 수 있어야 한다.
7. 휴대폰 연락처 등록 여부만으로 기존 고객을 판단하지 않는다.
8. 통화 전에는 고객 상태와 최근 메모를 바로 확인할 수 있어야 한다.
9. 수신·발신·부재중·거절 통화를 모두 관리한다.
10. 통화 후 처리는 10초 안에 끝나야 한다.
11. 캘린더에는 일정 점이 아니라 일정명 배지를 표시한다.
12. 일정은 Android 앱·웹 캘린더·고객 상세에서 같은 상태로 보여야 한다.
13. 상태 변경·일정·문자 발송은 하나의 고객 활동 기록에 남긴다.
14. 고객 추가의 기본 진입은 최근 통화 목록으로 한다.
15. 콜링크와 콜태그는 같은 계정·고객·통화 식별자를 사용한다.
16. 앱별로 고객 데이터를 중복 생성하지 않는다.
17. 클릭 가능한 요소와 읽기 전용 정보를 같은 모양으로 만들지 않는다.
18. 360dp 화면과 큰 글자 환경에서 좌우 잘림을 허용하지 않는다.
